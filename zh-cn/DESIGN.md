# 设计系统：SparkX 工作台

> 语言： [English](../DESIGN.md) | 简体中文

## 概述

**创意北极星：“一个安静的本地智能体工作空间，采用浅色磨砂玻璃。”**

2026-10-19 接受的用户提供的 Iconly 组件参考确立了材质、操作形状和成对的图标状态。
这一处理已从首页扩展到现有工作台：设置、日程、邮件、通知、任务搜索、文档选择、
设备菜单、账户菜单和确认框。它是一套统一的视觉系统，保留现有路由、内容、能力、
布局和工作流程。

这是一个操作者界面。阅读、撰写和理解真实状态优先于材质效果。首页保持已接受的
几何结构；二级页面保留既有的信息结构和密度。

**关键特征：**

- 冷灰色底面、乳白半透明表面、明亮的内边缘和柔和的层次。
- 蓝色主要操作；手绘线性和实心图形与真实界面状态绑定。
- 在各主题和文字偏好下保持稳定布局与无障碍交互。

## 颜色

frontmatter 记录共享的浅色主题基础值。运行时主题和偏好映射保留在 CSS 中；
令牌变化时更新此快照。共享材质在 `apps/webchat/src/styles/glass.css` 中使用 `--ui-*`。
已接受的首页在 `home.css` 中保留其 `--home-*` 材质和几何。

### 主色

`--ui-blue` 用于主要操作、激活强调和焦点。共享主要按钮使用 `--ui-primary` 和
`--ui-primary-hover` 渐变；邮件发送/回复和确认操作使用纯蓝色。共享蓝色足够深，
保证白色操作文字清晰。前景使用 `--ui-on-blue`；深色模式同时重映射两者，而不是在
较浅的深色主题强调色上保留白色文字。

### 中性色

`--ui-ground` 是工作区底面。`--ui-ink` 承载主要文字；`--ui-muted` 承载辅助文字和
静止图标。`--ui-glass` 是安静的容器材质；`--ui-glass-strong` 用于浮层和选中表面。
`--ui-glass-edge` 和 `--ui-glass-highlight` 定义明亮边缘。分隔线和输入框边缘使用各自的
低对比度令牌。高密度邮件阅读表面通过其派生阅读令牌保持近乎不透明。

危险、警告和成功色保留语义基础令牌及其主题映射。录音保持红色，处理中保持琥珀色。
禁用控件保持弱化且确实处于禁用状态。

## 字体排印

使用系统 UI 字体栈以及现有的标题、分区、正文、UI、标签和元数据角色。首页可使用其
现有的 SF Pro 字体栈和欢迎标题字号。“小”和“大”文字模式通过 `appearance.css`
重映射共享字号和行高角色；控件必须容纳这些尺寸。“小”还会更新首页固定的阅读角色，
同时保留字标、欢迎标题和控件几何。小、默认、大通过同一本地偏好持久化，启动时恢复。

中文阅读角色在 `chinese-typography.css` 中使用紧凑字号：默认正文/UI 为 16px/14px，
小为 14px/12px，大为 17px/15px。行高随各角色变化。对话正文、侧边栏标题和输入框
使用 13px（小 12px、大 14px），行高 1.75。这些映射同样作用于现有首页标签
和输入框，同时保留品牌字标和欢迎标题。Web 和桌面端启动时都会同步文档语言。
英文保留既有字号。

外观设置包含一个继承实时主题、字号和表面令牌的示例对话。在任何宽度下都以单栏位于控件之后。标准对话宽度为 760px；宽屏为 1040px，同时加宽欢迎页输入框。
透明度和动态效果各提供“跟随系统”或“减少”，遵循系统无障碍偏好并本地持久化。
减少透明度会使表面不透明并移除背景模糊；减少动态效果还会立即显示回复文字。
偏好变化无需重新加载即可同时作用于预览和真实工作台。

League Spartan 仅用于 **Spark X** 字标。保留字面空格、共享字母度量、蓝色 X 和已接受的
光学偏移（`translateY(3px)`）。其度量记录在上方 `typography.wordmark` 中。提供的图形
标志保持不变；组件效果和 SVG 规则不得改变它。

## 布局

保留桌面左侧边栏、中央工作区、响应式抽屉和所有现有入口。设置保留分组导航和表单流程；
日程保留表格及创建/删除对话框；邮件保留三栏工作区、移动端栏间导航以及受保护的
发送/审阅流程。

共享桌面外壳使用外边距和间距（14px），保持现有页头高度（68px）。在抽屉断点（840px），
外壳取消外边距，侧边栏变为视口高度的抽屉。更小的页面布局在 600px 处收紧；
邮件在 720px 变为全屏窗口。日程列在 900px 和 480px 处逐步适配。保持这些既有响应式行为，
不改变信息架构。

桌面客户端在全高外壳上方绘制一条 48px 标题栏，容纳 macOS 内嵌窗口控件的位置、
页面历史的后退与前进、侧边栏开关和工作区操作；拖动其空白处可移动窗口。侧边栏和设置导航
以分隔线紧贴在标题栏下方，而不是悬浮卡片。Linux 和 Windows 在同一标题栏之上保留原生边框。
Web 保留页内顶栏，不提供页面历史。桌面首页使用与 Web 首页相同的轻量欢迎样式，但没有建议行。

桌面标题栏随下方分栏划分：前段延续侧边栏的表面和分隔线，工作区段显示当前对话标题。
侧边栏收起或窗口宽度不超过 840px 时，前段变为透明，宽度只容纳其控件。侧边栏对话行参照
Codex：只显示标题，过长时在行尾渐隐而不用省略号；悬停或键盘聚焦时右侧显示归档和省略号操作，
长标题滚动一次到末尾、不循环（减少动态效果时不滚动）；右键在指针处打开同一菜单。对话历史只在该方向还有内容时，于标题栏下方和输入框上方渐隐。日程页内容下移，
并提供一行示例请求，点击后打开已填好内容的新建对话框。邮件窗口中的工具栏、列表行、消息和回复框
与窗口及窗格边缘保持内缩。桌面窗口默认以 1280x820 打开，在较小工作区内不超过其 85% x 80%，
最小可缩至 640x560。

六列首页输入框必须适配 320px。保持其 overflow 可见，使语音设备菜单能溢出卡片。
文档浮层保持视口内边距（16px），对话框宽高受视口约束。在 320px 和 390px 下检查现有和
新增交互，包括大字号、长标签、抽屉导航和对话框操作。

## 层次与深度

深度来自半透明平面、细亮边框、内侧顶部高光和柔和的向下阴影。分区使用安静的层次；
菜单、通知和对话框使用更强的浮层阴影。嵌套的设置记录比所属分区更安静，不会变成
重复的浮起卡片。

**表面磨砂规则。** 模糊只作用于可见的侧边栏、卡片或浮层表面本身。工作区、页头和
浮层祖先不加滤镜，以便固定定位的通知和对话框保持视口定位。原生对话框背景可使用
其已有的轻度模糊。

`body.glassWorkbench` 为挂载在 body 下的 portal 提供共享令牌；Web 和本地工作台也保留
该类名。portal 不得依赖首页祖先。深色模式把共享材质重映射为深色半透明平面。
减少透明度模式使其不透明并移除背景模糊。精确的阴影和模糊配方记录在
`.impeccable/design.json` 和 CSS 中。

## 形状

使用轻度圆角的矩形玻璃控件、更大圆角的分区表面和浮动窗口，以及胶囊形主要文字操作。
仅图标的发送按钮保持圆形。frontmatter 记录了常用圆角刻度；保留组件特有的几何，
如首页输入框、移动端全屏邮件窗口和不对称的消息圆角。

控件一般使用共享的舒适高度（40px），紧凑图标操作为 36px。导航行保留其更大的点击区域。
明亮边框描述玻璃边缘；密集列表和输入框内使用弱化分隔线。

## 组件

### 按钮和输入框

主要、次要和危险角色保持区分。次要控件使用安静的玻璃；悬停时提高表面不透明度和对比度。
主要操作使用共享蓝色处理，破坏性确认使用填充的危险操作。通过现有蓝色描边或输入框
焦点环保持可见的键盘焦点。输入框背景比所在平面更不透明。禁用控件保留真实的 disabled
属性，抑制按压位移并去掉激活阴影。

### 成对图标和导航

`ActionIcon` 在同一画布（24px）上包含手绘线性和实心图形，通常以共享图标尺寸（20px）
渲染，线条为圆角（1.75 单位）。小型关闭和展开图形可以更小。实心状态使用专门的剪影和
透明细节；不要填充任意线性路径，也不要使用宽泛的 SVG 重置。

**真实状态规则。** 静止和悬停状态保持线性图形。真实的打开、选中、当前或按下状态显示
实心图形和更不透明的选中表面。关闭菜单或面板会恢复其线性触发器。一次性操作在启用的
按压期间可显示实心图形。禁用按钮不会获得按下状态。

这种配对覆盖工作台操作、设置导航和邮件分类。在现有选中类名之外使用语义状态属性，
如 `aria-expanded`、`aria-current`、`aria-selected` 和 `aria-pressed`。图标是装饰性的
（`aria-hidden`）；可访问名称保留在控件上。语音停止和进度指示保留其专用符号。
短暂的不透明度过渡（120ms）在减少动态效果时消失；避免装饰性动画。

“连接”目录的标识使用用户要求的磨砂双层插画：品牌蓝（`#086DE1`）的不透明后层形状和
浅蓝玻璃前层，带柔和重叠。八个生成的剪影填满现有 44px（桌面）/40px（移动端）图标区域，
不额外加外框。保留其透明背景、装饰语义和当前入口操作。资源和生成提示词位于
`apps/webchat/src/assets/connections/`。

连接详情中的服务商标识使用参考原始产品标志、由 imagegen 生成的位图线性图标：QQ 邮箱、
Outlook、Gmail、ChatGPT、Claude、Gemini、Grok、微信和 Telegram。以当前主题的品牌蓝按
22px 渲染其生成的 alpha。所有服务商剪影都保留在生成文件中，不使用手绘 SVG 路径。
资源和提示词位于 `apps/webchat/src/assets/connections/providers/`。这些标志保持装饰性，
并保留现有的登录、刷新、默认服务商、开关和删除控件。

### 页面、窗口和菜单

设置分区使用共享玻璃，内含更安静的嵌套行、分段选择和开关。日程在既有列表和对话框上
使用同样的材质。邮件的分类选择、对话选择和阅读面板保持各自的层级。通知收件箱和
提示条把磨砂作用于自身，保持固定定位。搜索、文档、设备和账户表面共享浮层材质，
不移除其现有控件。

对话保持开放式的助手回复和柔和圆角、浅品牌蓝表面的用户消息，外观示例同样如此。
用户消息不显示头部；回复只显示时间，受管 MCP 的需求消息保留其标签。回复没有点赞或纠正栏。附件和任务状态保留共享玻璃材质和语义色。
“新建对话”入口带文字，位于“最近任务”上方。侧边栏行在悬停或键盘聚焦时显示归档操作和右对齐的
单个省略号；触屏设备保持可见。归档只在这台设备上（浏览器存储，按所有者区分）把对话移出
最近列表；账户菜单可打开已归档列表，用同一操作恢复。重命名和删除位于浮动菜单中，具备视口内
约束、键盘导航和现有的删除确认。当前行、设置导航、邮件分类和日程入口使用安静的灰色选中填充，
而不是凸起的玻璃。聊天输入框控件在桌面端为 36px，
小屏保持现有紧凑几何。首页输入框几何保持不变。`conversation-preview.html` 是仅开发用的
审阅入口，用内存示例数据挂载真实的侧边栏、消息和输入框组件；它不参与生产构建，也不会向
网关提交任务。

日程导航位于共享侧边栏底部、账户菜单之上，在首页和日程页都一样。保持两个页面中的几何和
间距一致。Web 日程页在顶栏提供“返回首页”图标操作；桌面端使用标题栏的页面历史。两者都只切换页面，
不创建对话，也不清除当前对话或输入草稿。

运行时配对以同样的玻璃输入框和蓝色操作就地展开。密码框和钥匙操作共享 40px 高度；窄布局
下在首页和设置页都把表单放在连接说明下方。钥匙的线性和实心状态共享相同的外轮廓、钥杆、
单个短齿和孔位，选中只改变线条粗细。

深层展开使用相同材质：凭据和策略编辑器、签发和集成操作、邮件同步和审阅表单、语音操作，
以及浏览器溢出、传输和权限行。共享的其余控件位于 `glass-expanded.css`；空间有限时保留
紧凑的 36px 操作，并使用 40px 输入框、清晰的蓝色焦点和语义危险状态。设置、邮件和桌面登录
中的单选菜单保留原生选择和键盘语义，在支持的引擎上使用 `glass-select.css` 中的共享选择器。
使用安静的实心玻璃材质、16px 圆角、40px 选项行和品牌蓝选中勾。锚定在控件下方、对齐其末端，
仅在视口空间不足时翻转。邮件的地址触发器保留单独截断的值和展开箭头；其菜单保持足够宽以读出
地址。Escape 会先关闭打开的邮件选择器，再关闭外层邮件对话框。搜索和地址控件在圆角外框上
显示焦点，内部控件不再出现第二个矩形描边。

### 统一邮件工作区

邮箱、搜索、分类和对话构成一个视图范围。重新打开邮件会恢复该范围。任何导航都会先保存
正在进行的回复；失败时编辑器及其文字保留原位。新到邮件不会替换当前的回复对象。
邮件详情、回复身份和发送确认显示实际的收件/发件地址。

分类规则控制今后的发件人路由；分类标签只选择当前视图。分类图标各不相同：对话/勾选、
铃铛和收件箱，线性和实心轮廓互相匹配。

接收账户保留在现有同步展开区内，按服务商分组。每个附加账户有各自的登录、身份核验和
接收开关。打开登录从不开始接收。依据运行时和传输能力保持不可用操作为禁用；运行时不可用时，
若管理接口仍可用，仍允许停止已有账户。

在后端提供之前，附加接收账户只是前端界面：账户行和“添加邮箱”保持可见，其操作保持禁用，
直到账户列表报告 `multi_account_available`，且桌面端连接暴露 `mail_accounts` 能力面。
桌面端沿用不显示邮箱登录按钮的既有规则；身份检查和后端登录后的恢复接收仍可用。

原件清理在提交前确认其确切邮箱或全局/日期范围。确认说明本地原件和附件将不可用，而邮件
元数据/正文和远端邮箱中的邮件保留。它以内联方式位于原生邮件对话框内，以保持在该对话框
之上可见，默认聚焦“取消”，并把 Escape 视为取消。

### 反馈表面

错误和校验反馈使用同样的中性玻璃表面、1px 边缘、14px 圆角和常规可读正文。不要使用粗的
彩色侧边条或大面积红色区域。紧凑的状态图标承载错误、警告、成功或进度颜色；恢复操作保持在
相关消息旁，并保留全部错误文字、alert/status 语义和禁用状态。

### 输入框审批和绑定窗口

输入框审批以卡片（22px）替换输入区，使用同样的强玻璃。答案行使用 14px 圆角和 44px
最小高度；选中行显示蓝色边缘。提交是蓝色胶囊主要操作，在做出选择前保持禁用。
微信绑定窗口使用浮动对话框材质（26px），二维码位于白色 16px 圆角底块上。

### 确认框

应用内确认使用共享的 `ConfirmationProvider` 和 `useConfirm` 对话框。它是带标签的模态框，
具备焦点约束，默认聚焦 **取消**，Escape 和直接点击遮罩均视为取消，关闭后焦点回到触发控件。
请求排队处理；所有者在卸载时取消其待处理请求，provider 销毁时把待处理请求作为取消处理。
破坏性操作保留语义危险选项。原生 `window.confirm` 回退仅用于挂载在 provider 之外的独立组件。

## 应做与不应做

### 应做

- **应** 通过 `--ui-*` 扩展共享材质，同时保留首页几何和 `--home-*` 规则。
- **应** 保留所有现有路由、菜单、控件、业务行为和 API 边界。
- **应** 在浅色、深色、大字号和减少偏好模式下，同时验证原有交互和新样式。
- **应** 在用户需要处理时显示失败或恢复指引，并对暂时不可用的入口保留入口、禁用操作。

### 不应做

- **不应** 用简化页面替换现有界面，或为方便样式而删除入口。
- **不应** 模糊工作区或页头祖先、裁切浮动菜单，或让 body portal 依赖仅首页使用的令牌。
- **不应** 改变 Spark X 字标、图形标志、图标状态语义或确认框焦点行为。
- **不应** 添加虚构的连接状态、占位数据、常驻技术状态界面或装饰性动画。
