# 设计 QA——邮件对话回复

[English](../design-qa.md)

- 参考视觉真值：`http://localhost:3000/`（JingSi-mail 收件箱会话详情的浏览器原生截图）
- 实现截图：`http://127.0.0.1:4173/email-design-preview.html`（由 CUA 捕获并内联保存于任务证据；浏览器 API 未提供本地截图文件路径）
- 归一化视口：两者均为 1280 × 720 CSS px／图片像素，设备像素比均为 1
- 状态：选中会话、按时间顺序排列的逐封摘要（原文收在次级详情）、空回复意图框；聚焦检查另覆盖可编辑润色草稿和单次“发送回复”动作

## 发现

没有遗留可执行的 P0、P1 或 P2 问题。

- 字体：实现保留 SparkClaw 的 Inter／系统字体栈、深色主题层级和既有字重，没有复制 JingSi-mail 的浅色产品皮肤。标题、发件人元数据、逐封摘要、回复提示和按钮均清晰，无异常换行；这是有意的产品 token 差异。
- 间距与布局：归一化桌面对照保留“列表→选中会话→按时间排列的逐封摘要→底部回复框”的层级。回复框是历史滚动区的兄弟节点，不再覆盖邮件。390 × 844 下进入详情会隐藏仅列表需要的筛选／分类控件，为可编辑草稿和发送动作保留空间。
- 颜色：参考页的绿色强调映射到 SparkClaw 现有 `--cyber-blue`／绿色成功 token。选中、禁用、焦点和直接发送动作都与现有深色界面一致。
- 图片与资产：目标没有产品图片。可见动作使用现有 Lucide 图标；发件人首字头像与参考页的信息模式一致。没有引入位图占位、自制 SVG、CSS 插画、渐变或伪造 logo。
- 文案与内容：会话级 AI Overview 已取消。每封邮件以所选语言摘要作为主内容，原始正文保留在次级折叠详情。流程清楚表达“输入意图→生成可编辑回复→检查或修改→一次发送回复”。
- 可访问性与行为：邮件正文保留语义内容；意图和正文编辑框有标签；禁用状态可见；交互控件有键盘焦点；编辑后只有一个“发送回复”最终动作。

## 全屏对照证据

最终对照在同一次 CUA 输入中放入两张 1280 × 720、DPR 1 的浏览器截图。列表／详情构成、逐封消息层级、选中会话和底部回复入口一致。SparkClaw 有意保留自身全局邮件工具和三栏信息架构。

## 聚焦区域证据

回复区分别检查了空意图和已编辑润色草稿。实现实际走通输入意图、润色、直接编辑和单次“发送回复”。另以 390 × 844 检查详情和直接发送布局；最终新桌面标签的控制台没有警告或错误。

## 对照历史

1. 首轮发现 P1：粘性回复框覆盖会话历史；P2：程序化聚焦的非交互标题出现大号浏览器描边。已把回复框移到历史滚动区外，并移除非交互标题描边；复查显示底部回复区独立且历史可读。
2. 移动端发现详情仍保留筛选／同步／分类工具，挤占视口。详情态现在隐藏列表专用控件；390 × 844 复查无重叠、裁切或按钮断字。
3. 最终新开参考和实现标签，把两者归一到 1280 × 720／DPR 1，在同一输入中比较，并走通回复流程、检查实现控制台；无遗留 P0/P1/P2。
4. 用户后续明确移除二次确认，同时保留润色正文可编辑。最终动作改为单个“发送回复”按钮；底层版本化原生回复保存／发送栅栏保持不变。
5. 用户后续取消会话级 AI Overview，并把主内容改为随界面语言切换的逐封摘要。原始正文仍可在每封邮件的次级详情中查看；已同步历史邮件复用同一语言投影链路。
6. 部署验收打开了一封历史验证码邮件。本地化摘要既未暴露凭据，也未带出旧 CSS 前导；完整原件仍在折叠详情中，新开的部署后标签没有控制台警告或错误。
