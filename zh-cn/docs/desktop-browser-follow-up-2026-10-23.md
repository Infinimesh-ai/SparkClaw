## 范围与验收修正

负责人要求：自动化打开的网页应像正常浏览器一样，占满可用浏览区域，并随窗口、面板大小
变化。本轮要求是查明原因、核实 Codex 开源情况，并留存问题供后续一起解决。
本检查点仅更新记录，不修改、安装或部署产品代码。

此前[验收续接](desktop-iscp-capability-expansion-design.md#920-反向浏览器命令验收续接2026-10-23)
证明了原控件保留、原生网页能够打开。全屏、加宽只是临时绕行，不能作为视口体验验收通过。
固定尺寸、强制居中、小窗口整页消失，正式归为 **BR-01：未解决的产品缺陷**。
原有命令、重启恢复和数据保留证据仍有效。

## 已确认的本地原因

SparkX 在 [main.mjs](../../apps/desktop/src/main/main.mjs) 中为个人页、任务页创建真实的
本机 Electron `WebContentsView`。ISCP 负责命令与结果传输，用户看到的网页由本机浏览器
视图绘制。显示消失可由本地展示代码直接解释，无需假设传输故障或 Codex 的内部实现。

- [presentation.mjs](../../apps/desktop/src/main/presentation.mjs) 第 1–2 行将任务视图写死为
  640 × 720；第 145–150 行计算居中偏移，面板任一边不足就不返回显示区域。
- `showTask`、`setPanelBounds` 在上述条件下不显示或隐藏整张原生页面。个人页则直接使用
  全部面板尺寸，小面板也能显示。
- [BrowserPanel.tsx](../../apps/webchat/src/desktop/BrowserPanel.tsx) 已用 `ResizeObserver`
  测量可用区域并发送给主进程；任务页分支主动放弃自适应尺寸。因此仅补监听器、改 CSS
  居中样式，无法解除这里的限制。
- [page-registry.mjs](../../apps/desktop/src/browser/page-registry.mjs) 第 70–78 行释放控制权时，
  没有改变保留页面的 task 角色，所以任务完成后仍受同一限制。

[原内嵌浏览器设计](desktop-client-embedded-browser-design.md) 刻意固定活动任务视口，
并隔离人工输入；目的是保持自动化布局稳定，要求视口变化后重新取得证据。实现将这个选择
直接带到了用户观看的视图，甚至覆盖已完成页面。自动化本身并不要求用户只能观看固定矩形。
负责人本次要求更新了显示目标；控制权、授权和不确定写入保护仍须独立保留。

使用生产展示类和假的原生视图对象执行诊断，复现如下结果。这是逻辑诊断，不是新增原生
渲染验收：

| 页面 | 可用面板 | 实际决策 |
| --- | --- | --- |
| 任务页 | 800 × 900 | 仍为 640 × 720，偏移 (80, 90)，居中 |
| 任务页 | 640 × 720 | 恰好可见 |
| 任务页 | 639 × 720 | 整页隐藏，空间不足 |
| 任务页 | 640 × 719 | 整页隐藏，空间不足 |
| 个人页 | 480 × 600 | 可见，占满 480 × 600 |

这些是原生视图布局单位（Electron DIPs），不是 Retina 物理像素。应用最小窗口为
1180 × 720，扣除工作台和浏览器控件后无法再容纳 720 高的网页，因此单纯加宽也可能无效。
此前真实 Mac 现象另见 §9.20 的记录。

## Codex 开源核实

核实日期为 2026-10-23，来源为官方文档和官方 GitHub 仓库。查看到的 `openai/codex`
main 为 `d6817454d76885e9d0e118bbf82e507aed6f715a`；`openai/plugins` 仓库树为
`0722921d5542fc593105c27bd52630babd8b8c2a`。

| 部分 | 已核实的范围 |
| --- | --- |
| CLI、SDK、App Server | [官方开源清单](https://learn.chatgpt.com/docs/open-source) 明确列出；[Codex 仓库](https://github.com/openai/codex) 采用 Apache-2.0。 |
| Agent 集成接口 | [App Server 官方文档](https://learn.chatgpt.com/docs/app-server) 描述认证、历史、审批、Agent 事件流等集成；它不等于完整的桌面内嵌浏览器界面。 |
| 浏览器策略、配置 | 仓库公开了[内置浏览器配置要求](https://github.com/openai/codex/blob/d6817454d76885e9d0e118bbf82e507aed6f715a/codex-rs/config/src/in_app_browser_requirements.rs)及 browser-use 策略类型，不能据此认定视口和浏览器控制实现也已公开。 |
| 桌面浏览器视图与控制实现 | 本轮查看的公开仓库中未找到完整、可直接复用的实现。[浏览器官方文档](https://learn.chatgpt.com/docs/browser?surface=app) 描述用户与 Agent 共享桌面网页，并明确 CLI/IDE 不提供该内置浏览器；文档没有公开内部布局算法。 |

这是有范围的调查结论，不证明所有 OpenAI 浏览器相关代码都未公开。不能把整个 Codex
称为开源、推定其内部视图类型，或把安装包代码当成受 CLI 开源许可证覆盖的源码。
可参考其公开描述的使用体验；SparkX 已具备原生浏览器，无需取得 Codex 桌面源码才可自适应。
