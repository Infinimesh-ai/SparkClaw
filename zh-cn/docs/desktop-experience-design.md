# SparkX 桌面端字体布局与交互优化设计

> 语言：简体中文 | [English](../../docs/desktop-experience-design.md)
>
> 状态：原始设计日期为 2026-10-18；P0–P2 本地实现进度见[实现与验证](desktop-experience-validation.md)。未打包或部署。

建议保留 SparkX 现有工作台和全部功能入口，以“更容易阅读、更稳定的布局、更可预期的操作”为主线优化。第一阶段统一字体、间距、颜色和内容对齐；第二阶段优化输入、键盘、滚动和分栏交互；第三阶段完成邮件、文件、日程、设置的整体一致性。

## 1 范围与原则

面向 Electron 桌面端，优先以 macOS 中文使用场景验收，并覆盖 Windows、Linux 的字体回退和键盘差异。桌面默认窗口维持 1440 × 900，最小窗口维持 1180 × 720。共享 WebChat 组件需要做浏览器回归，但本次不重新定义移动端布局。

- 保留会话侧栏、日程、通知、账户菜单、邮件、文件、语音、浏览器面板和九项设置导航。
- 按本轮明确要求，移除右侧只有“浏览器”一项的工具选择中间层；顶栏改为浏览器图标，直接打开新标签页。这是对原菜单结构的指定调整。
- 在原组件内优化样式与状态呈现，不另做简化工作台，不迁移会话、草稿、凭据或任务数据。
- 保留 SparkX 标识、蓝色强调色及浅灰侧栏；采用系统无衬线字体，避免为模仿竞品引入中文不一致的衬线正文。
- 功能暂不可用时，入口仍在，相关操作禁用并说明原因。连接恢复、传输协议、队列等技术信息不成为常驻页面内容。
- 本文尺寸、颜色和交互是 SparkX 的建议值，不代表 Codex 或 Claude 的内部设计规范。

## 4 字体与视觉规范

### 4.1 字体和字号

界面和中文正文统一使用系统字体。建议字体栈为 `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。代码使用 `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace`。首期不下载网络字体；Linux 缺少中文字体时在安装依赖中解决，不能用图片替代文字。

| 语义 token | 默认字号／行高 | 大字号／行高 | 字重与用途 |
|---|---|---|---|
| `--font-body` | 16／28px | 18／32px | 400；会话正文、邮件阅读正文、输入文字 |
| `--font-ui` | 14／20px | 16／24px | 400；导航、按钮、设置字段 |
| `--font-label` | 13／20px | 15／22px | 500；分组标题、字段说明 |
| `--font-meta` | 12／18px | 14／20px | 400；时间、来源、文件大小 |
| `--font-title` | 22／30px | 24／34px | 600；页面标题 |
| `--font-section` | 16／24px | 18／28px | 600；设置分区、内容小标题 |
| `--font-code` | 13／21px | 15／24px | 400；代码块、需要精确辨认的标识符 |

数值均为 100% 页面缩放下的 CSS px。常用字重统一为 400／500／600；正文不加字距，不对中文套用全大写元信息样式。数字列可采用 tabular-nums；完整路径、URL、标识符需要可复制。

保留 `sparkclaw.appearance.text-size` 的 `default`／`large` 值，只替换呈现方式。更改字号后，侧栏仍为 244px，面板宽度偏好仍有效；行高与控件最小高度随文字容纳需求增长。不得同时应用 CSS zoom 和字号 token。系统／Electron 页面缩放作为独立可访问性能力保留，验证 100%、125%、150%、200%。

### 4.2 色彩与空间

| 语义 | 浅色建议 | 深色建议 |
|---|---|---|
| 主工作区 | `#FFFFFF` | `#171A1F` |
| 侧栏／次级背景 | `#F5F5F5` | `#20252C` |
| 主文字 | `#202226` | `#EDF0F4` |
| 次级文字 | `#626873` | `#B9C1CB` |
| 普通分隔线 | `#E3E5E8` | `#414954` |
| 蓝色按钮／链接／焦点 | `#2563EB` | `#93B8FF` |
| 强调按钮文字 | `#FFFFFF` | `#171A1F` |

沿用蓝色品牌方向，浅色按钮用较深蓝保证白字可读。分隔线用于组织内容；需要识别的输入边界、选中状态、焦点环单独验证。普通文字对比度目标至少 4.5:1，重要非文本控件至少 3:1；不能仅凭这些色值宣称全界面达标。错误、警告、完成状态同时使用图标和文字。

间距采用 4／8／12／16／24／32px；控件圆角 8px，内容卡片 12px，输入框 16px。图标保持现有 lucide 系统，常用图标 18px、可点击区域至少 32 × 32px，主要操作 36px。只在浮层使用明显阴影，正文以留白和标题区分层级。悬停／焦点过渡 120–160ms；系统“减少动态效果”下移除位移和非必要动画。

## 5 布局方案

### 5.1 基本结构

以下为结构线框，数值以本节表格为准；原生窗口标题栏在工作区之外。

```text
┌────────────────────┬─────────────────────────────────────────────┐
│ SparkX       收起  │ 本地工作区                    通知  浏览器图标│
│                    ├─────────────────────────────────────────────┤
│ 日程               │              会话内容列                     │
│ 最近任务  搜索 新建│       最大 760px，正文与输入文字对齐         │
│ 当前会话           │                              用户消息       │
│ 其他会话           │ SparkX                                      │
│                    │ 回答正文、列表、引用、文件结果                │
│                    │                                             │
│                    │ ┌─────────────────────────────────────────┐ │
│                    │ │ 输入文字／待发送附件                    │ │
│                    │ │ 上传  文件  邮件  语音              发送│ │
│ Owner  账户菜单    │ └─────────────────────────────────────────┘ │
└────────────────────┴─────────────────────────────────────────────┘
```

| 区域 | 建议规范 | 保留的行为 |
|---|---|---|
| 左侧栏 | 244px；左右 padding 12px；任务行最小 40px | 展开／收起、新建、搜索、改名、删除、当前项及完成提示 |
| 顶栏 | 工作区内 52px；左右 padding 24px | 工作区标题、通知、浏览器图标直接入口；收起侧栏后仍能重新展开 |
| 会话和输入内容列 | 共同最大外宽 760px；容器左右留白至少 24px；内部 padding 16px | 主滚动区独立，输入区常驻底部；用户消息右对齐且不超出内容列 80% |
| 消息节奏 | 消息间 24px；段落间 12px；列表项间 6–8px；小标题前 24px 后 8px | 保留完整内容、来源与附件；不以折叠正文减少高度 |
| 输入区 | 空态约 112px；底部距工作区 20px；文本区 1–6 行自动增高 | 附件、文件、邮件、语音、麦克风选择全部保留；超出文本上限后内部滚动 |
| 设置内容 | 最大 800px；页面 padding 32px；字段行最小 64px | 原九个导航分类及返回位置；说明可换行，控件不挤压说明 |

760px 指共享外框，不是每种气泡独立声明的上限。消息和输入文字都从该外框内侧 16px 起始；宽表格／代码在各自容器横向滚动，不撑宽整个窗口。列表、邮件和时间线使用页面级宽度，不强行限制到会话内容列。

### 5.2 浏览器直接入口

右侧只提供浏览器，不再呈现“侧栏工具→浏览器”的二级选择页。顶栏原 `PanelRight` 展开图标替换为现有图标库的 `Globe2` 浏览器图标，18px 图形、至少 32 × 32px 点击区域，位置与通知按钮的关系保持不变。悬停提示及可访问名称随状态显示“打开浏览器”或“收起浏览器”，并保留 `aria-expanded`。

```text
收起状态：[通知] [浏览器图标]
                     │ 点击
                     ▼
右侧直接展开： [新标签页 ×] [+]          [放大] [收起]
              [后退] [前进] [刷新] [搜索或输入网址…]
              新标签页内容区
```

| 操作或状态 | 明确行为 |
|---|---|
| 收起时点击浏览器图标 | 一步展开浏览器，选中新标签页，并聚焦地址栏；不经过工具选择页 |
| 已存在个人网页或任务标签 | 保留全部标签；本次展开选中空白个人标签，不覆盖原网页或接管任务页 |
| 已存在未使用的空白个人标签 | 优先复用；有未提交地址或其他用户输入的标签不视为可复用空白页 |
| 没有可复用空白标签 | 为本次用户展开动作创建一个；重复渲染、状态推送或快速重复点击不能重复创建 |
| 已展开时再次点击顶栏图标，或点击面板“收起” | 隐藏面板与原生网页视图，保留标签及其状态；焦点返回顶栏浏览器图标 |
| 点击标签栏“＋” | 沿用显式新建标签动作，并选中新增标签；不是展开二级菜单 |
| 关闭最后一个可关闭的个人标签 | 保持浏览器面板，显示可直接输入地址的新标签页空态；不返回工具列表、不自动关闭任务标签 |
| 浏览器暂不可用或打开失败 | 图标保留；不可用时禁用并说明原因，失败在浏览器区域提示；不恢复工具菜单作为降级界面 |

删除工具启动页、“返回工具列表”按钮，以及浏览器更多菜单中的同名动作；原位置需要保留收起能力时，直接改为“收起浏览器”。浏览器自身的标签栏、地址栏、前进／后退／刷新、下载与权限、更多操作仍属于浏览器内部控件，不属于本次移除的二级工具选择页。

实施时同时覆盖 `App.tsx` 的桌面分支和 `LocalWorkbench.tsx`，在原 `BrowserPanel.tsx` 内移除 launcher 状态。纯 WebChat 的非浏览器检查面板不随这次桌面入口修改而删除。地址栏焦点在展开和空白标签就绪后设置；之后的后台任务状态更新不能抢走用户正在输入的焦点。

### 5.3 右侧面板与窄窗口

保留浏览器默认 640px 和用户已保存宽度，分隔条仍支持拖拽与方向键。进入并排模式必须满足 `可用主区宽度 ≥ 520 + 6 + 面板宽度`；宽度指原生内容区扣除侧栏后的实际 CSS 宽度。

| 场景 | 预期布局 |
|---|---|
| 1440px 内容区、244px 侧栏、640px 面板 | 1196px 主区，可容纳 550px 会话＋6px 分隔条＋640px 面板 |
| 1180px 内容区、侧栏展开、640px 面板 | 主区 936px；面板使用主区聚焦模式，提供“返回对话”，不留下被遮住的输入框 |
| 侧栏收起或调整面板后满足条件 | 可返回并排，保留面板标签、会话滚动位置与未发送内容 |
| 用户明确放大面板 | 维持聚焦状态，直到用户退出；窗口变宽不能擅自退出 |

聚焦模式是原面板的布局状态，不新建另一套浏览器。因窗口缩窄自动进入聚焦时，窗口恢复足够宽可恢复之前的并排状态；边界增加 24px 回差，避免来回抖动。自动布局变化不夺取键盘焦点：焦点在会话时保留会话，通过原面板按钮切入浏览器；焦点在浏览器时保留浏览器，通过“返回对话”切回。暂时隐藏的区域保持挂载，对应原生视图同步隐藏。分隔条取得焦点时显示 2px 焦点指示，提供可读尺寸；原有拖拽收起行为保留。

Electron 原生 `WebContentsView` 不受普通 DOM z-index 控制。面板边界、页面缩放、弹窗遮挡和聚焦切换必须同步原生视图 bounds／可见性；打开应用模态框时不能让原生网页盖住审批或设置。不能通过重新加载网页实现布局切换。

## 6 核心交互

### 6.1 会话列表与查找

当前项以浅底色和字重区分，减少边框装饰；完整标题通过悬停或键盘焦点提示，操作按钮在 hover／focus 时出现，并预留位置避免标题跳动。搜索仍由现有入口与 Cmd/Ctrl+K 打开，支持方向键、Enter、Esc，关闭后恢复焦点。保留现有已查看完成提示的清除规则，不用永久蓝点表示所有历史完成任务。

### 6.2 输入与草稿

Enter 发送、Shift+Enter 换行维持原语义；中文候选确认时绝不发送，保留已有 composition 及结束后保护逻辑。发送是否可用继续由现有执行／语音／上传状态决定，不因视觉调整绕过业务保护。

- 长文本逐行增高至 6 行；更长内容在输入框内滚动。附件区单独占行并显示名称、状态和移除操作。
- 上传失败只在对应附件附近展示重试；不能清空已输入文字或其他成功附件。
- 发送成功后保留输入焦点；提交失败保留原草稿。会话切换沿用现有草稿隔离和持久化能力。
- 语音录制时在原语音区域展示录制／转写／失败及既有停止或重试操作；切换会话时仍遵守原限制。
- 生成期间保留现有排队／禁用语义。停止按钮只有在已有可靠取消能力时启用；本设计不凭空增加取消 API。

### 6.3 长回答和流式反馈

用户停留在底部时跟随新内容；主动上滚超过 80px 或选中文字时停止自动跟随，出现“回到最新”按钮。点击后恢复跟随。切换会话保存并恢复各自的阅读位置；最终结果替换流式预览时保留消息锚点，不重置整个列表。

进行中的操作在当前回复内用一行简短状态呈现，例如“正在整理资料”；必要时展开既有步骤。审批必须明确展示操作对象、范围和确认按钮。完成后收起过程信息，突出结果和文件。不得删改模型正文中的事实、风险、引用或限制来美化界面；来源链接与系统状态的渲染优化必须保留原文可访问性。

### 6.4 状态与恢复

| 状态 | 展示与操作 |
|---|---|
| 初次加载 | 与最终内容结构接近的轻量占位；短于 300ms 的加载不闪出占位 |
| 正在执行 | 当前任务／回复的简洁进度，不在全局顶栏重复堆叠 |
| 等待审批 | 原审批入口与对应会话内明确提示；只读预览与批准动作分开 |
| 自动重连且可恢复 | 保存草稿和已显示结果，保持界面稳定；无需用户处理时不弹 Toast |
| 需要重新连接或授权 | 在受影响入口附近解释原因并提供“前往连接设置” |
| 提交结果未知 | 显示“正在确认上次提交结果”，沿用原请求身份查询；不得显示会产生重复副作用的普通“重试发送” |
| 明确失败且可安全重试 | 简短原因＋匹配已有语义的操作；技术详情按需展开 |
| 能力不可用 | 原入口保留，相关动作禁用；键盘可获取禁用原因 |
| 后台完成／新通知 | 沿用通知中心与当前未读语义；前台已读不重复打断 |

### 6.5 键盘与焦点

| 动作 | 快捷键建议 | 范围 |
|---|---|---|
| 新建会话 | Cmd/Ctrl+N | 保留已有行为与忙碌／录音限制 |
| 搜索任务 | Cmd/Ctrl+K | 保留当前语义，不改成命令面板 |
| 展开／收起侧栏 | Cmd/Ctrl+B | 新增；可编辑区域或网页已有含义时不拦截 |
| 工作区设置 | Cmd/Ctrl+, | 新增；返回时恢复原页面 |
| 关闭当前浮层 | Esc | 菜单→对话框→面板逐层处理，不同时关闭所有层 |
| 分隔条调宽 | 方向键；Shift 加大步长；Home／End | 保留原键位，范围受布局模式约束 |
| 控件遍历 | Tab／Shift+Tab | 焦点顺序与视觉顺序一致，焦点始终可见 |

弹窗打开时聚焦标题或首个操作，模态弹窗限制焦点范围，关闭时回到触发控件；非模态面板允许在会话与面板之间往返。原生网页或编辑区的 Esc、复制、撤销、格式操作优先由当前内容处理。应用快捷键不能重复被主进程与 React 各执行一次。

## 8 实施顺序与工程边界

| 阶段 | 内容 | 对应文件 | 完成出口 |
|---|---|---|---|
| P0 视觉基础 | 字体 token、深浅主题、字号档位、间距、消息／输入列对齐 | `foundation.css`、`appearance.css`、`workbench.css`、`conversation.css`、`composer.css` | 主会话和设置页的默认／大字号截图评审通过 |
| P1 操作连续性 | 浏览器图标直达新标签页、移除工具选择页；输入增高、滚动锚点、焦点返回、Esc 层级、快捷键、面板布局 | 原 `composer.tsx`、`messages.tsx`、`App.tsx`、`LocalWorkbench.tsx`、`BrowserPanel.tsx`、`inspectorResize.tsx` 及 desktop bounds 适配 | 浏览器一步打开、中文输入、键盘、流式完成、窄窗口原生面板场景通过 |
| P2 全页面收口 | 邮件、文件、日程、通知、九项设置及深色细节 | 对应原组件与样式 | 全部保留项和可访问性矩阵通过 |

先整理现有 CSS 导入顺序与覆盖关系，不再以不断叠加高优先级选择器修补差异。桌面布局选择器应受桌面宿主范围约束；公共排版 token 可共享，但必须验证 WebChat 不受非预期影响。实现可按阶段回退；字号与面板偏好读取旧值，业务数据不需要迁移。

本设计不变更 Gateway、ISCP、JingSi 或 IMMS 的对外契约，不引入新的执行状态、自动重试或权限。如果实现发现必须新增后端能力，应单独立设计与 InfiniCenter 决策，不能塞入 UI 优化。

## 9 验收标准

### 9.1 视觉矩阵

使用脱敏固定样例覆盖空会话、短回答、2000 字中文长回答、中英混排、嵌套列表、表格、代码、长 URL、附件、审批、失败、邮件、日程和九项设置。

- macOS：1180 × 720、1440 × 900、1920 × 1080；浅色／深色／跟随系统；默认／大字号。截图注明内容区尺寸、系统缩放、页面缩放和字体，不能把 Retina 像素当 CSS px。
- Windows、Linux：至少默认窗口和最小窗口各验证中文字体、控件截断、快捷键；缺少目标环境时标为待验收。
- 100% 下正文与输入文字起始线偏差不超过 2 CSS px；全页面无意外横向滚动；主要操作、最后一条消息与输入区不互相遮挡。
- 页面缩放 125%、150%、200% 下主要内容和动作仍可达；允许滚动或切换聚焦布局，不允许截断后无恢复入口。
- 颜色对比度用实际计算样式验证，覆盖正常／悬停／选中／焦点／禁用；深色模式检查每一种浮层和原生视图周边。

### 9.2 行为矩阵

| 场景 | 必须满足 |
|---|---|
| 中文拼音确认＋Enter／Shift+Enter | 选词不误发，换行不误发，真正提交只发生一次 |
| 1 行到 30 行输入＋附件失败 | 高度有上限，文字和成功附件不丢失，键盘焦点连续 |
| 生成中上滚、选中文本、切换会话、最终回复到达 | 阅读不被拉回、选择不被打断、会话位置隔离、最终内容完整 |
| 搜索＋菜单／对话框＋右侧面板 | Esc 一次仅关闭最上层，焦点回到对应入口 |
| 顶栏浏览器入口首次打开、收起后重开、已有网页、最后一个个人标签关闭 | 一次点击直接进入新标签页，地址栏可输入；旧网页与任务标签保留，不出现工具选择页或“返回工具列表” |
| 快速连续开关、重新渲染、后台浏览器状态推送 | 不重复创建空白标签，不抢走地址栏输入焦点，收起后原生网页不可见 |
| 面板拖拽、收起、放大、缩窗、切换字号 | 无不可达遮挡；页面不重载；原生 view bounds 与可见区域一致 |
| 断网恢复、提交结果未知、权限失效 | 草稿保留；沿用原请求对账；不重复执行，不误显示成功 |
| 原功能回归 | 会话改名／删除、邮件、文件、语音、日程、通知、全部设置入口及操作仍可用 |
| 只用键盘／屏幕阅读器 | 有可访问名称和可见焦点；模态焦点可退出；状态变化不重复逐字播报 |

本地输入和菜单反馈目标在 100ms 内；该目标不包括网络、模型生成或任务执行耗时。验证长列表与流式更新时不因每个 token 触发整页布局或丢失滚动锚点，具体性能结果在实施阶段记录。

代码实施时运行受影响的 WebChat 测试和严格构建；涉及快捷键、面板 bounds 或原生窗口再运行对应 Desktop 检查。功能测试不能代替截图对照和原生窗口手动走查。本次文档交付只验证文档镜像、链接和设计内部一致性，不声称上述验收已通过。

## 10 评审建议

建议第一版采用：系统无衬线字体、16px 正文／14px 导航、760px 共用内容列、244px 原侧栏、52px 顶栏；保留现有颜色方向和全部功能入口。右侧浏览器入口已按本轮要求明确为“浏览器图标→新标签页”，删除工具选择中间层。先评审 P0 的长回答、空会话、设置三类样稿，再进入 P1 的面板和操作优化。

方案的主要取舍是正文增大后，同屏字数会减少；通过降低顶栏高度、缩减空输入区域和统一段落节奏补偿。首期不增加字体选择器、主题市场、全局快捷输入窗口或第二套导航，避免把本次体验优化扩展为新产品功能。
