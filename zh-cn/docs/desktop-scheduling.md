# 桌面工作台调度

> 语言：简体中文 | [English](../../docs/desktop-scheduling.md)

桌面 main 进程在其私有工作台 SQLite 数据库中保存调度定义与执行轮次，并通过普通
执行客户端提交到期任务。保存未来任务不请求后端，不创建执行服务租约或计时器。

首次到期须在未来 366 天内。界面支持单次，或每 1 小时、24 小时、7 天按固定时长
重复；main 接受 1 分钟至 366 天的重复间隔。间隔计算实际经过的时长，因此
“24 小时”不是跨夏令时切换的日历／时区循环。每个轮次保留用户明确保存的输入与
上下文，分配新的不可变请求 ID，并归属原对话；其他工作台不会自动获得这些定义或历史。

## 到期行为

main 调度器运行且认证连接可用时建立在线区间。到期位于连续可用区间内的轮次，通过
独占 SQLite 事务领取。事务先持久化提交意图和私有单次派发凭据，再走普通执行 POST。
并发 tick 或 main 进程恢复不能再次领取同一轮次。同一区间内的正常计时器延迟仍可派发。

进程重启、认证代次变化、断线和 `powerMonitor` 休眠事件都会终止在线区间。新在线
区间排除所有已经到期但尚未领取的轮次，将其永久标记为 `missed`。休眠处理还阻止
晚到的连接成功回调在唤醒前重新启动调度器。隐藏窗口不会停止 main 调度器。

循环任务的离线错过轮次以有界区间保存：`due_at`、`interval_ms`、`missed_count`
与 `missed_until` 可确定每个被跳过的到期时间，不积累离线待执行队列。只有下一次
未来轮次保持待执行。取消定义会取消未来轮次；已准入的轮次遵守普通执行取消规则。
“立即执行新请求”明确创建新执行，不复活错过的轮次，也不复用其 ID。

如果在持久化领取和 POST 之间崩溃，重启后保守地视为不确定，只核对已经记录的请求 ID。
POST 回包丢失后即使查询得到 404，也不能再次 POST，包括用户再次点击提交。若派发前
认证变化，仍未消费的派发凭据可证明本次尚未发送，并将其记为错过。可靠结果落盘、ACK
重试、审批和取消继续遵守普通执行客户端规则。

## 存储和验证

研发版本切换直接初始化选定 schema。不支持的旧目录会显式报错；此代码不升级其
schema，也不导入或删除其数据。选定版本中新建的数据在普通重启后保留，包括调度定义、
领取记录、错过区间与交付回执。

改动前受影响的 29 项桌面测试全部通过。实现验证通过全部 116 项桌面测试和 WebChat
生产构建；回归覆盖两个 SQLite 领取者、在线计时抖动、重启／重连、休眠／唤醒生命周期、
认证变化、磁盘故障、循环未来轮次身份、POST 前崩溃、回包丢失／404，以及撤销尚未发送
的领取。渲染层测试覆盖单次和循环调度提交。这些确定性测试不代表原生系统休眠／唤醒
或打包发布验收。执行服务成套 API 切换及退休未来租约处理器的移除，随整体统一重构
版本验证。
