# 桌面工作台调度

> 语言：简体中文 | [English](../../docs/desktop-scheduling.md)

桌面 main 进程在其私有工作台 SQLite 数据库中保存调度定义与执行轮次，并通过普通
执行客户端提交到期任务。保存未来任务不请求后端，不创建执行服务租约或计时器。

首次到期须在未来 366 天内。界面支持单次，或每 1 小时、24 小时、7 天按固定时长
重复；main 接受 1 分钟至 366 天的重复间隔。间隔计算实际经过的时长，因此
“24 小时”不是跨夏令时切换的日历／时区循环。每个轮次保留用户明确保存的输入与
上下文，分配新的不可变请求 ID，并归属原对话；其他工作台不会自动获得这些定义或历史。

## 从聊天显示本地日程

聊天原文仍进入普通的已认证执行服务。桌面主进程在用户明确提交聊天时加入与输入摘要绑定的
`client_presentation` 能力、IANA 时区及请求时间。后端通过现有 guard 和语义路由选中
`schedule.manage#read`，再解释展示范围：完整的简单日历表达使用有界日期解析，其他请求使用严格
结构化决策，返回 `schedule.show` 客户端动作。
后端不查询自己的提醒库，也不接收本地日程内容；请求和会话 ID 来自已认证执行绑定，不能由模型
生成。后端回复只说明已请求打开，不提前声称本地数据已显示。

动作包含本地日历日期范围（含起始日，不含结束日）、时区和五分钟有效期。两个日期均为空表示
本机可见的全部日程；范围最多 366 天。模糊或无法表达的筛选条件要求澄清。此动作不执行分析、
计数、摘要或修改，原日程创建、编辑、取消及到期行为仍由各自路径处理。

“显示明天的日程”等简单表达只有在语义路由确认日程读取后才提取日历范围；解析器匹配完整
句式，否定、排除、多日期、时段和分析条件继续走结构化决策。`tomorrow`、`next_week` 等相对
范围由后端基于原请求时间和时区计算，模型不能同时提供日期字符串。明确写出的单日保留原
年份，结束日由代码计算。

桌面将动作、已验证结果及投递回执原子保存。只有当前活动会话里明确提交的请求才能打开现有
日程页。主进程检查原身份范围、会话、能力和动作标识，单次领取动作后读取并筛选本地日程库。
继续使用原页面、展开的日程列表、侧栏、编辑、删除确认、新建弹窗和聊天草稿；手动点击侧栏
日程入口恢复完整列表。本地日程内容不会上传。

界面实例标识用于拒绝重载前的旧回调。加载历史、重复投递、切换会话及界面／进程重启都不会
重复跳转。中断的已领取动作转为 `skipped`，不推定此前是否已展示。原页面渲染本地数据后才
报告 `shown`（空列表也算成功显示）；本地读取失败报告 `failed`。有限状态回执本地持久化，
通过原执行 ACK 独立于结果持久化 ACK 重试，始终保留原请求 ID。相同回执幂等，冲突回执拒绝；
重试不会重新提交聊天任务。

这是 SparkClaw 现有 execution 操作中的业务载荷扩展，不改变 ISCP 帧、认证、传输恢复或
其他项目的契约。后端与桌面须配对发布：旧客户端仍使用原请求和结果格式，但旧后端的严格
解码器不接受新桌面的能力字段。

## 到期行为

main 调度器运行且认证连接可用时建立在线区间。到期位于连续可用区间内的轮次，通过
独占 SQLite 事务领取。事务先持久化提交意图和私有单次派发凭据，再走普通执行 POST。
并发 tick 或 main 进程恢复不能再次领取同一轮次。同一区间内的正常计时器延迟仍可派发。

进程重启、认证代次变化、断线和 `powerMonitor` 休眠事件都会终止在线区间。新在线
区间排除所有已经到期但尚未领取的轮次，将其永久标记为 `missed`。休眠处理还阻止
晚到的连接成功回调在唤醒前重新启动调度器。隐藏窗口不会停止 main 调度器。

循环任务的离线错过轮次以有界区间保存：`due_at`、`interval_ms`、`missed_count`
与 `missed_until` 可确定每个被跳过的到期时间，不积累离线待执行队列。只有下一次
未来轮次保持待执行。取消定义会取消未来轮次；已准入的轮次遵守普通执行取消规则。
“立即执行新请求”明确创建新执行，不复活错过的轮次，也不复用其 ID。

如果在持久化领取和 POST 之间崩溃，重启后保守地视为不确定，只核对已经记录的请求 ID。
POST 回包丢失后即使查询得到 404，也不能再次 POST，包括用户再次点击提交。若派发前
认证变化，仍未消费的派发凭据可证明本次尚未发送，并将其记为错过。可靠结果落盘、ACK
重试、审批和取消继续遵守普通执行客户端规则。

## 存储和验证

ClientStore schema 13 仅新增展示动作账本。受支持的 schema 6–12 原地升级，保留已有
安装 ID、原请求上下文、消息、草稿、文件和日程；不改写原请求摘要。不支持的版本仍显式
报错。调度定义、领取记录、错过区间、交付回执与展示回执在普通重启后保留。

最初调度实现前受影响的 29 项桌面测试全部通过；该次实现验证通过全部 116 项桌面测试和 WebChat
生产构建；回归覆盖两个 SQLite 领取者、在线计时抖动、重启／重连、休眠／唤醒生命周期、
认证变化、磁盘故障、循环未来轮次身份、POST 前崩溃、回包丢失／404，以及撤销尚未发送
的领取。渲染层测试覆盖单次和循环调度提交。这些确定性测试不代表原生系统休眠／唤醒
或打包发布验收。执行服务成套 API 切换及退休未来租约处理器的移除，随整体统一重构
版本验证。

展示链路有独立原生验收入口：
```sh
SPARKCLAW_STREAM_FIXTURE_ISCP_SOURCE=/path/to/ISCP \
SPARKCLAW_STREAM_FIXTURE_LINUX_IMAGE=<prepared-image> \
  node apps/desktop/test/run-schedule-native-qualification.mjs
```
它以合成本地日程连接 Linux 中的生产 Go agent、加密 ISCP 与生产 Mac Electron 界面。
使用 Node 26、Go 1.25 和 Docker；`--real-model` 还要求在
`SPARKCLAW_STREAM_FIXTURE_MODEL_CONFIG` 指定私有模型配置的绝对路径。
源码测试和原生证据必须与发行包的部署、安装区分。

2026-10-30，源码 `95d830d1` 使用 work2 配置的真实模型完成原生整链验收：6 组场景、4 次原请求
执行、2 条持久 `shown` 与 1 条 `failed` 回执。覆盖原筛选页面、编辑／删除／取消／新建弹窗、
返回、草稿、历史和重载去重、原折叠列表展开、空结果、Owner 隔离及本地读取失败。
上传本地日程内容和直接业务 HTTP 请求均为零。work2 原容器、启动时间、挂载集合、配置及模型
目录摘要不变，前后均健康。此前 mock 模型原生测试同样通过 6 组场景。

最终桌面 593 项通过（1 项跳过）、WebChat 561 项通过、生产构建通过；Linux Go 5,680 项
通过（含子测试，203 项跳过），build／vet 通过；137 份 Markdown 及双语镜像和链接检查通过。
真实模型把明天算成今天、或扩大为全部的失败记录保留，后续日历解析和绑定原请求时间的计算
修复了这些问题。[验收回执](../../docs/evidence/desktop-schedule-presentation-2026-10-30.json)
记录源码、摘要、确切范围及保留诊断。本轮未安装桌面、部署 Gateway 或修改共享契约。
