# 摘要定位与幻灯片图形评估 — 2026-11-09

语言：[English](../../docs/document-workflow-evaluation-20261109.md) | 简体中文

本轮在 `codex/document-system` 的 `13402280` 基础上继续改进，新增 `document.read`
revision 8、总结契约 4（源码提交 `518fab07`）。保留一个 Workflow 和原有 UI；节点内部可以分批总结原文或读取
选定幻灯片图像。失败记录及 revision 4/5/6/7 的历史执行契约继续保留。

## 采集暴露的原因

[上轮评估](document-workflow-evaluation-20261105.md) 已记录：七项检查内容正确，但摘要
误称位于“第 21 节及附录前”。原文标题在 `document.p[641]`，属于“快速复习与仓库阅读路线”，
位于附录之后。分节摘要把原生定位压成模型文字，最终模型又推测章节归属及常规附录顺序。
分组后的总结单元不是原文的章节编号。

新增同名标题样例还暴露了分节模型的职责错误：它把“当前这节没有用户要求的内容”推断成
“全文缺失”。最终回答因此称材料不完整且矛盾，虽然原文采集完整、关键词检查也通过。
该失败完整保留。改写原始长文档问题又触发了定向读取：最初定位表只接入 summarize，
范围读取仍会定位错对象，并把“清单说应理解限制”误当成限制正文。本轮继续补齐了这条路径。

原始 PPT 第 14 页含 65 个原生节点，其中 28 个非文本形状未被原生解析支持，主要是矩形、
背景和一个自由形状。这不等于有 28 条事实未读。旧读取链路没有把整页渲染图像送入模型。
新增左箭头样例因此只输出 ALPHA/BETA 名称、无法判断方向，关键词检查仍通过；纯图片柱状图
则无法读取数值。

## 已实现的改动

- 总结契约 4 将原生标题、段落位置、父级位置及原文顺序直接送入最终证据，绕过分节和合并
  摘要的有损改写。同名标题保留不同位置；定位表计入同一预算，不截断成不完整 JSON。
  范围读取同样携带来源定位元数据，但元数据不能证明对应正文已读。
- 分节模型只总结当前原文，不能作全文缺失判断；范围选择必须包含用户所要求主题的实际
  说明段落，不能用清单中“应理解某概念”的要求替代概念正文。
- Revision 8 读取选定 PPTX 页的图像，复用固定版本 Gotenberg/PDFium 渲染链路，输入为
  不可变来源快照。每次真实图像调用绑定来源哈希、页码、PDF/PNG 哈希和模型调用 ID。
  即使修改视觉 QA 被禁用，读取也独立校验 renderer 端点及允许列表；不使用修改 QA 评审模型。
- 每次最多处理八页，或 renderer 配置的更小上限。未处理页、模型输出不合法、基础设施不可用
  都保留明确记录；来源变化或渲染完整性错误停止读取。续读不重复图像调用。
  原生对象覆盖率不被改写为完整，页图像已处理不等于逐对象精确解析或理解无误。
- 最终证据保留原生文本与图像观察，并分别记录覆盖情况；部分回答不再把原生 shape 缺口
  说成图像未读。持久化旧版本仍按原契约执行。
- 离线评估脚本核验实际的 `model.http.dispatched` 事件、图像哈希及来源／页码／调用绑定。
  语义验收必须绑定本次 run ID 和回答哈希，分别检查任务完成、来源定位、图形关系及限制说明。
  关键词检查保持独立，未复核不能自动通过。

## 样例与复核方式

Owner 文档使用 `test-files/document-evaluation-20261109/workspace` 内的副本。
新增 DOCX 包含不同父标题下的同名检查，并用另一份文档反转附录顺序、取消章节编号。
新增 PPTX 包含分组装饰矩形、与文字排列直觉相反的左箭头、纯图片柱状图
（37、82 units/hour，差值 45）、相邻干扰页（999、111）及更换名称的右箭头变体。

评估串行运行生产 Runtime、ToolHub、真实 Fast 模型、OCR 和文件存储，使用隔离的内部采集配置。
复核比对 DOCX 原始段落／原生结构，以及模型请求中实际传入的 PNG 字节，而非模型声称看过图像。
所有结果 JSON 与封存 ZIP 保留在 Git 外，包括旧基线、失败运行和未能奏效的提示调整。
来源比对由编码代理完成，不是独立人工评分，也不是统计准确率估计。

仓库入口为 `eval/document-workflow/generate_location_visual_fixtures.py`、
`location-visual-cases.json`、`location-visual-variants.json`、`analyze.py` 及原有
`TestRealDocumentWorkflowEvaluation`。`analyze.py --reviews` 接受逐次运行的来源复核记录。
首版样例元数据误用了 DOCX 定位前缀；修正后的原生 `document.p[N]` 真值另外保存，原记录未覆盖。

## 结果与仍保留的缺陷

本轮保留 **13 个不同请求、33 次真实运行**：粗检查通过 32 次，来源／回答语义复核接受
21 次。33 份导出全部完整封存；核验 2,357 个 payload 哈希、242 次模型 HTTP 请求及
11 个真实 PNG 输入。这些是反复诊断的运行，不是 33 个独立样本，也不是准确率估计。

| 运行目录 | 次数 | 粗检查通过 | 语义接受 |
| --- | ---: | ---: | ---: |
| `baseline-results` | 3 | 2 | 0 |
| `fix1-results` | 3 | 3 | 3 |
| `owner-fix1-results` | 4 | 4 | 3 |
| `final-results`（首次较广复跑） | 11 | 11 | 9 |
| `qualified-results`（追加探测） | 2 | 2 | 0 |
| `range-fix-results` | 3 | 3 | 2 |
| `order-fix-results` | 1 | 1 | 0 |
| `regression-results` | 6 | 6 | 4 |

每个请求取**最新一次、而非最好一次**，结果是 **13 项中接受 8 项**。未接受的五项分别为：
长文档摘要、复合摘要定位任务、PPT 对比中的无来源延伸、采访摘要的证据性质分组，以及
工作表公式解释。最后一次广义摘要又将末尾检查称为“附录”；之前答对的记录不能抹去这种
不稳定性。原生定位改善了输入契约，不保证最终措辞正确。

定向读取探测通过运行时计算的同级前后关系（前后各最多八个邻居），已经正确指出 p641
属于 p580、位于附录 C 的 p630 之后。但整个任务仍未通过，因为它读取的是“应理解限制”的
清单，而不是 CloakBrowser 限制正文。r8 不再在搜索阶段冻结内容任务模式，实际内容范围
和续读仍保持冻结；这允许后续改选总结，但不宣称模型一定能作出正确选择。

观察到的左右箭头、图片图表及原始第 14 页都补上了视觉采集；但最新 PPT 对比仍扩写了
原页没有的大数据、复杂网络、对顺序不敏感等场景建议。视觉提取正确不等于最终综合严格
依据来源。部分回答还暴露内部节点／状态名称，属于未解决的表达问题。

按用户要求，本轮停止继续针对个别样例叠加提示或强制修正答案。未证明有效的重复证据状态
提示已删去，未为这次措辞清理再启动模型刷样例。采集保留各探索版本的精确输入和回答，
最终源码的工程验证与语义验收分别记录。私有目录内的 `semantic-reviews.json`、
`all-attempts-analysis.json`、`latest-results.json`、`review-ground-truth.json` 和
`review-images/` 保留完整复核链条。

现有 Workflow 对原生 PPT shape 缺口仍保守返回 `blocked`，即使选定页图像已经足以支持回答。
这个状态本身不证明语义成功或失败，应分别检查原生与视觉覆盖。文本提取、页图像处理和
逐对象精确解析是不同能力。

本轮主修范围外的两个失败说明了模型仍有能力边界。采访摘要保留了“模拟”限制，却仍把
模拟访谈归入“已有事实”；多次明确提示未能可靠消除这种分类错误。工作表回答正确算出 220，
也识别缓存 999，但错误称 `SUM(B3:B5)` 未排除已取消的 B6。这是无依据的原因解释，不是
算术错误。两者都通过粗事实检查，但未通过语义验收。后续需更强的证据性质分类和公式引用
范围绑定，本轮不宣称已经解决。

最终措辞仍由模型生成：原生定位表约束输入，却不是确定性的引用校验器。图像模型可能误读
小字、歧义箭头、复杂分组或图表；renderer 仍有资源与结构上限，超过页数预算的部分明确未完成。
定位表过大也可能耗尽总结／最终预算，此时返回限制而不猜位置。本轮改善了已观察样例，
不能据此保证任意 PPT 图形理解、完美摘要或不受限制的整份幻灯片读取。
