## 当前邮件读取契约（2026-09-18）

### 结构化内容与用户点击操作（2026-09-18）

Remote 产品现已在原有 MIME 遍历中生成持久化 `structured-mail-v3` 内容，只通过 owner 鉴权的
`render-preview` 接口提供。WebChat 用 React 呈现已知语义节点，不使用发件方 HTML 或 iframe。远程
图片、样式、表单和主动内容被移除；已校验且有界的 CID PNG／JPEG／WebP 可以保留。合法的绝对
HTTP(S) 认证、确认和参考链接会成为明确操作并显示实际域名，但用户点击前不会产生请求。纯文本邮件
也使用同一套转义后的结构化界面；`BodyText` 只作为搜索与模型分析的内部证据保留。

普通 MIME 附件会在同一次解析中从已校验原件解码到 owner 隔离的本地文件。附件字节不会进入
`BodyText`、模型证据、摘要或结构化正文制品，WebChat 只取得下载元数据。WebChat 不嗅探或预览附件
内容；只有用户明确点击后，才通过 owner 鉴权接口以 `application/octet-stream` 下载，并重新校验大小
与 SHA-256。正文引用且受限的 CID 资源仍属于结构化正文呈现，不是附件预览。当前提取上限为 20 个
附件、单个 25 MiB、合计 100 MiB；超限或提取不完整会保留明确来源缺口，已校验原始邮件继续留存。

运维迁移已覆盖当前 8 封保留邮件且零失败，部署镜像第二次执行复用了全部 8 份产物。手动清理原件后
投影仍保留；删除整个对话会清除其记录及文件。Gateway 镜像
`de17b2ba8b085aa4b22c760535ec4167ee3f20f072669b7c242f97ae280f69c4` 健康，WebChat 镜像
`ead37ba2ae0de2a7d12a1270b266bd5fa167c4bb5badef0c8f602cd4dbe52fc1` 返回 HTTP 200。完整证据见
[安全邮件结构化内容呈现设计](email-safe-html-preview-design.md)。

专用浏览器中的托管 Reader 是邮件读取唯一来源。列表发现、分页、稳定邮件身份和原件字节，必须来自已登录页面中由 Reader 观察或重放的提供方网络请求。DOM 检查、菜单导出和页面点击不能作为邮件来源证据；上游请求变化时，在专用浏览器重新观察真实请求，维护对应适配器并重新验收。只有在 Reader 绑定精确已观察目标、且能用新的提供方响应独立确认结果时，才允许用提供方原生页面动作发起单独授权的可变效果。

发现只有 `recent_inbound` 一个通道，每次发现／分页请求都必须带 `interval_start`、`interval_end`。正常同步枚举半开区间 `[last_completed_fetch_time, fixed_current_time)`，首次下界为持久化部署时间。已读状态只是远端观测证据，不决定是否纳入。原件采集与 mark-read 解耦；mark-read 失败不撤销已成功采集，也不改变同步边界。QQ mark-read 已通过实机验收并对 QQ 自动接收默认开启：Store 提交完整来源后，Reader 只触发精确已观察邮件行，再重放已验收的 `/list/maillist` 页面；只有同一邮件返回 `unread=0` 才在 Store 记录 `read`。目标缺失、响应结构变化或超时均保持 `unknown`。Gmail／Outlook 在取得同等级实时证据前继续 fail-closed；不存在 `unread` 通道或 `inbox_unread` coverage。

专用 Browser Bridge native socket 与 Controller 当前健康。实时测速已两次完成 QQ 的网络列表与原件采集；Outlook 当前没有可观察的 `ItemRows`／Inbox `ConversationRows` Worker 模板，Gmail 当前没有匹配 `/sync/u/<account>/i/bv` 的列表请求。这两家要等重新观察到当前网络请求并维护适配器后才能验收；发现失败耗时不计作邮件获取耗时。

## 已实现链路

自动接收现以固定时间区间的网络列表为一个浏览器任务：持久保存网络清单，通过网络适配器
逐封获取已证明身份的原件、保存 MIME 部件，并在本地来源持久化后单独处理 mark-read。
每封处理完返回原列表；一页最多 50 个已证明身份的邮件，虚拟列表及不完整会话仍明确报告 partial。

整轮完成后默认空闲 20 分钟。每页脚本预算 30 分钟，单一通道的外层总预算 95 分钟，
租约 3 分钟、每分钟续租。传输失败至少 20 分钟后重试（最多 5 次）；单封导出失败保留未确认
页供下个正常轮次重试，其他通道继续。已经保存原件、仅附件提取不完整的 partial 结果可以
结束浏览器采集，缺口保留给本地处理，不无限重复下载。

QQ、Gmail、Outlook 并行；每个邮箱的页面与页内邮件串行。自动接收仅启动按页作业，首次
页接纳会将旧 capture／mark_read／thread_sync 队列标为被替代，不伪造成功或已读状态。
显式单封读取工作流保留原 API。当前页中可证明的非草稿线程成员直接采集；未确认成员、
文件夹及完整分页仍保留未验收缺口。

打开前持久保存本地页检查点；Gateway 逐封校验并发布来源后才确认整页。未确认页可重放
已验证回执，失败成员即使已经变成已读也保留。相同邮箱暂停再启用仍能恢复；页面重试与观测
共享原件身份，避免重复下载。每次浏览器调用仍校验账号及凭据代次。解析、模型及
查看回执仍以单封记录为单位，不把整页合并成一封邮件。

只用返回检查点的原始区间推进进度；下界是上次完成获取时间（首次为部署时间），上界在发现前固定。未知覆盖、分页不完整或网络错误不推进完整边界。
离线测试不代表完整服务商分页或真实采集速度已经验收。当前开关及实测限制见上文。已观察清单超过 50 个目标时，确认子批后仍保留剩余成员，与远端已读状态无关。

标准化表示和模型输入／输出保存为不可变 owner 文件。候选检索先登记依赖，再调用模型；
输入指纹、代次、归属 epoch 与有效租约拒绝过期结果。模型完整输入限制 48 KB，截断必须
披露。mock 模型不能伪造分析成功。模型调用进入现有 Fast 遥测，不新增模型 lane 或跨项目契约。
回复检索与依赖登记统一选择最近 32 条引用，模型明确看到缺口，完整来源头部保留原始顺序。
主题／内容与往来参与者检索排除自有收件地址干扰，再以近期对话作最后候选补充。

原文摘要任务执行时读取持久化的 WebChat `zh`／`en` 偏好，并把语言写入来源分析产物；这些
原始产物保持不可变。对话界面不直接显示它们，而是对每封已加载邮件按当前界面语言确保一份
独立展示投影，已同步的历史邮件同样适用；切换语言后会替换成对应语言版本。分类首先执行
严格的验证码规则：必须有明确验证码／OTP 标记和邻近、包含数字的 token；命中后保存为受约束
的 `pattern` 通知，并跳过分类、摘要和事件归属模型调用。含糊数字邮件仍进入语义链路。

已有对话 ID 和成员归属保持不动。后续证据可产生或清除有版本的“疑似重复／待修正”，
持久反向依赖刷新摘要。相同且当前的工作合并；耗尽失败可显式重试。分析失败仍能查看来源。

WebChat 提供响应式原生邮件弹窗、来源过滤、服务端搜索、独立分页、待归属邮件、疑点跳转、
同步状态与接收设置。仅卡片实际进入视口时提交逐封查看 ID。专用文件接口根据 owner、
邮件 ID 和 part ID 解析已提交清单并校验字节；旧文档下载接口拒绝邮件路径及其别名。
附件直接下载，避免 HTML 在 WebChat 来源中执行。
