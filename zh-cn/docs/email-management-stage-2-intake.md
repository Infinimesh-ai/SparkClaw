用户已确认：首次遇到线程补齐可取得的来信与已发送历史，此后增量同步；不扫描整个历史邮箱。

## 页面批次接收更新 — 2026-09-09

自动接收现以有界邮箱页面为一个浏览器任务：扫描当前列表、持久保存清单，在同一任务页中
逐封打开已证明身份的目标、下载真实 EML、保存 MIME 部件，并在本地来源持久化后确认已读。
每封处理完返回原列表；一页最多 50 个已证明身份的邮件，虚拟列表及不完整会话仍明确报告 partial。

整轮完成后默认空闲 20 分钟。每页脚本预算 30 分钟，最多三条通道的外层总预算 95 分钟，
租约 3 分钟、每分钟续租。传输失败至少 20 分钟后重试（最多 5 次）；单封导出失败保留未确认
页供下个正常轮次重试，其他通道继续。已经保存原件、仅附件提取不完整的 partial 结果可以
结束浏览器采集，缺口保留给本地处理，不无限重复下载。

QQ、Gmail、Outlook 并行；每个邮箱的页面与页内邮件串行。自动接收仅启动按页作业，首次
页接纳会将旧 capture／mark_read／thread_sync 队列标为被替代，不伪造成功或已读状态。
显式单封读取工作流保留原 API。当前页中可证明的非草稿线程成员直接采集；未确认成员、
文件夹及完整分页仍保留未验收缺口。

打开前持久保存本地页检查点；Gateway 逐封校验并发布来源后才确认整页。未确认页可重放
已验证回执，失败成员即使已经变成已读也保留。相同邮箱暂停再启用仍能恢复；未读／近期
通道共享原件身份，避免重复下载。每次浏览器调用仍校验账号及凭据代次。解析、模型及
查看回执仍以单封记录为单位，不把整页合并成一封邮件。

未读优先和不依赖未读状态的近期来信通道保留；历史续扫未完成时额外检查最新重叠范围。
只用返回检查点的原始区间推进进度。24 小时重叠不早于启用时间，未知覆盖不推进完整边界。
离线测试不代表完整服务商分页或真实采集速度已经验收。三个接收开关保持关闭。 已观察清单超过 50 个目标时，确认子批后仍保留剩余成员；即使打开首封导致整段线程变成已读，也不丢弃尚未采集成员。

以下章节描述保留的覆盖要求和兼容操作。

## 定时器与任务

定时器属于 Gateway 后台生命周期，弹窗不创建定时器。每个已启用邮箱最多一个活跃扫描，
重复 tick 合并；启动时恢复未完成任务。模型积压不阻塞采集，队列接近容量时暂停新的扫描并保留进度。
QQ、Gmail、Outlook 接收在各自任务页中并行。浏览器 worker 池按已注册 provider 分配名额
（当前 3 个）；Store 持久领取保证同一 owner/mailbox 的发现、采集、线程枚举与标已读
同时只有一个有效浏览器任务。Provider 准入还保证跨 owner 对同一站点账号的访问串行，
一个邮箱缓慢不阻塞其他站点。通用 MCP、发送、登录交接与令牌验证仍全局独占；
独占请求等待时，先让当前接收任务结束，再处理独占请求，避免持续接收导致饥饿。

自动接收的当前默认空闲间隔为 20 分钟，每页最多 50 个可证明目标，以上述更新为准。
每个任务有截止时间、有限重试和退避；停止接收阻止新发现，已领取任务按既定关停预算收尾。
历史补齐优先级低于新来信，单个大线程不能长期占用邮箱。

## 发现覆盖与账号生命周期

发现分两路：未读扫描提供优先级；近期来信增量扫描不依赖已读状态。首次启用持久保存启用边界，
第二路覆盖此后收到的来信，包括首次 tick 前已在手机读过的新线程。更早的未读邮件仍可被发现；
更早的已读邮件仅通过遇到的线程补齐。枚举承载普通来信的文件夹/标签，包括被普通规则移出 Inbox
的邮件；排除草稿、垃圾邮件和废纸篓，并展示各服务商实际验收的范围。已发送历史与新增回复通过
线程同步取得；主动发起、与已登记线程无关的新外发线程不在来信发现承诺中。

每次近期扫描固定上界，从上次完整接纳边界开始，默认重叠回扫 24 小时，但不早于启用时间。
依据已证明的服务商接收/变更顺序，不能用发件人 RFC Date。无法证明边界或继续位置时报告 partial。
候选与分页进度先持久接纳，仅完整枚举区间才能推进已完成边界；可变列表使用稳定游标或有界重叠
扫描。超过一批的区间跨 tick 继续，不能仅取 50 条就宣称完成。
旧区间未完成时，独立的近期观察探测最新重叠范围，避免固定上界挡住之后已读的新来信。
该观察不能推进或替换历史边界／游标；有限页面／文件夹范围必须明确保留，直到服务商覆盖验收。
周期发现必须在上一轮完成后至少等待一个扫描间隔，即使上一轮跨越了多个规划器 tick。
已排队任务在反复唤醒和重启后保留原到期时间，重试耗尽后需显式重试。
一轮发现的不同通道共用一次已验证登录准入，每次脚本仍检查账号、配置与浏览器凭据代次。

停机、暂停或背压期间保留旧边界，恢复时即使超过 24 小时仍从原进度继续，不能改成“现在减重叠窗口”。
服务商保留/检索限制导致无法恢复时显示缺失区间。重叠窗口只是日常复查范围，不证明任意延迟出现的
邮件都不会遗漏；记录已验证的服务商限制，不宣称全邮箱完整。遵循阶段 1 绑定失效保护：重回同一账号
恢复原边界，新账号独立开始。暂停接收阻止新浏览器任务领取与发现，并取消当前邮箱正在执行的
后台浏览器操作，任务页按独立清理预算关闭；
已提交来源的本地分析继续。

## 脚本职责与输入输出

| 操作 | 输入 | 输出与副作用 |
|---|---|---|
| collect_page | 已验证账号、通道、区间／游标、上一页确认 | 同页采集、原文回执及持久页检查点 |
| discover | 已验证 mailbox/绑定、未读或近期来信通道、文件夹范围、区间/继续位置和预算 | 单封候选、接收/变更顺序证据、线程定位、读状态/文件夹证据、覆盖与继续位置；不下载、不主动标已读 |
| enumerate_thread | 已固定线程、继续位置和预算 | 单封成员及草稿/方向/文件夹证据；不返回模型猜测的关联 |
| capture | 已持久化 mail 目标、尝试 ID | 一封原件与附件、清单、观察到的读状态；不自行改选下一封 |
| mark_read | 已提交采集对应的单封目标 | 操作结果及逐封状态观察，与采集和分析结果分开 |

discover/capture、enumerate_thread 和独立 mark_read 保留为兼容 API，
具体注册方式在实现时遵循单一 Registry，不复制多份脚本清单。
目标需同时表达单封身份和导航定位，支持 Inbox 或已发送等实际文件夹，不能继续硬编码只在 Inbox 找重试目标。
原件统一通过原生 Playwright download/saveAs 保存；附件由 MIME 解析提取，DOM 不重新拼造原件。

当前页面的稳定属性、可见标记、展开行、菜单及网页自身响应都可作为确定性证据。
不要求所有邮箱提供相同字段或相同 DOM 证明方式；将各自证据映射到统一结果即可。
只设计当前页面路径；没有未来改版适配或模型浏览器补救层。

## 页检查点与来源发布

采用上述页面批次更新中的持久化及确认顺序；以下线程覆盖要求继续保留。

## 线程补齐与增量

线程唯一键带 mailbox；新观察到的成员按 mail 唯一键差集入队，包括已读来信和已发送邮件。
草稿不采集为正式邮件，不纳入时间线。完成一次成员枚举、完成下载、完成模型分析分别报告。
再次发现线程或后台轮转已登记线程时重新检查新增成员；活跃与未完成线程优先，其余分页轮转，
避免只依赖未读筛选而漏掉用户在网页发送的回复。既有单封执行单元不变。

Outlook 全局计数包含其他文件夹，不能用“全局总数减已见条目”直接推断丢了来信；
必须记录缺少身份或范围、继续位置，拿到足够范围证据才结束本次观察。
Gmail 若搜索结果只提供部分匹配成员，需线程枚举补齐，不能把搜索命中数量当线程总数。
QQ 若当前视图逐封列出且没有可枚举线程，则保存实际回复头；只沿明确链接或可确定搜索逐步补齐，
无法定位的历史保留缺口，不用主题相同冒充线程成员。

没有稳定游标的未读列表采用有界重复扫描＋持久去重，不按不断缩短的结果集偏移推进。
已登记线程的重试与补齐不受后来未读状态影响；每次扫描都区分 empty、partial 和 complete_for_observation。

## 三家实施与验收

| 邮箱 | 已有基础 | 本阶段补齐 |
|---|---|---|
| QQ | data-mailid、单封样式、原件附件采集 | 真实回复、当前视图的关联发现、逐封未读和已读效果 |
| Gmail | 列表逐封标签、legacy ID、单封下载菜单 | 去掉单邮件会话前提；线程多成员和草稿区分；目标展开与原件对应 |
| Outlook | 展开条目的祖先 ID 可对应 ItemIds；单封菜单有下载入口 | 单封导出验证、当前中文菜单、成员加载/文件夹区分、逐封未读证据 |

三家都验证普通来信、回复、同线程多封未读、已读历史、附件及重试固定目标。
模拟枚举后崩溃、自动已读后下载失败、线程部分加载和同名附件；恢复后无漏任务、无重复来源。
此阶段输出确定性资料，不决定管理对话，也不等模型总结完成才收下一封。
补测发现前已读的新线程、范围内自动移文件夹、超过 50 封新增、相同时间戳、暂停/重启超过重叠窗口，
以及切换后恢复原账号；三家分别证明近期扫描顺序与范围。

## QQ 详情与空页面（2026-09-09）

QQ 按页采集核对可见标题和正文 React 节点绑定的一致 mail.id、单封完整详情标记，
以及一致的 isUnread 状态。打开详情后不再要求存在选中列表行，也不从 QQ 内部不透明
的 messageId 猜测 RFC 身份。邮件头和正文以原生 EML 为来源；保存来源后再明确确认已读。

观察范围内没有候选、采集、失败及不支持记录时，页面可以正常结束为 empty，同时保留
局部 discovery 覆盖及续扫游标。证据不可用仍是 partial。空页不创建逐封任务或触发重试。
必要的近期已读新邮件检查仍保留；仅未读为空不代表整个邮箱没有新邮件。
