## 视图与交互

在现有 WebChat 提供“邮件”入口，打开大型管理弹窗；默认不是另起操作系统窗口。
弹窗关闭保留当前对话选择，重开从 Store 查询；选中 ID 可保存在本地偏好，但不是对话数据存储。
桌面左右两栏，小屏先列表后详情，支持返回列表、键盘选择、焦点恢复与明确关闭按钮。

| 区域 | 展示 |
|---|---|
| 顶部 | 全部来源/收件地址筛选、联系人/内容搜索、接收状态与手动触发同步 |
| 对话列表 | 对方或参与者、事项标题、摘要预览、最近时间、本地未查看数、疑似重复／待修正标记 |
| 对话详情 | 持久标题与参与者、整体摘要、往来时间线、历史补齐/分析进度、有版本的疑点依据及相关对话链接 |
| 单封卡片 | 来/去方向、实际 From/To/CC、时间、来源收件地址、单封摘要、展开正文、附件与原件 |
| 待归类区域 | 已接收但模型尚未完成或无法归属的邮件；可查看资料与重试分析 |

不按 QQ/Gmail/Outlook 建三个主栏目。服务商仅在账户设置或来源详情需要时显示。
相同地址多个事项显示为不同卡片；跨地址多人对话显示参与者集合，不伪装成一个联系人。

时间线以单封 mail_id 为项键，按来源时间＋稳定 ID 排序；未知来源时间明确标注并使用到达时间排序。
同封重复扫描不新增卡片。不同邮箱副本保留来源；只有后台提供已验证的副本关联时才折叠显示，
折叠后仍可展开各来源，前端不自行按主题、摘要或 RFC ID 去重。
顶部会话摘要与逐封摘要分开；分析未完成显示状态，不能用邮件预览文字冒充模型总结。

## 本地查看与远端已读

采集后远端已读不代表本地已查看。ViewReceipt 按 owner＋mail_id 逐封保存。
邮件卡片进入当前活动弹窗详情或待归类视图的可见视口，才算实际呈现；仅打开对话、加载/预取分页、
展示对话预览都不确认查看，也不要求展开并读完整个正文。每批仅提交明确呈现的 mail_id，最多 100 个，
待归类邮件同样适用。重放及多标签页请求幂等合并；迟到请求不能确认不在请求列表中的邮件。
未查看数由后台逐封记录计算，不使用到达序号最大值。

例如历史补齐邮件 101 在尚未加载的旧页，新邮件 102 已呈现，确认 102 后 101 仍未查看。
折叠副本组中隐藏的来源卡片在实际呈现前不确认；归属与摘要刷新不重置查看记录。
查看不触发远端标已读或重新下载。原件与附件通过现有 owner 文件授权边界读取，
不暴露宿主机绝对路径和下载令牌。

“疑似重复／待修正”与未归属 pending、未查看和处理失败分开显示。两个既有对话保持可见和原成员，
通过相关对话链接核对证据；重分析可更新疑点，但首版不提供修复/合并按钮，也不自动重组。

## 拟议查询和命令

下列是后续本地 Gateway API 设计，不是已注册接口，不是新增跨项目契约：

| 方法/路径 | 语义 |
|---|---|
| GET /api/email/conversations | owner 范围、来源/地址/内容筛选、游标分页，返回有版本的列表投影 |
| GET /api/email/conversations/{id} | 参与者、当前摘要、未查看数、疑点/相关 ID 及覆盖/处理状态 |
| GET /api/email/conversations/{id}/messages | 独立时间线分页、来源引用与逐封查看状态 |
| GET /api/email/pending | 已接收待归类邮件分页，包含逐封查看状态 |
| GET /api/email/sync-status | 各 mailbox 扫描、已接纳区间/文件夹范围/缺口、绑定暂停、线程补齐、积压和错误摘要 |
| POST /api/email/sync | 合并调度一次发现请求；不在请求内长时间执行浏览器 |
| POST /api/email/messages/viewed | 明确 mail_ids，最多 100 个；校验已认证 owner 后幂等插入逐封记录，支持待归类邮件 |
| POST /api/email/messages/{id}/reanalyze | 合并当前输入的摘要/关系检查刷新；仅新/pending 邮件可归属，耗尽失败可显式重新开启尝试 |

沿用并扩展现有 provider 设置/登录端点，提供阶段 1 的已验证 mailbox、独立接收开关和切换暂停状态。
每家服务商显示一个活跃账号，历史 mailbox 保留为来源筛选。
首个实现采用有界轮询刷新投影，接口使用 record_version，过时响应不覆盖新结果；
未来是否沿用既有事件通道由实现评审决定，不另建消息基础设施。
列表分页与时间线分页独立，刷新保留已加载页和当前选中项。列表搜索作用于后端完整已接纳范围，
不是只筛选当前加载的几行；搜索索引由提交记录重建。

## 验收

验证同地址两个事项、多地址同事项、多收件邮箱来源、模型失败与待归类、线程补齐、
附件原件打开、迟到邮件、本地红点、分页后刷新、断线重连、弹窗关闭后收件、重启后 ID 稳定。
检查键盘/小屏/长正文/长地址布局。仅复制 JingSi-mail 的静态卡片样式不算完成本阶段。
必须覆盖旧页 101 未呈现但新页 102 已确认、待归类查看后再归属、隐藏副本、多标签重放，
以及疑似重复两侧均可见、原归属不动、重分析不提供隐式修复。
