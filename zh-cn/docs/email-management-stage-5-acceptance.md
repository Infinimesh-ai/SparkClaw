## 验收矩阵

归类示例默认具备该场景所需的延续证据；明确测试缺失、冲突或迟到证据的行除外。

| 场景 | 必须观察到的系统结果 |
|---|---|
| 三家各一封新地址来信 | 定时发现、单封原件/附件入库、摘要、新对话、弹窗可见 |
| 同地址连续两件无关事项 | 两个持久对话，来源正确 |
| 同事项的多封回复 | 复用对话 ID，逐封同步，不重复摘要卡片 |
| 已有线程含已读、已发送、草稿 | 非草稿历史有界补齐，草稿排除，覆盖缺口明确 |
| 相同事项跨两个收件邮箱 | 统一管理对话，原件来源不混淆 |
| 新参与者加入/线程换话题 | 不被新地址或 provider thread 机械决定归属 |
| 两个相关新邮件并发 | 拒绝过时 epoch 并重新检索判断，不重放旧 new 决定 |
| B/C 分别归属后原信 A 才到达 | 保留原对话 ID/成员，按证据在双方显示疑似重复／待修正 |
| 新线程在首次扫描前已读 | 近期来信通道接纳，不依赖未读状态 |
| 暂停超过重叠窗口/超过 50 封新增 | 从已接纳边界跨批恢复，不静默截断时间窗口或分页 |
| 切换账号后再返回 | 旧浏览器任务暂停/失效保护，来源隔离，同账号身份与进度恢复 |
| 打开会话自动标已读后进程退出 | 持久成员/线程任务恢复，不依赖再次未读 |
| 原件已写入但 Store 发布失败 | 文件不进入产品投影；同次尝试可对账恢复 |
| 模型宕机或附件不能提取 | 接收继续，资料可查看，摘要覆盖和错误明确 |
| 分析时新成员到达 | 过时摘要不覆盖当前，重新安排更新 |
| 成员不变但附件提取改进/父邮件补齐 | 依赖摘要/检查持久刷新，分批展开时崩溃不丢意图 |
| 关闭弹窗、重启 Gateway、重开 | 后台恢复，邮件和对话 ID 不变，本地查看状态保持 |
| viewed 批次与新到/未加载历史并发 | 仅确认提交的 mail_id；呈现并确认 102 后，旧页 101 仍未查看 |

三个服务商逐项记录实测范围，不用某一家通过替代其他家。
语义归属另有人工标注样本及错误分类，不要求偶然一次模型输出作为稳定能力证据。
错误分为未发现、错误采集、重复入库、错误归属、摘要缺证据、状态投影错误，分别归对应阶段修复。

## 首版通过门槛

以下是验收目标，不是已测成绩或生产延迟承诺。验收前冻结语料 ID/哈希、人工期望、模型/提示/解析器
版本、输入顺序、运行配置和主机；不能用计分样本调参，也不能为了通过失败结果而降低门槛。
每项门槛分别通过。

| 门槛 | 必须提供的证据与阈值 |
|---|---|
| 身份与状态 | 冻结语料及故障用例中，错 owner/账号接纳、错误原件、重复邮件记录、已接纳任务丢失、旧结果冒充 current、擅自搬移归属、确认未提交 mail_id 均为 0 |
| 证据充分的归属 | 至少 100 个覆盖阶段 3 场景的人工标注决定；记录不同种子/顺序运行 3 次，每次正确 append/new ≥95%、误合并 ≤1%、误拆分 ≤5%、pending ≤5%；所有比例都以充分证据决定总数为分母，包含待定 |
| 缺失/冲突证据 | 每次另测至少 20 个标注案例，包含 B/C 先归属后 A 到达；适当 pending/疑点结果 ≥95%，所有案例保留既有归属。此组保留的重复对话不算必须自动修复的失败，另报重复数量及疑点漏报/误报 |
| 摘要依据 | 每次模型运行审查至少 100 个单封与 20 个对话摘要：关键金额/日期/承诺编造及无效证据引用为 0，事实陈述有依据 ≥95%，已知提取/历史/输入截断缺口全部明确披露 |
| 真实空闲接收 | 三家分别测试 10 封范围内新邮件，其中 5 封发现前已读；初始队列为空且浏览器/Store 健康，从网页可观察到起 2 个 60 秒 tick 内全部持久发现，接纳后 10 分钟内原件可见。服务商/账号锁等待及失败须记录，不能从报告剔除 |
| 恢复与刷新 | 测试租约 60 秒、tick 60 秒，依赖恢复后 3 分钟内重新领取遗留可运行任务；最后输入发布且依赖恢复后，每个小型验收对话 10 分钟内出现最新摘要或明确的重试耗尽失败 |
| 容量与 UI | File/PostgreSQL 各有 10,000 封已接纳邮件、1,000 个排队任务，模型停机 30 分钟、重启并尝试超出有界容量；已接纳工作零丢失、进度不越过未接纳候选。记录主机上列表/详情各 100 次查询 p95 ≤1 秒；提交后活动弹窗在 2 个 5 秒轮询间隔内反映状态 |

误合并指 append 到无关事项，误拆分指已有可靠延续候选却 new。缺失证据组独立计分，不能把困难案例
排除出分母来提高准确率。数量与比例同时报告，三次各自达标，不能只取最佳结果或合并平均。
身份/状态使用确定性断言，语义判断使用真实模型输出的人工核对。容量/恢复可用有界假适配器注入故障，
不证明真实服务商吞吐；另报实际采集/模型吞吐及 pending 时长，指定负载外的延迟保持未验收。

## 工程检查

执行受影响的 Controller 测试和生成契约检查、Gateway build/test/vet、Store 三 backend
契约与真实 PostgreSQL 集成、前端测试/build、双语文档检查。
故障测试覆盖租约失效、命令结果未知、进程退出和输入版本变化；无改版 DOM 兼容性测试要求。
真实样本核对 Message-ID/回复头、正文、附件字节、mail_id、conversation_id 和最终 UI，而不只看成功日志。

## 启用与运维边界

先用隔离验证数据走完整流水线，再由已配置账户启用后台接收；常驻服务升级是后续实施阶段动作。
默认配置也需可用；不能只在 PostgreSQL 环境通过而让 File 后端无效。
已有私有测试邮件不自动导入管理系统，历史产品采集通过阶段 1 的显式接纳迁移处理。

可按邮箱暂停新发现/浏览器任务领取，保留发现边界；账号变化遵循阶段 1 绑定失效保护。
模型重试和来源保留独立。停止后台接收不删除本地邮件或对话；
模型任务失败只重试分析，不回退浏览器采集。持续失败可见于同步状态，不阻塞其他邮箱/任务。
需要观测扫描/补齐区间与缺口、待采集数、待分析数、pending 时长、归属疑点、重试及最近成功时间，
日志只含必要 ID/错误，不倾倒邮件内容。

阶段完成报告必须列明：已实现、真实验证范围、尚有缺口、部署状态。
最终验收后更新现行架构与开发文档；不能把本讨论稿提前写成已上线能力。
发送/回复编辑、人物合并和会话批量合并拆分是后续独立需求，本轮不顺带实现。
