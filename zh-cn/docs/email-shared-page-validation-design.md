> 语言：简体中文 | [English](../../docs/email-shared-page-validation-design.md)
>
> 状态：按用户“先默认使用合并方案，使用中遇到问题再修复”的决定，
> 2026-09-28 起合并页为默认。未设置开关或设置
> `SPARKCLAW_MAIL_SHARED_PAGE_CANDIDATE=1` 均启用合并页，显式 `0` 回退双页。
> 配对实测已验证任务页由六页减为三页；B／C 完整验收仍未完成，
> 本次上线决定不将未完成案例标记为通过。

## 1. 目标与范围

验证每个符合条件的邮箱能否只用一个**有头 Chromium 受控任务页**，同时承载
常驻通知监听和逐轮复用的 Reader 读取。当前启用的 QQ 邮箱、Gmail、个人版
Outlook，稳定状态下邮件任务页由六个减少到三个，继续位于现有不抢焦点的
任务专用后台窗口。个人页和登录页不计入这三个，也不得被收编为采集页。

目标是减少用户看到的任务标签，同时保持采集正确性和通知行为。仅减少 tab
数量不算通过。监听状态与读取状态仍然独立，只共享一个页面和一个 CLI 连接。
浏览器子进程数不必等于标签数。

本设计落实[通知唤醒生命周期设计](email-notification-wakeup-design.md)中同页复用的
验证要求。不考虑无头、CDP 隐藏目标、Electron 迁移、新开浏览器实例、转移 Cookie、
扩展多账号、修改通知规则，以及改变轮询频率、覆盖规则、公共 API 或跨项目契约。
发送、登录、探测及其他注册操作保留现有准入语义，不借用合并采集页。

## 2. 已确认的基线与缺口

| 方面 | 原双页基线 | 合并页需要证明 |
| --- | --- | --- |
| 监听 | `ResidentMailObservers` 单独创建 `PlaywrightCLITask`、受控页和 daemon，导航前安装监听钩子 | 监听能常驻在 Reader 实际使用的同一页 |
| 读取复用 | `MailReadPool` 单独保留成功的 `collect_page` 租约，空闲 30 分钟回收，已取消固定两小时寿命 | 监听存活不受读取空闲回收影响 |
| 准入 | 空闲监听释放 provider 占用，Reader 执行时取得占用 | 页面常驻不变成永久占锁 |
| 轮次清理 | `prepareMailRound` / `parkMailRound` 调用 Reader `resetRound`；失败或取消会销毁读取租约 | 重置保留监听，销毁不与监听或其他借用者竞争 |
| 恢复 | 监听健康恢复和 feed 退役可直接停止、重建监听任务 | 页面变更和退役均经过唯一资源所有者 |
| 事件 | 本地心跳每 15 秒一次，超过 45 秒无活性则降级；Gateway 意图租约 90 秒 | 读取不阻塞续租，也不能伪造监听健康 |
| 证据 | 已有三家验证证明双页状态下监听与读取并行 | **不能**作为同页共存已通过的证据 |

Reader 重置会清除行、分页、查询回复和原文缓冲。监听的文档身份、通知去重和
待投递提示分开维护。但同页共存还取决于钩子安装顺序、原生订阅和取消行为，
仅有不同的 JavaScript 对象不足以证明可靠。原双页监听调用 Reader `snapshot`
校验账号；候选改用不遍历已保留行的本地 `checkAccount`。查询进行中的同页行为仍须实测。

## 3. 候选资源归属设计

默认合并页方案以 `MailReadPool` 作为内部邮箱页面所有者，没有新增公开的
`MailboxPageSession` API。租约持有受控页、CLI daemon 和运行目录；池内槽位
维护监听保留标记、Reader 借用、退役状态与共享清理结果。监听管理器继续维护
通知分类、健康与投递状态，但候选页面通过读取池退役。不把两个 CLI 客户端
或调试连接强行连接到已有 tab 上。

复用身份包含 provider、owner scope、规范化的预期账号、凭据代次及身份、读取和
监听源码版本。Controller 运行时代次和文档 nonce 另行约束动作及回调。feed 的
邮箱绑定代次继续在准入和投递处检查。身份摘要仅内部使用，诊断不新增密钥或
账号标识。其他有效绑定不能抢占或借用此页面。

每轮业务读取仍有新的调用身份、截止时间、取消信号和回执。复用物理页不复用
上轮结果。空闲监听不得继承上一轮已过期的 deadline 或 abort signal。钩子或
受管脚本版本变化，需要先在安全边界退役旧页，再接受新版本。

### 初始化顺序

1. 先取得现有 Controller 准入，再取得邮箱读取池槽位；先处理身份及被隔离的
   清理失败，再分配页面。
2. 导航前安装两套兼容的基础钩子。Reader 先启动时，监听钩子保持休眠；有效
   监听注册激活前，不准入提示，也不保存注册前通知供事后投递。
3. 只导航一次，验证受控页、来源、预期账号与能力，绑定文档身份。监听注册
   沿既有路径请求补查。
4. 后续匹配的监听启动和读取不导航，直接复用。没有提前安装钩子的旧读取页，
   在空闲边界先退役再创建；不得假定迟装钩子能捕获已创建的 Outlook Worker。

## 4. 生命周期、串行与失败策略

下表是候选内部状态，不新增 Gateway 公共状态。

| 情况 | 页面与占用行为 |
| --- | --- |
| 监听中、无读取 | 监听保留标记维持页面，不占 provider 执行槽，也不循环调用 CLI 查询 |
| 监听加读取 | 一个 Reader 借用者持有正常准入，监听回调和 feed 投递独立继续 |
| 读取成功结束 | 本地重置并校验身份，释放借用及占用，保留监听标记和同一页面 |
| 只有读取、没有监听注册 | 保留当前空闲 30 分钟复用规则 |
| 有效监听期间读取空闲定时器到期 | 保留页面；过期的旧定时器也不得将其退役 |
| 停止监听或 90 秒意图租约到期 | 立即撤销事件准入、标记退役，不能在 Reader 执行中关页；借用者结束后关闭，不再放回读取池 |
| 关闭收信或移除绑定 | 应用既有 Gateway 取消规则，拒绝新的匹配定时读取和提示，结束已准入借用后退役；其他独立授权请求仍走自己的准入检查 |
| 读取取消、失败或重置结果不确定 | 保守地使合并页失效，在有界停止后退役；仍有有效监听意图时，由正常监督器统一重建并请求补查 |
| 监听通道降级、Reader 仍健康 | 明确上报监听降级；仅在 Reader、页面和账号独立检查通过时继续周期读取，读取成功不能代表监听健康 |
| 关页、崩溃、文档替换或身份失效 | 拒绝旧回调及结果，使受影响读取失败，退役并重建自有资源，在订阅前重装钩子，从已保留检查点请求补查 |
| 无法证明自有 daemon 已终止 | 保留隔离元数据，阻止替换并报告失败，不能遗忘旧页后再创建第二个 |

对失败读取先采用保守退役策略，不新增“所有已取消原生请求都能安全重置”的
假设。未来若按失败类型保留页面，需要另外举证。重建不能在旧调用里重放失败
查询，也不能把不完整列表认证为完整。已有合格的部分回执、已保存原文、失败预算
和时间线规则仍为准；退役页面不能删除已经提交的邮件。

固定锁顺序：Controller 执行占用 → 邮箱生命周期锁。恢复也必须经同一准入路径
调度，不能先拿页面锁再等待 Reader 持有的执行占用。事件接收、确认和续租不等待
Reader 的 CLI 命令锁。关闭请求可立即标记退役，但销毁必须等在途命令和页内操作
结束，或完成有界取消。所有退役调用共享一个幂等清理 promise。

保留独占操作优先级。登录、发送、校验和通用独占操作开始前，在独占准入下挂起
并排空合并页；独占占用释放后才恢复仍启用的监听。reconcile 不能在独占操作中途
重建监听。确定性测试已覆盖合并页暂停与替换；完整实机独占及故障矩阵
仍待验证。

临时任务页和探测页由其确切所有者关闭。产品创建的临时登录页，仅在现有流程
证明登录完成且归属明确后清理；个人页和用户明确接管页不自动关闭，也不改为
合并页。登录失败时，监听继续显示等待登录。

## 5. 同页必须维持的不变量

1. **物理资源唯一**：每个有效绑定最多一个存活邮件页和一个保留 CLI daemon；
   先退役旧资源再替换。监听和读取同时启动，也只能创建一次。
2. **状态独立**：`resetRound` 只清除本轮行、分页、查询状态、原文字节／Blob URL
   和临时下载状态；保留监听钩子、文档序号、分类状态、去重和待处理提示。监听
   的账号检查不能改变当前 Reader 查询。
3. **钩子透明**：原生请求、回调、返回值、错误和流消费者行为保持一致；重置
   不重复安装包装器或订阅，多轮执行不能叠加监听器。
4. **结束边界不丢工作**：读取期间到达的提示按现有信号代次继续待处理。R 轮
   完成不能结算超出 R 已对账代次的新提示，持久化准入后才 ACK。提示不是邮件
   数量、完整性证明或轮询水位。
5. **代次隔离**：迟到查询回复、旧文档事件、旧凭据工作、关闭后的迟到结果，
   都不能影响新轮次或新绑定。不得把旧文档 nonce 写入替换文档来通过过期检查。
6. **资源有界**：保留现有缓冲限制、恢复退避和次数上限。空闲缓存、监听标记、
   读取借用及停机都有明确释放路径，反复读取或恢复后任务页不能增长。

保持现有 60 秒周期兜底及通知 `qualified:false` 设置。本验证不启用五分钟安静档，
不扩展收件箱／文件夹覆盖、Microsoft 365 支持或发送范围。

## 6. 三家邮箱的同页检查重点

| 邮箱 | 原生监听与读取的交汇点 | 必须取得的证据 |
| --- | --- | --- |
| QQ 邮箱 | WebSocket 通知与范围列表／原文请求共存；启动可能替换文档 | 列表和原文阶段均保留原生有效到达通知；启动替换正确隔离并重装；重置不重复包装 socket |
| Gmail | 通知 XHR 流与 Reader fetch/XHR 钩子共用页面 | 查询／下载期间分片帧、ACK、保活帧处理正确；Reader 不消费或截断通知流；只有查询时不制造到达提示 |
| 个人版 Outlook | Worker/MessageChannel 通知订阅与范围搜索、分页、原文准备及重置共存 | 搜索不悄悄把监听订阅换成仅查询视图；迟到回复留在旧轮；`RowAdded` 和投递签名变化仍可见；只改已读标记不算到达 |

Outlook 的本地心跳健康不足以判定成功：必须证明范围搜索返回后、多次重置后，
仍收到真实有效的投递通知。若同页搜索持续破坏必要订阅，记录该 provider 验证
失败，不放宽通知规则来制造通过结果。

## 7. 分阶段验证矩阵

原始矩阵的所有案例初始为 `NOT_RUN`。构造测试验证顺序与隔离，真实邮箱验证 provider
兼容性，两者不能互相替代。没有受控到达的运行不能通过正向通知案例。

### A. 确定性的生命周期与传输测试

使用假时钟、可控 promise 和结构化通知夹具，检查确切资源归属、命令次数及
状态转移，不只看截图。扩展现有读取池、监听、feed、CLI 清理和 userscript 测试。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 监听先启动、Reader 先启动、同时首次获取；并发重复启动监听 | 只创建／连接／导航一次；休眠钩子注册前不发事件；重复启动不改变身份 |
| A02 | 同 provider 两次读取、跨 provider 独立读取、读取中独占操作等待 | 同家串行，跨家容量不变，独占操作不饥饿，原有 `browser_busy` 处理保持 |
| A03 | 重置、列表／下载期间、结果返回到 ACK 之间到达通知；重复投递和重连 | 新信号保留待处理，不重复持久化工作或提前推进游标，重置保留监听状态 |
| A04 | 查询中执行心跳／账号校验，有／无监听标记时空闲到期，读取中停止／租约到期 | 不修改 Reader 状态，续租独立，保留及退役符合第 4 节 |
| A05 | 取消、超时、部分结果、原文失败、重置失败及之后的迟到回调 | 不危险复用、不伪造完成／水位，保留原有部分回执规则，只退役一次，仅按当前监听意图有界恢复／补查 |
| A06 | 旧文档，owner／账号／凭据／源码变化，关闭再启用，旧任务迟到完成 | 拒绝旧工作，不跨身份复用，新绑定不接收旧事件／结果 |
| A07 | 恢复与读取／启动／停止并发，清理失败，重复停机 | 无锁顺序反转、双重关闭／回收或孤儿收编，清理失败阻止替换 |
| A08 | 钩子顺序、反复重置、分片／畸形流、事件缓冲满 | 原生语义不变，无包装器／监听器增长，溢出可见并请求补查 |

### B. 有头实机基线与候选比较

使用相同固定版本的 Chromium、Bridge、CLI、受管脚本、邮箱夹具和冻结读取区间，
记录实际安装哈希。基线显式设置 `SPARKCLAW_MAIL_SHARED_PAGE_CANDIDATE=0`，合并页仅改变页面归属与共存方式。在授权
验证配置中先后执行，不能让两个 Controller 竞争同一生产绑定，也不复制 Cookie
或 profile。本文件不授权测试发信、改变收信设置、重启服务或迁移生产；执行时
使用明确安排的测试账号和动作。离线及只读案例可以先独立完成。

| ID | 负载 | 通过条件 |
| --- | --- | --- |
| B01 | 三家有效绑定启用，冷启动、热空查询，再做 0／1／N 封原文读取及重放 | 稳定邮件页 6 → 3，一个无焦点任务专用窗口；个人页／焦点不变；冻结区间有效结果及原文哈希一致；重放不重复原文 |
| B02 | 空闲、列表请求在途、原文请求在途时分别真实到达邮件 | 每家每个阶段至少三次确认到达；有效提示及最终确切原文分别举证；读取阶段时间戳证明原生事件与该阶段重叠 |
| B03 | 只有查询的对照和已知非到达事件，包含 Outlook 只改已读标记 | 不产生由读取／重置制造的到达提示；识别真实外部事件，否则该对照结果不确定并重做 |
| B04 | 持续有效续租、至少 45 分钟完全不读取，然后再读取；另做无监听读取页空闲超过 30 分钟 | 有监听标记的页／daemon 保持，恢复读取不重新连接或导航；无标记读取页按原空闲策略回收 |
| B05 | 连续至少两小时、每家完成至少 100 轮热读取，含空和非空轮次 | 除计划故障外页／daemon 身份稳定；tab、包装器、缓冲不增长，无本轮数据泄漏；周期推进和通知投递持续 |

如安排正向发信，发件端必须位于被测 Controller／profile 之外。用被测实例的独占
发送操作会挂起正在验证的监听与读取，破坏共存条件。私下保存唯一夹具身份和
发送回执；结果不确定先核对，不自动重发。通知允许合并，不要求每封恰好一个提示。

关联原生事件接收、列表／原文开始结束和持久化准入时刻；仅“在读取期间发出邮件”
不构成阶段重叠证据。A03 用夹具屏障覆盖精确重置／ACK 竞争；实机人为延迟另行
标记，不能替代自然重叠。若原文只靠周期兜底发现，证明采集仍可继续，不能证明
通知共存成功，两种结果分别记录。

### C. 故障、独占和生命周期实机验证

在验证环境中，对三家分别执行适用案例。

| ID | 故障／动作 | 通过条件 |
| --- | --- | --- |
| C01 | 关闭受控页，重载／替换文档，终止自有 CLI，重启 Controller | 旧工作失效，有界恢复只产生一个替换页和合并后的补查意图，无页面／daemon／运行文件泄漏 |

## 8. 证据与判定标准

每次运行在 `data/qualifications/mail-shared-page-<run-id>/` 保存机器可读清单和简报。
执行前不得生成声称通过的证据文件。记录：

- 基线／候选源码和实际安装制品哈希、provider 范围、环境、起止时间，以及每项
  `PASS`、`FAIL`、`BLOCKED`、`INCONCLUSIVE` 或 `NOT_RUN` 状态。
- 页／会话／文档／轮次的运行内别名，生命周期及占用转移；查询、原文、提示接收、
  准入、ACK、重置、取消和清理的单调时钟时序。
- 任务窗口／tab、daemon／运行目录数量，可观测的钩子／订阅数量，有界队列峰值，
  冷／热耗时分布。
- 私有夹具及原文核验回执；仅导出脱敏计数、哈希和结果。普通验证报告不包含正文、
  账号地址、token、原始 URL 或原生负载。

以下为候选执行前固定的资格验收目标（后续用户上线决定见第 9 节）：

| 门槛 | 要求 |
| --- | --- |
| 正确性及归属 | 三家所有适用 A／B／C 案例通过，零错账号读取、过期结果准入、非自有页面操作、受控原文丢失或自有资源泄漏 |

## 10. 候选实现与现有证据
