# ISCP 链路优化与原生实测

[English](../../docs/iscp-latency-optimization.md)

2026-10-14 使用已安装 Mac SparkX 的原界面、原 Main 身份，经 TEST1 公网
Relay 连接 work2 Gateway 实测。最终 Mac/work2 运行 `3ddde02b`；TEST1 Relay
运行 `f19847c3`，持续接收窗口为 55 秒。另四台 Gateway 保持原版本，已通过
新版 Mac 客户端的原界面兼容性验收。

## 实测结果

优化前后各发送 5 次独立会话的“你好”，再发送 1 次约 600 字的雨后公园短文
请求。使用原输入框、真实模型、helper 和持久化存储；模型配置、Client 身份
和授权不变。

| 指标 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 短回复开始显示，5 次中位数 | 20.948 秒 | 7.164 秒 | 65.8% |
| 短回复完整落盘，5 次中位数 | 18.070 秒 | 7.823 秒 | 56.7% |
| 短回复可靠交付 ACK，5 次中位数 | 23.308 秒 | 8.106 秒 | 65.2% |
| 长回复开始显示，单次样本 | 23.968 秒 | 7.142 秒 | 70.2% |
| 长回复完整落盘，单次样本 | 22.109 秒 | 11.244 秒 | 49.1% |
| 长回复交付 ACK，单次样本 | 29.312 秒 | 11.637 秒 | 60.3% |

短回复完整落盘范围由 16.025–20.878 秒变为 7.639–7.933 秒，所有请求均达到
`delivered`。长回复由一次性显示变为 9 次内容更新（8 次预览及最终结果）；前后存储内容分别为 679
和 617 字符。生成内容和网络会变化，这是少量连续生产实测，不代表百分位
SLA，也不是同时进行的严格对照实验。

开始显示使用渲染器 MutationObserver，从原输入框提交时计时；完整结果和
ACK 使用同一台 Mac 的 SQLite 时间戳。优化前可能先落盘、后刷新界面；优化后
可以先显示临时文本、再收到完整可靠结果。不同机器的时钟不直接相减，重叠的
RPC 阶段也不累加。

## 时间花在哪里

基线版本 `f91a4142` 只增加计时。短回复服务端执行约 6.918 秒，但本地完整
落盘中位数为 18.070 秒；本地提交不足 1 毫秒，Gateway 的查询和 ACK handler
也只有几毫秒。

原 Relay 每轮排空后重连，两端接收循环各有 1 秒等待。响应授权阻塞接收回调，
记录的 94 次实时校验没有重叠；查询轮询再引入等待。界面通知排在交付 ACK 后面，
但基线实际上由 3 秒兜底刷新先显示结果，落盘到可见间隔为 76–2,898 毫秒，
不能把它直接说成完整 ACK 耗时。

事件通道还存在恢复错误：测量期间 28 次事件拉取全部返回 409，`cursor_gap`
被通用 `revision_conflict` 外层错误码覆盖，无法触发快照恢复。这批基线没有
发生事件 ACK，因此不能把串行事件 ACK 算成已测得的耗时来源。

最终关联日志进一步区分了模型时间和被消除的等待：

| 阶段 | 优化前均值 | 优化后均值 | 样本 |
| --- | ---: | ---: | --- |
| 提交到接纳 | 4.294 秒 | 0.312 秒 | 前后各 5 次短回复 |
| Gateway 执行 | 6.919 秒 | 6.913 秒 | 前后各 5 次短回复 |
| 本地提交到交付 ACK | 4.694 秒 | 0.291 秒 | 前后各 5 次短回复 |
| 执行查询 RPC | 5.477 秒 | 0.408 秒 | 前 12 次 / 后 19 次 RPC |

短回复总耗时扣除内部 Gateway 执行时长的余量，均值从 11.088 秒降到 0.902 秒。
该差值仍包含轮询、授权和调度，不能称为纯网络延迟。前后 5 次短回复的最终
内容摘要完全相同。新事件通道在首次 409 后成功恢复快照，随后记录 27 次成功
拉取和 28 次成功 ACK。捕获证据未出现丢弃/上限标记或解析错误，但尽力而为
的诊断日志仍不等于全局审计账本。

## 按顺序完成的改动

1. 补齐接纳、RPC 授权/收发、Relay 循环、handler、执行、查询、落盘、通知、
   增量内容和 ACK 计时。`SPARKCLAW_PRIVATE_LATENCY_TRACE_DIR` 必须指向已存在
   的私有绝对目录。只记录固定计时和身份元数据，不写正文、凭据、URL 或错误
   文本。Go 队列与文件受限，文件上限 64 MiB；出现丢弃/上限标记就不能进行
   完整归因。桌面达到 100,000 条后停止记录。诊断失败不影响交付。
2. 完整校验并可靠落盘后立即通知原界面，ACK 保留原持久化重试、摘要和身份
   校验。事件持久化后并行处理结果与 ACK，下一次拉取仍等待两者完成。
3. Relay 在认证后的同一接收连接中继续投递后续消息，入队立即唤醒，连接
   替换和存活检查有明确边界。帧格式、密码学和上游 ISCP 契约不变；PostgreSQL
   单消息认领、写入和标记位于一个事务，失败或取消回滚。
   详见[Relay 部署说明](public-iscp-node-deployment.md#10-有界持续接收)。
4. 将匹配响应的实时授权移出串行接收回调，不缓存已完成的授权结果。交付前
   重新核对原 pending 调用、截止时间、会话、Grant 和撤销状态。
5. 通过原 v2 操作注册表和授权协商可选 `execution.progress`。仅最终回答的
   文本增量进入临时预览，每执行最多 8 KiB、全局最多 8 MiB；epoch/revision、
   输入摘要和身份限制拒绝过期或错配内容。容量不足只停预览。继续使用原消息
   组件，完整查询、文件、摘要、本地事务和可靠 ACK 仍为交付依据。旧节点协商
   原操作集合，不重放业务请求。
6. 修复加密响应外层和桌面适配器的游标错误转换。旧节点兼容只接受严格的
   `events.pull` 409 游标缺口结构，其他修订冲突保持原有处理。

逐步实测的短回复完整落盘中位数为：界面/ACK 解耦后 18.584 秒（3 次），持续
接收后 9.792 秒（3 次），异步响应授权后 9.547 秒（3 次）。这是累积版本，
不能相加为各项独立收益。另做三轮八路并发读取，**没有证明**异步授权带来
额外速度收益；它消除了已证实的串行阻塞点，同时保留实时校验，不单独宣称
生产提速比例。

## 保留与验证

Desktop 372 项、WebChat 310 项、严格生产打包、受影响 Go 竞态测试、真实
PostgreSQL 18 Relay 测试通过。Linux/arm64 的 71 个测试包、`go vet ./...`
和 `go build ./...` 全部通过，使用 Node 26.2.0、Go 1.25.5 和已安装的文档
依赖。Mac 全量 Go 仍有已在基线复现的 `/tmp` 符号链接、`/dev/shm` 和驻留
投影限制，不能称为全绿；Linux/x64 全量测试不在本次验收范围。

五个原有配置均通过原生验证：原身份和历史、九个设置入口、设备控件、日程
创建/取消。已安装版本的 61 个桌面源文件、5 个 UI 资源和 helper 与构建一致。
未增加 CSS、布局、菜单或常驻技术状态面板。

另一次约 1,800 字的真实请求，在显示 50 字符预览且最终消息/交付回执均为零时
关闭客户端。冷启动后沿用相同请求 ID 和输入摘要，收到唯一一条 1,979 字符
最终消息及唯一交付回执。临时预览不作为完成结果，也不提前 ACK。
Gateway 日志确认仅执行一次，重启后没有再次提交。最终 6 个基准请求也均为
一次执行、一次最终本地提交、一次成功交付 ACK。

保留冷备份后，通过原有带状态保护的 ClientStore API，仅清理本任务创建且
已交付的 23 个测试会话。五个配置的原消息、任务、文件及会话字段均保留；
事件游标随恢复正常推进。四个原冷配置执行此前已发布的 schema 9→10 标题
迁移，增加 `title_pending=0`，原字段不变。默认启动选择文件保持字节一致。

work2 升级保留 41 张业务表的原记录、端口、挂载、模型配置和授权；responder
仅增加 `execution.progress` 资格，诊断环境仅调整私有计时目录。TEST1 的
27 张表中身份/授权记录及原限流保留。应用、配置、数据库和授权有配套检查点；
回滚状态前必须考虑后续效果和撤销，不能直接覆盖运行中的账本。

## 证据与复现

使用 Node 26 运行 `scripts/iscp-latency-benchmark.mjs`，显式指定已安装程序、
真实配置目录、新建私有输出目录、`--samples 5` 和 `--long-reply`。该脚本
会创建真实会话，并等待每个请求完成可靠交付。先保留配套冷备份，再通过原
ClientStore API 清理它自己创建且已完成的会话。

运维私有证据归档为 `sparkclaw-latency-opt-20261014`，包含前后
JSON、分段日志、截图、中间阶段、对比数据、重启检查、测试日志和升级回执。
凭据与数据库备份不入 Git。work2 检查点为
`/var/backups/sparkclaw-latency-opt-20261014`；TEST1 检查点为
`/var/backups/sparkclaw-latency-relay-20261014-r2`。

规定的上级路径均未找到 InfiniCenter，因此不宣称已写入中枢决策、契约或达成
跨项目共识。改动位于 SparkClaw 实现和可选应用操作内，上游 ISCP 帧格式不变。
