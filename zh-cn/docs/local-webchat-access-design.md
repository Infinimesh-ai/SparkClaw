>
> 日期：2026-10-06（Asia/Shanghai）。状态：**产品决策 D01–D04 已确认；用户已授权完善设计并实施；实现与隔离验收已完成；实机部署验收待完成，尚未上线**。本次评审补齐防嵌入、旧凭据恢复、语音 Ticket 及分阶段验收；选定方案见 6.4。

## 1. 用户需求与范围

在后端机器上通过本地地址打开 WebChat，不应要求用户手动输入凭据；局域网浏览器和独立客户端仍需各自的凭据。“免输入凭据”消除的是用户操作，业务请求仍须具有经过验证、限定于 Owner 的身份。

本方案适用于 Local、Remote 两种模型部署模式的产品 WebChat 入口。模型位于哪里，不决定浏览器是否属于本机。本方案不改变工具审批、客户端浏览器宿主授权、MCP／ISCP 认证、JingSi 接口及邮箱授权。

现行[共享后端基线](local-shared-backend-design.md)要求浏览器即使走回环地址也提供 Token；[R3 目标](client-backend-architecture-design.md)要求客户端安装首次凭据登录，包括与后端同机的桌面安装。本次实现引入仅针对本机 **WebChat** 的例外，已在两份基线文档明确记录；独立桌面安装仍保留首次登录要求。

认证变化不改变 R3 数据归属：浏览器安装保存各自的非邮箱数据，后端持有邮箱数据。共享本机 Owner 身份，不意味着合并浏览器配置文件、安装 ID 或会话存储。当前已部署的服务端存储 Web UI，与未来 R3 Web 存储适配器，仍是不同实施阶段。

## 3. 拟议访问规则

| 调用方与地址 | 拟议结果 |
|---|---|
| 后端本机浏览器，使用 `localhost`、`127.0.0.1` 或 `::1` 及配置的 WebChat 端口 | 自动取得本机身份，不显示 Token 输入框 |
| 同一台机器，但使用其局域网 IP 或局域网域名 | 走普通凭据登录；仅仅人在同机，不改变所选入口的规则 |
| 其他机器的浏览器，使用局域网入口 | 使用独立浏览器凭据 |
| 其他设备，经已授权本机用户的隧道转发到回环入口 | 按 D04 视为主动转授，可继承本机访问；仍须符合配置的 Host／Origin／端口检查 |
| SparkX／其他独立客户端，即使与后端同机 | 保留安装凭据和后端身份验证 |
| 外部网站尝试调用本机 WebChat | 不获得本机权限；在访问受保护数据或产生效果前拒绝 |
| 远端伪造 Host、转发头或 Electron／浏览器标记 | 不获得本机权限 |
| Gateway TCP 接口、MCP、ISCP、浏览器宿主控制、JingSi | 保留原有独立准入规则 |

自动准入必须同时满足：可信传输来源、明确配置的本机目标入口、允许的浏览器请求上下文，以及有效的部署与 Owner 绑定。任何单个请求头都不能证明来源或身份。域名解析到本地 IP 也不够；`example.localhost` 等任意名称不自动受信任。

## 4. 产品决策

| 编号 | 问题 | 决策及状态 | 影响 |
|---|---|---|---|
| D01 | 本机免凭据是信任整台机器，还是仅部署 SparkClaw 的系统用户？ | **已确认：信任整台本机** | 本机其他系统用户的进程也能连接回环地址，不承诺系统用户之间的隔离；回环 TCP 无法识别浏览器属于哪个系统用户 |
| D02 | 本机 WebChat 是否拥有完整 Owner 权限，包括签发、撤销其他设备凭据？ | **已确认：完整 Owner 权限** | 本机设备管理不另设凭据输入；原有业务／工具审批仍然有效 |
| D03 | 本机入口是否允许 HTTP，而局域网继续 HTTPS？ | **已确认：本机回环 HTTP 即可，局域网使用验证证书的 HTTPS** | HTTP／HTTPS 路由及监听绑定须验证后再选端口方案；HTTP 本机入口不要求用户配置浏览器证书信任 |
| D04 | 已授权本机用户通过 SSH／本地终止的转发，能否将本机访问能力转授给另一台设备？ | **已确认：接受，按本机用户主动转授处理** | 入口看到的是本机连接对端，而非转发背后的远端；这是已接受的整机信任边界 |

D01–D04 均来自用户明确回答，不是推断的默认值。本版本没有尚未回答的产品问题。用户随后明确授权完善设计并开始实施；部署完成须有真实运行证据。

本次实施采用以下规则：

- 请求显式携带凭据时，继续走普通凭据校验。无效或已撤销时明确拒绝，不悄悄降级成本机 Owner。界面另提供用户显式触发的“清除凭据并使用本机访问”，仅清除当前服务凭据并重新核验本机准入，不删除会话历史；构建时固定 Token 无法由此清除，须明确说明。
- 本机工作台权限与可撤销的远端设备身份分离。撤销所有用户设备后，仍保留有意设置的本机管理／恢复入口，与 D02 一致。
- 显示“本机访问”，不套用普通凭据的退出登录按钮。关闭页面结束该页面活动；重新打开已启用的本机入口可以再次自动认证。关闭本机访问属于部署策略操作，而非浏览器退出登录。
- SSH 隧道或其他终止于本机的转发可能呈现为回环连接。D04 明确接受 D01 整机信任模型下的这类转授。产品必须说明此限制，不能声称能识别任意隧道背后的远端终端。转发仍须保持获准的 Host／Origin／端口，任意端口映射不会自动受信任。

## 5. 身份与权限

建议区分三个概念：

| 概念 | 生命周期与范围 |
|---|---|
| Deployment／Owner | 由私有本机配置及后端状态核验，不由 URL 或请求体选择 |
| 本机工作台权限 | 仅适用于受控本机 WebChat 入口，不是可携带到局域网使用的 Bearer，也不是某个独立桌面端的凭据 |
| 浏览器安装／会话 | 区分浏览器生命周期及 R3 本地数据，不意味着共享会话数据库 |

公开身份响应包含 `access_mode=local`、`local_access_id`、`owner_id`、`actor_id`，`client_id` 为空且不含秘密。本机变更请求记录准入审计，包含已注册的方法／路由、Actor、`auth_method=local`、`local_access_id` 和 `owner_id`，不记录请求正文、查询参数或秘密；原有业务审计继续记录结果。准入事件只表示获准进入处理器，不表示操作已成功完成。

禁止把 `desktop-client.json` 复制进浏览器存储，禁止将可撤销的桌面身份充当永久本机权限，也不把现有管理凭据扩展成网络 API Token。现有管理 Socket 保留原有路由集合。新的本机工作台传输须有独立明确的边界和路由策略。

实施前身份及事件处理器要求 `client_id`，连接撤销逻辑会检查持久化 Client。实现采用独立本机身份并复用 Owner 范围检查；空 Client ID 不能继承旧调试身份的全局权限，会话、配置档案、文件和审批仍限定于部署绑定的 Owner。

完整 Owner 权限仍执行原有业务授权和工具审批。设备凭据签发复用现有幂等、一次性展示流程；本机会话本身不能导出成远端凭据。

## 6. 传输与浏览器边界

### 6.1 可靠判断本机来源

Docker 端口发布路径可能改变连接地址。不得把 Docker 网关地址、私网网段、Host、`X-Forwarded-For` 或 User-Agent 当作本机浏览器的身份证明。

选定方案（细节见 6.4）：由宿主机上的 WebChat 入口观察真实连接的对端及目标，提供页面资源，并经私有、经过认证或受操作系统权限保护的通道连接 Gateway。选定的 Unix Domain Socket 独立于现有凭据管理 Socket。Gateway 无需因此发布宿主机 TCP 端口。

另一候选方案是独立绑定回环地址的入口，并配置同样受保护的上游。局域网入口及其他容器不能借此取得本机权限。本次采用 6.4 的独立宿主入口及私有上游，保持原有集成路由及已验证的桌面 HTTPS／WSS 语义。

D01 不要求系统用户之间的隔离。将来若改成仅部署用户受信任，必须在建立本机工作台权限前补充系统用户验证。仅把上游 Socket 设为 Owner 私有，无法区分访问开放回环 HTTP 监听的不同系统用户。

### 6.2 浏览器来源检查

取消手动输入 Token，不能让外部网站借浏览器的 localhost 访问能力操作工作台。授予本机权限之前：

1. 核验可信传输及精确配置的本机 Host／端口；拒绝非预期域名及有歧义的地址解析。
2. Origin 必须匹配预期协议、主机及端口；需要浏览器 Origin 的请求拒绝 `null`、外站和畸形值。WebSocket 同样核验 Origin。
3. 对没有 Origin 的请求，使用 Fetch Metadata 及仅限同源的请求证明／会话机制。简单 GET、图片、表单提交或宽松 CORS 响应不能单独建立本机权限。
4. 本地会话建立及受保护 Cookie／会话调用需防 CSRF。若采用 Cookie，使用 host-only、HttpOnly、同站限制、与协议匹配的 Secure 设置、有界服务端有效期及入口绑定检查。Cookie 的 Domain／Path 属性本身不够，因为 Cookie 不按端口隔离。
5. JSON、上传下载、SSE、语音 Ticket 创建及 WebSocket，以及重试重连路径，均遵守同一边界。本机上游秘密不进入 HTML、JavaScript 包、URL、日志或浏览器存储。保留现有语音协议的短期、一次性 URL Ticket 作为唯一受控例外：绑定签发入口和本机主体、消费前核验、禁用访问日志、禁止缓存和 Referer 泄露；复制到局域网入口不可消费。设备凭据仍只在用户明确签发时临时展示。
6. 工作台 HTML 及错误响应发送 `Content-Security-Policy: frame-ancestors 'none'`，拒绝 iframe／object／embed 入口。API 同源检查不能证明顶层页面受信任，必须独立防止点击劫持。

不允许的受保护请求应在执行前拒绝；单靠 CORS 响应头只约束浏览器读取响应。除 `fetch` 外，还需检查原始请求及资源嵌入场景。

本机会话证明即使被复制，也不能在局域网／客户端入口鉴权；必须明确定义并测试这种绑定。普通客户端不能仅凭浏览器 User-Agent 取得 R3 安装或可执行宿主授权。

整机信任意味着本机原生进程能够模仿浏览器请求。HTTP 请求头无法证明发送程序的身份。产品可以保留独立客户端的凭据注册流程，但没有更强的操作系统边界，就不能声称隔离了所有受信任的本机程序。

### 6.3 本机 HTTP 与局域网 HTTPS

按照 D03，自动认证的 HTTP 入口只能绑定回环地址。不能把本机权限凭据放到明文局域网入口，也不能重定向到远端 Origin。会话及来源核验须包含协议和端口。

实施前测试环境在工作台端口统一提供 HTTPS，包括回环访问。本次增加独立本机端口，保留现有 LAN／桌面端口和 TLS overlay。不能预设通配监听与另一个监听可以无冲突占用同一端口。保留局域网证书校验，以及 R3 宿主控制对 Gateway 原生 TLS 的要求。

### 6.4 本次选定的实现契约

- 独立 `local-webchat` 进程在宿主网络绑定 `127.0.0.1:18794` 与可用的 `[::1]:18794`；端口由 `SPARKCLAW_LOCAL_WEBCHAT_PORT` 配置。仅接受该端口的 `localhost`、`127.0.0.1`、`[::1]` Host。现有 LAN／桌面入口保持原配置。产品容器使用 Linux host networking，禁止借 Docker bridge 对端推断本机身份；其他平台只允许经验证的宿主进程模式。
- 提供独立构建的 WebChat 静态资源。页面禁止被嵌入；API 不发送跨源许可。常规 API 要求非秘密标记 `X-SparkClaw-Local-WebChat: 1`、`Sec-Fetch-Site: same-origin`，并在存在 Origin 时精确匹配 `http://Host`。缺少 Fetch Metadata 的客户端明确拒绝，不扩大准入。顶层页面及无秘密的健康检查可匿名加载，不授权业务。
- 不创建 Cookie 会话或浏览器 Bearer。授权每个请求重新判断；连接的寿命依附服务进程。WebSocket 使用同源 Origin／Fetch Metadata 和已绑定入口的短期一次性 Ticket，不要求浏览器无法设置的自定义握手头。
- Gateway 新增独立 `local-webchat/workbench.sock`（0600），私有目录 0700。`local-webchat.json`（0600）包含部署／Owner 绑定及独立的随机上游秘密。入口读取并核验权限，以专用请求头传递秘密；Gateway 只在该 Socket 接受。既不使用管理 Socket，也不注册可携带的普通设备凭据。
- 私有身份核对接口仅在新 Socket 存在。入口验证部署、Owner、独立本机身份后代理业务；不跟随重定向，不接受客户端注入的转发身份头。配置缺失、权限异常或身份不匹配均关闭本机授权，不影响独立客户端。
- Gateway 路由注册明确标记工作台业务路由并复用处理器；本机表排除 `/mcp`、`/api/bridge/`、`/api/jingsi/`、`/api/r3/`、配对及浏览器宿主控制。新增路由不会仅因属于 `/api/` 自动获得本机权限。Owner 的设备管理及集成设置属于工作台业务。
- 本机主体使用独立的 `local_access_id` 和 `access_mode=local`，`client_id` 为空且不充当持久化 Client。身份查询、事件流、审计及语音显式支持此类型；普通设备撤销仍校验持久化 Client。显式 Bearer 优先且无效即拒绝，不能覆盖失败结果。启用本机入口要求普通 Gateway 认证同时开启。
- 当前阶段仅改造已存在的服务端存储 Web UI；浏览器 R3 安装／本地存储另行实施。每次初始连接先确认身份再加载私有数据，恢复只重读，不重放消息／审批／签发。

## 7. 前端及失败行为

UI 应采用后端确认的访问状态，不能再以 localStorage 中是否存在 Token 推断授权。此规则覆盖首次私有数据加载、后台刷新、工作台 SSE、二进制获取、语音及重连。

| 状态／事件 | 拟议行为 |
|---|---|
| 本机首次打开 | 自动验证本机访问，再加载授权数据；不要求凭据，也不意外创建会话 |
| 局域网首次打开 | 保留原有凭据登录 |
| 显式凭据被拒绝 | 显示无效／已撤销；不退回本机权限 |
| 后端不可用 | 显示连接失败及重试；不新建身份，不重放写操作 |
| 本机配置缺失或身份不匹配 | 说明本机访问配置故障；保留独立客户端及显式本机恢复 |
| 本机访问被禁用或会话失效 | 停止本机受保护流及操作，不扩大匿名访问 |
| 页面刷新／后端重启 | 重新核验及刷新状态，不重新提交消息、发送、审批或凭据签发 |
| 所有普通设备被撤销 | 按 D02，本机入口继续可用；已撤销设备继续无效 |

唯一开关为 `SPARKCLAW_LOCAL_WEBCHAT_ENABLED`：产品配置默认 `true`，独立 Gateway 调试默认 `false`；非法值启动失败。切换后重新协调／重启服务；禁用停止回环入口和私有工作台 Socket，关闭活动连接，旧本机 Ticket 不再可用。切换认证不删除浏览器历史，也不改变数据归属。

## 8. 验收计划

以下是验收要求；已完成证据和剩余部署验收见第 10 节：

| 编号 | 必须具备的证据 |
|---|---|
| A01 | 干净浏览器配置在已配置的 IPv4／IPv6／localhost 入口可打开工作台并使用授权 API，无需输入或持久化设备 Bearer |
| A02 | 另一台真实局域网机器无凭据得到 `401`，持自己的有效凭据成功 |
| A03 | 同机使用局域网 IP／域名访问仍走普通凭据登录 |
| A04 | 伪造 Host、Origin、转发头、浏览器标记及 Docker 网络来源不能取得本机权限 |
| A05 | 外站／null Origin、资源嵌入、表单、CORS 预检、重定向及 WebSocket 尝试不能读取受保护数据或触发修改 |
| A06 | 直接复制到局域网入口的本机会话／证明无效；无效或撤销的显式设备凭据不能降级放行 |
