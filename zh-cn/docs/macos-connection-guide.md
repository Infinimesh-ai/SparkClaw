# SparkClaw Mac 实机联调连接指南

> 语言：简体中文 | [English](../../docs/macos-connection-guide.md)

配套文档：[客户端与后端架构 R3](client-backend-architecture-design.md) 和 [macOS 桌面端设计 R3](macos-lan-desktop-design.md)。

日期：2026-09-30。本指南用于开发和 Mac 实机验收，不表示已配置远程访问、实现 R3 或迁移数据。Linux 后端负责业务处理和邮箱保存；Mac 本地保存自己的对话、消息、任务历史、生成文件及其他非邮箱用户数据。客户端之间只同步邮箱。Mac 浏览器自动化通过统一后端适配层操作它自己的真实内嵌浏览器。

产品连接使用局域网 HTTPS 和客户端主动建立的鉴权 WSS 宿主通道；下面的 SSH 是可选开发接入。同机 Linux 客户端可以使用回环地址，异机 Mac 必须连接 Linux 主机可达的 LAN origin，不能使用 Mac 自己的 localhost。配对、ClientStore 和远程适配器仍待实现，因此本指南尚不是面向最终用户的安装教程。

Mac 构建包含 UI、本地数据库／文件存储、Browser Host Agent、Electron／Bridge 执行核心及经验证的受管页面资产。不传输 Gateway、模型、后端服务配置、App-CLI Registry／Executor、服务端数据库转储或凭据。客户端本地存储是必需组件，不是共享后端数据库副本。

## 1. 准备 Mac

让 Mac 与 Linux 主机连接同一个可互通的局域网，Mac 登录桌面并接通电源。避免带客户端隔离的访客 Wi-Fi。联调 GUI 时保持登录会话；持续测试可在 Mac 终端运行 `caffeinate -i`，测试结束按 Ctrl+C。Mac 合盖、休眠或退出可能使 Mac 宿主任务失去执行资源，须验证等待/结果不明与租约到期处理；后端常驻收信应继续，其他任务遵循 R3 的执行与交付预算。

Mac 打开：**系统设置 → 通用 → 共享 → 远程登录**。开启后选择“仅这些用户”，加入用于联调的 Mac 用户。基础构建与日志检查无需开启远程用户的“完全磁盘访问”。记录页面给出的 `ssh 用户名@主机名`。[Apple 官方远程登录说明](https://support.apple.com/guide/mac-help/allow-a-remote-computer-to-access-your-mac-mchlp1066/mac)

## 2. 提供这些非秘密信息

在 Mac 终端分别运行：

```sh
sw_vers
uname -m
id -un
scutil --get LocalHostName
networksetup -listallhardwareports
```

局域网 IP 可从“系统设置 → 网络 → 当前网络 → 详细信息 → TCP/IP”查看。若使用终端，先从最后一条命令确认当前网卡设备名，再执行 `ipconfig getifaddr en0`；只有当前网卡确实是 en0 时才使用此示例。

发给我以下内容即可，密码和私钥不要放进聊天：

```text
Mac 局域网 IP：
Mac 用户名：
macOS 版本：
CPU 架构（arm64 / x86_64）：
是否已开启“远程登录”：
Mac 当前是否已登录图形桌面：
```

如果使用 Remote Login 页面提供的 `.local` 主机名失败，改用已核实的局域网 IP；这不代表 SSH 服务不可用。

## 3. 配置 SSH 密钥

收到上述信息后，我可以在 Linux 的本任务 `work/` 中创建专用 SSH 密钥，把**公钥**给你添加到 Mac 对应用户的 `~/.ssh/authorized_keys`。已有可用的受授权 SSH 连接可直接复用。无需把 Mac 密码或私钥交给我。

如果手工添加公钥，以下模板在 Mac 的目标用户终端运行；先把占位整行换成我提供的实际公钥，再执行：

```sh
mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat >> ~/.ssh/authorized_keys <<'PUBLIC_KEY'
替换为完整的 ssh-ed25519 公钥行
PUBLIC_KEY
chmod 600 ~/.ssh/authorized_keys
```

这一步仅追加专用公钥，不覆盖已有授权记录。实际需要文件传输时使用 SSH/SFTP；开发路径优先 `~/Documents/SparkClaw-dev`，避免直接覆盖 Mac 上可能已有的工作副本。

首次连接核对主机指纹：Mac 可运行以下命令显示 SSH 主机公钥的 SHA-256 指纹：

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Linux 初次连接显示的 ED25519 指纹应与它一致；如服务选用其他算法，核对对应类型的主机公钥。不要关闭 host key 校验来绕过错误。

## 4. 连接后先做只读检查

实际用户名、地址和密钥路径确定后，连接形式为：

```sh
ssh -i /absolute/path/to/task-key MAC_USER@MAC_LAN_IP
```

在远端检查：

```sh
sw_vers
uname -m
xcode-select -p
command -v node
command -v npm
```

开发构建时再核对客户端锁定的 Node/npm 要求、可用空间、签名环境和 Linux 可达性；开发工具不作为正式安装包的外部运行依赖。检查成套 Bridge/页面资产版本、Mac Browser Host 能力、ClientStore／本地数据路径及客户端包白名单；Mac 不安装 Linux 业务后端组件。

SSH 可完成客户端文件同步、构建依赖安装、客户端构建、单元测试和日志读取。GUI 测试需要在登录的 Mac 用户会话中启动开发应用或安装包；可先由你从 Mac 终端/Finder 启动。若需远程启动，再单独验证 launchd GUI 会话和权限，而不是假设 SSH shell 已拥有图形会话。

## 5. R3 产品连接与验收

R3 组件实现后，记录后端可达的 HTTPS origin、部署身份／证书指纹、已配对的 Owner／客户端／宿主标识、所用构建版本及实际客户端本地数据根目录，检查可用空间和本地 Schema 版本；记录中不包含密钥。应用配对与宿主权限是两项授权，SSH 登录不能代替它们。

凭据交换前先验证服务端信任。随后由 Mac main 主动建立 WSS，注册 host_id／runtime_generation／能力并取得角色限定宿主租约；裸 CDP 和 Linux 私有 Adapter secret 不对外暴露。可选 SSH 隧道可辅助网络诊断，但不能绕过证书主机名校验或充当产品控制通道。

| 检查 | 预期证据 |
|---|---|
| 非邮箱本地数据 | Mac 创建对话 A、Linux 创建 B；分别重启后保留自己的消息、任务历史和文件，对方客户端不会自动出现该对话 |
| 后端邮箱同步 | 两端收到获授权邮箱的版本／删除；离线缓存、游标重置可恢复；清除本地缓存不删除后端邮件 |
| 浏览器适配层 | 使用无外部副作用测试页，通过同一后端适配层分别在 Mac 和 Linux 导航、输入随机标记、读取 DOM、接收事件并取消 |
| 仅内嵌活动 | Mac 网站请求由 Mac 发出并操作可见内嵌页面；拒绝独立／系统浏览器自动化及静默后端替代；获准子页面仍内嵌 |
| 对话绑定 | 同一 Mac 快速切换 A／C，各自保持页面，迟到事件不串对话，无页对话显示空态 |
| 后端采集角色 | 专用浏览器仅作为后端采集资源并持有独立 Profile；客户端退出后常驻收信继续，不新增重复采集器 |
| 本地文件交付 | 下载文件、接收生成输出、另存附件副本，验证本地清单／哈希；模拟磁盘满和 ACK 丢失，后端完成不得虚报本地保存 |
| 故障恢复 | 断网、休眠／合盖、退出、重启、吊销、丢响应，验证资源端租约到期、有界临时保留及未知写操作不重放 |
| 隔离与迁移 | 拒绝错误 Owner／客户端／证书，检查非邮箱内容清理；验证本地备份／导入及已分配旧数据，不复制服务端数据库 |

使用隔离测试数据及专用本地数据目录，连通性测试不迁移或删除现有生产历史。真实邮箱操作继续遵循既有授权及资格边界，不能用无副作用测试页通过代替邮箱验收。

GUI 测试在登录的 Mac 会话内运行，通过 SSH 收集脱敏证据。补测中文输入、Retina／多屏、内嵌站点登录／弹窗兼容、启用时的麦克风、本地权限、安装包白名单、选定 CPU 架构、签名／公证及升级／Schema 回退。必要的人工屏幕共享不属于产品页面传输。

证据对应 R3 A01–A16 和 Mac M01–M10。SSH 可达、成功构建或仅 Linux 测试通过，都不表示这些用例完成。具体产品注册／构建命令在对应实现存在后补齐，不虚构已经可用的远程控制端点。

## 6. 联调结束

只删除本次专用 authorized_keys 公钥行，关闭不再需要的远程登录，保留其他密钥和访问设置。保留需要的开发成果、测试记录及客户端本地数据库／文件。卸载／升级应明确本地用户数据是否保留，不能把删除数据当作 SSH 清理的一部分。

之后产品使用自身局域网连接，不依赖 SSH。记录仍失败／待验收用例、临时数据清理证据，以及另行提出的旧数据迁移方案；区分 runtime 实现、硬件验收和生产切换状态。
