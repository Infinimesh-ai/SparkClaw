# macOS 桌面端设计 R3：局域网客户端与内嵌浏览器控制

> 语言：简体中文 | [English](../../docs/macos-lan-desktop-design.md)

日期：2026-09-30。版本：R3。状态：产品边界已确认，本地数据拆分、LAN 控制及 Mac 实机验收待完成。跨平台目标以[客户端与后端架构 R3](client-backend-architecture-design.md) 为准。本文同时取代原 R2.1 和中间修订 R2.2，不表示已实现代码或部署。

**Mac 呈现业务结果，持久保存自己的非邮箱用户数据，并且只在内嵌浏览器中执行获授权的浏览器命令。Linux 后端负责业务处理及邮箱权威存储。** Linux 客户端也遵循相同规则，包括与后端同机部署时。

## 1. 重新评估 R2.1 与 R2.2

| 旧假设 | R3 决定 | 影响 |
|---|---|---|
| R2.1 通过 WSS 展示 Linux 截图 | 已被替代 | 呈现 Mac 真实内嵌页面，不实现画面发布器或远程实时视口 |
| R2.2 共享后端对话／消息／任务 | 被用户明确补充取代 | 每个客户端拥有本地数据库／历史／文件，只同步邮箱 |
| Mac 不含数据库或浏览器执行代码 | 已被替代 | ClientStore、Host Agent、Bridge 和受管页面资产应包含在客户端中 |
| 核心业务留在 Linux | 保留 | 模型／路由／Workflow／审批验证仍由后端负责 |
| 统一适配层控制真实 Linux 和 Mac 浏览器 | 保留并明确角色 | 后端采集及客户端内嵌宿主共享控制语义，不共享 Profile／数据 |
| 交互任务可任意选择设备或独立浏览器窗口 | 调整 | 客户端浏览器活动固定在该客户端内嵌浏览器 |
| Mac 下载上传为共享后端产物 | 调整 | 下载和生成文件持久保存在本地，邮件附件仍属于后端邮箱 |
| 桌面端天然只能使用回环地址 | 调整 | 目标支持 LAN，同机回环仅为传输优化 |
| 相同 URL／元数据即可使两端页面完全同步 | 不作保证 | 不跨客户端同步像素、DOM、登录态或对话 |

项目目前不满足“只编译 Mac 安装包即可发布”的条件。先要修改后端历史／上下文、文件交付、客户端持久化、浏览器路由及连接身份，再做实机验收。

## 2. Runtime 与安装包边界

| 组件 | Mac 客户端 | Linux 后端 |
|---|---|---|
| 工作台与本地状态 | React UI，主进程 SQLite／文件、发送队列及邮箱缓存 | 业务 API 与临时执行上下文 |
| 业务处理 | 提交意图、呈现结果，不复制业务策略 | 模型、路由、Workflow、验证及已接纳任务调度 |
| 浏览器命令 | Host Agent 操作真实内嵌 WebContents | Controller／Playwright 经 BrowserHostAdapter 编排 |
| 浏览器存储 | 客户端本地 Profile、下载及任务产物 | 专用采集 Profile、后端邮箱存储 |
| 网络连接 | HTTPS 业务／邮箱客户端及主动 WSS 宿主通道 | 鉴权入口及浏览器宿主 Broker |
| App-CLI | 仅必要且经验证的宿主／页面资产，不部署第二套 Registry／Executor | 保持现有公共 Registry／Executor 边界及授权 |

安装包白名单包括 Electron、UI、ClientStore／Schema 升级、受限 IPC／Host Agent、Bridge 和已验证受管页面资产；不包含 Linux Gateway 二进制、模型、服务管理器、服务端数据库转储、服务端凭据或 App-CLI Registry／Executor。“Mac 没有后端”不等于禁止本地用户数据库。

现有 main 进程需要拆开客户端启动与后端服务启动。Linux UDS 路径、systemd、/run/user 假设及后端私有密钥不能进入 Mac 装配；可移植部分继续复用 React UI 与现有内嵌页面执行核心。

## 3. 局域网连接与授权

同机 Linux 和远程 Mac 使用相同的逻辑 API。Mac 连接后端可达的 LAN HTTPS origin，验证证书／部署身份，获得安装实例专用客户端凭据。Mac 自己的 127.0.0.1 不是 Linux 主机。SSH 仅用于开发，不是产品连接方式。

首次登录必须由用户输入 SparkClaw 服务凭据，后端验证并绑定本安装身份后才解锁服务；不能随源码或安装包预置已解锁状态。同机 Linux 遵循同一规则。Mac 主进程通过受控认证流程把登录凭据保存到 Keychain，后续有效凭据可恢复连接；失效、吊销、退出或切换后端需重新登录。首次成功前不发任务、不同步邮箱、不接收可执行浏览器命令；解锁不替代宿主授权。详见统一架构的[首次登录规则](client-backend-architecture-design.md#31-首次登录与服务解锁)。

凭据领取与管理按统一架构的[3.2 节](client-backend-architecture-design.md#32-凭据领取与设备管理待实施)实施：首次凭据由后端主机受控初始化入口为目标设备独立签发；已有登录设备可在“设置 → 设备与凭据”新增设备。名称、client_id、创建／最后活跃时间和撤销状态可查，旧 Token 明文不可查。新 Token 仅领取时显示并支持复制／收起，遗失需撤销后重发；同一 Mac 的有效凭据跨连接复用，不能每次重连生成新身份，也不能复制 Linux 预置 Desktop Token。当前后端接口存在，但初始化领取入口、新版设置导航和 Mac 安全登录仍待实现，本轮只补文档。

实现时把 Keychain 项限定到经验证的部署／Owner／客户端身份。撤销当前设备后停止受保护通道、清除对应 Keychain 凭据并回到登录；保留本地历史与文件，后端邮箱和其他设备继续工作。全部用户设备无法登录时走后端部署用户的受控恢复流程，不能在 Mac 匿名请求新凭据。后端重启、签发丢响应和一次性明文过期按统一架构处理，不能从客户端静默重复签发。

现有严格 v1 回环描述符保持当前约束，另行实现版本化加载器。新加载器需要 Schema 版本、服务端 origin、部署身份、信任引用、客户端身份／凭据引用及浏览器宿主权限引用。这些是设计要求，不是当前代码已经接受的配置文件。

工作台凭据允许范围内的业务请求，独立宿主授权允许浏览器命令。Mac main 主动建立 WSS 控制通道，注册宿主身份、运行代次与能力，不开放 Mac 入站监听或裸远程 CDP。宿主绑定经认证的 Owner／客户端安装实例；重连产生新连接代次并撤销旧租约。

业务 API 名称和宿主消息信封待 Schema 冻结，不能把拟议端点写成可用命令，也不能把当前本地 relay 协议原样转发到局域网。

## 4. Mac 上的统一浏览器适配层

后端持有 BrowserHostAdapter，统一提供能力发现、资源获取、租约续期／释放、命令派发、结果／事件、取消及对账。本地 transport 连接后端浏览器，远程 transport 连接客户端 Host Agent；两者使用相同的经验证命令模型，保留 Controller／Bridge 和 App-CLI 公共边界。

Mac 客户端任务的调用链为：

```text
Mac 本地对话 -> 后端 Workflow / 授权
  -> BrowserHostAdapter -> 已鉴权的主动连接通道
  -> Mac main Host Agent -> 自有内嵌 WebContents
  -> 命令结果 / 事件 -> 后端业务处理
  -> 持久交付结果到 Mac ClientStore
```

导航、读取、点击、输入及任务范围内的浏览器操作，作用于 Mac 工作台中可见的页面；网站请求由 Mac 发出并使用它自己的会话。显式工具取证截图是有界本地任务产物／后端临时输入，不是连续呈现画面流。

远程信封绑定 request_id、命令序号、期限、参数摘要、客户端／任务／对话身份、宿主／运行／连接代次、租约及页面代次。ACK 仅表示接收，不表示完成。宿主命令 journal 区分未开始、已完成和结果未知，非邮箱 journal 的内容保存在客户端本地；不能因为通道断开就重放写操作。

宿主端检查只允许访问获授权的任务页和操作，不暴露任意 Shell、文件系统、未受管脚本注入、调试目标或个人浏览器。保留经验证的受管脚本流程。弹窗／新目标创建必须绑定同一任务，获准子页面也在内嵌视图中呈现；站点流程不受支持时报告能力不足，不能逃逸到外部自动化窗口。

取消使用独立控制预算。到期、吊销及代次变更在确认清理前先于资源端隔离命令。已经发往网站的写请求可能继续完成，应保留未知结果并对账。Mac 失联不会静默把交互浏览器任务迁移到 Linux。

## 5. 按本地对话呈现内嵌页面

维护本地对话／任务到宿主／页面及代次的映射。切换 A／B 时选择对应真实内嵌页，后台事件仍绑定原任务；没有页面时显示空态。切回 A 可以看到原页面，无需重建或重做任务。

所有客户端自动化保持内嵌，不增加独立任务浏览器窗口、不镜像 Linux 画面，也不再打开一个页面模仿原页面。同一任务被多个工作台窗口引用时，移动／聚焦真实视图或显示其位置，不能产生竞争控制者。隐藏面板、关闭页面和取消任务是不同操作。

后端命令结果与本地展示指向同一张 Mac 页面。另一客户端拥有自己的对话和页面映射，即使 URL 相同也是独立页面。后端专用浏览器是数据获取／操作资源，不是 Mac 要显示的页面。

## 6. 邮箱、文件与任务交付

邮箱缓存按 revision／cursor／tombstone 从后端同步；Mac 发起邮件变更也经过后端策略和冲突检查。Mac 退出后，后端常驻收信继续；Mac 不启动第二套采集器，不复制后端邮箱凭据。

本地对话可以引用经授权的邮箱记录。该对话历史及据此生成的报告仍在本地，原邮件附件保存在后端邮箱；另存附件副本属于 Mac。普通下载和生成文件不进入共享后端产物归档。

先持久保存请求 ID／上下文再提交；收到事件／结果／文件后，先本地提交再确认交付。后端临时输入／输出存储有界，确认或过期后清理。磁盘满、客户端缺席或输出过期必须显示为交付问题；业务完成与本地保存成功是两种状态。见 R3 的[执行与交付规则](client-backend-architecture-design.md#5-执行与可靠交付)。

不能通过选择另一客户端的对话来恢复，因为那里没有自动副本。用户已确认不迁移现有测试数据，新建客户端本地存储，不导入旧后端历史。未来客户端备份／恢复属于独立工作，不能重放已接纳请求。

## 7. 当前实现与实施顺序

用户已明确构建分工：当前 Linux 环境负责实现源码、Mac 构建配置及适用的 Linux／共享检查，再通过 Git 推送交付；用户在 Mac 同步指定提交并自行编译／打包和运行。当前环境不执行 Mac 编译、交叉构建、签名或公证，也不通过远程登录代编译。Mac 编译不阻塞 Linux 实施和源码交付；Mac 专属验收等待用户在对应提交上的反馈。每次交接附分支／SHA、实际构建命令和待验清单，见[连接指南](macos-connection-guide.md)。

| 阶段 | 交付项 | 门槛 |
|---|---|---|
| P0 | 在已确认数据／保留边界内冻结容量、控制字段、本地 Schema、传输范围和全新存储初始化 | 跨项目变化先取得 accepted 决策，不隐式删除账本 |
| P1 | ClientStore 与有界客户端上下文提交 | 对话／任务／文件本地持久化，无后端历史后备 |
| P2 | 凭据领取／设备管理／安全登录、LAN 身份、事件交付／ACK 和邮箱同步 | 首次解锁及凭据复用／撤销通过，证书／Owner／客户端隔离，丢响应可对账 |
| P3 | Broker 和统一本地／远程浏览器适配器 | Mac／Linux 内嵌命令、资源端租约、无外部自动化 |
| P4 | 文件交付及平台装配 | 验证本地保存，全新存储不导入测试历史，审核安装包白名单 |
| P5 | 推送源码后由用户在 Mac 构建及完成硬件／签名／升级验收 | 同一提交的 Mac 构建记录、GUI／浏览器故障矩阵及分范围切换证据 |

现有代码入口包括[桌面装配](../../apps/desktop/src/main/main.mjs)、[回环加载器](../../apps/desktop/src/main/local-backend.mjs)、[本地适配器](../../apps/desktop/src/browser/adapter-server.mjs)、[浏览器协议](../../apps/desktop/src/browser/protocol.mjs)、[页面呈现](../../apps/desktop/src/main/presentation.mjs)、[BrowserPanel](../../apps/webchat/src/desktop/BrowserPanel.tsx) 及[后端 Store 契约](../../services/gateway/internal/store/store.go)。它们现有的本机／共享状态行为不能证明 R3 已实现。

现有集成仍适用已接受的 App-CLI 持久账本及 JingSi Runtime v1 恢复保证。修改其保留／协议语义前，必须解决[跨项目门槛](client-backend-architecture-design.md#9-跨项目边界与待完成门槛)；内部适配器命名不能绕过契约。

## 8. Mac 专项验收与剩余问题

| 编号 | 必需的 Mac 证据 |
|---|---|
| M01 | LAN HTTPS 不依赖 SSH，拒绝错误证书／部署／客户端身份 |
| M02 | Mac 重启后保留本地对话／消息／历史／文件，Linux 没有收到副本 |
| M03 | 两端同步后端邮箱，包括删除和游标恢复，非邮箱历史保持独立 |
| M04 | 同一后端适配层导航／输入／读取真实 Mac 和 Linux 内嵌页，后端采集是独立授权角色 |
| M05 | 命令不能开启独立／系统浏览器自动化、复制 Profile 或替换为后端页面 |
| M06 | A／B 切换、弹窗及页面重启保持精确页面／任务归属，拒绝迟到事件 |
| M07 | 断网、合盖、休眠、退出、吊销及结果丢失能隔离命令并对账未知写操作 |
| M08 | 磁盘满、交付 ACK 丢失、后端重启及临时结果过期，不虚报保存或重复执行 |
| M09 | 在 Mac 验证 GUI 启动、中文输入、Retina／多屏、权限、启用时的麦克风及支持站点 |
| M10 | 安装包审计、选定 CPU 架构、签名／公证、升级／本地 Schema 回退和数据保留通过 |
| M11 | Mac 全新安装显示 SparkClaw 凭据解锁流程；验证错误凭据阻断、Keychain 保存及重启恢复、吊销／退出后的受保护通道停止，不删除本地历史 |
| M12 | 从后端初始化入口或已登录设备设置领取独立 Mac 凭据；只显示一次，跨重启／重连复用，遗失重发与撤销生效，设置真实可达；Linux 预置 Token、Keychain 明文及其他设备凭据不进入安装包／日志／Git |

全部 M 用例均待完成。产品归属、离线行为及后端临时处理／控制记录边界已确认，未交付结果最长保留至生成后 24 小时；旧测试数据迁移已移出范围。工程上仍需冻结边界内的容量／控制字段等参数、解决外部契约兼容并取得 Mac 实机证据。这是客户端／后端架构调整，不是画面查看器升级。
