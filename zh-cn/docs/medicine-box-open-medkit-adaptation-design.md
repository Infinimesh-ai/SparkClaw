# 药箱界面参考 open-medkit 的适配设计

> 语言：简体中文 | [English](../../docs/medicine-box-open-medkit-adaptation-design.md)
>
> 日期：2026-11-02。状态：设计已定稿，负责人于 2026-11-02 确认第 9 节各项，尚无代码改动。参考项目：[MonoYan/open-medkit](https://github.com/MonoYan/open-medkit) 提交 `8c2217ba707cf239ec3c8285c3ff3aa3b357a1c4`（MIT 许可）。范围：桌面端药箱的工作区页面、详情、添加／编辑弹窗、药品字段与本机数据迁移，以及文字录入。模块栏、药箱侧栏和照片识别链路保留。

## 1. 背景与目标

药箱模块已于 `add4e7dc`（Gateway `medicine.recognize`）和 `21a455cb`（桌面端／WebChat）提交，尚未推送或安装。现在的工作区只有一个逐行列表，药品一多就难以查找，也看不出哪些药快过期。

负责人要求药箱界面直接参考 open-medkit，并适配 SparkClaw。本设计要做到：

1. 采用 open-medkit 的信息结构和交互：统计行、搜索、按效期筛选、卡片／列表切换、排序、详情弹窗、两步添加流程。
2. 外观仍属于 SparkClaw 客户端：沿用玻璃主题 token、深浅色、字体和 Codex 式模块栏／侧栏，不引入 open-medkit 的暖纸色、衬线字体和深色顶栏。
3. 守住负责人此前的决定：固定 8 个功能分类、剩余数量用数字加单位、药盒正面照片识别、不调用摄像头。
4. 落实负责人 2026-11-02 的决定：药品字段改为名称、有效期、剩余数量、存放位置、用途、备注（另保留功能分类）；文字录入与照片录入并存，每次一种药品；两种录入保存同一格式，所有信息由用户确认后才入库；照片识别后剩余数量和有效期由用户填写；详情里可以快速加减剩余数量；AI 检索暂不实现。
5. 分两个阶段推进：第一阶段改界面和本机数据，只随桌面端发布；第二阶段加文字录入并调整识别输出，需要 Gateway 与桌面端配套发布。

## 2. 参考项目界面拆解

以下依据该提交的 `frontend/src` 源码、`backend/src/ai/prompts.ts` 和 README 截图整理。

| 界面 | open-medkit 的做法 |
|---|---|
| 顶栏 | 深色顶栏：Logo、居中的「AI 检索／药品列表」分段切换，右侧「添加药品」主按钮、主题切换和设置 |
| 页头 | 大标题「药品列表」，下面一行等宽小字统计：`药品总数 12 · 30天内过期 N · 已过期 1`，数量为 0 的项不显示 |
| 分类栏 | 左侧独立面板，「全部药品」加各分类，每行带计数，选中项为深色填充 |
| 工具栏 | 吸顶：搜索框（名称、品牌、用途、位置），状态分段「全部／30天内过期／已过期」，刷新、卡片／表格视图切换、排序分段「按过期时间／按添加时间」；有筛选时下方出现筛选标签和「清除筛选」 |
| 卡片 | 自适应网格 `minmax(260px, 1fr)`；名称加右上角状态徽标（已过期／N天后到期／未临期）；英文名与规格（等宽）；用途两行截断；底部分隔线下为有效期、剩余、位置。过期卡片整体淡红底，临期卡片淡橙底 |
| 表格 | 名称（附规格）、分类、有效期、状态、数量、位置、操作（编辑／删除） |
| 详情 | 弹窗：标题加分类、状态徽标；按状态显示一句话提示条；两列信息卡（品牌、规格、有效期、剩余数量、存放位置）；「用途／适应症」「备注」区块；底部「编辑药品」「删除药品」，删除需二次确认 |
| 添加 | 两步：①「输入原始描述」：一句话或多行批量文本，或拍照／相册选图（选图后补填有效期、位置）；②「核对并提交」：分「关键信息」「补充信息」两组表单，AI 填入的字段有闪烁提示 |
| AI 检索 | 首页大标题「今天想查什么？」加居中搜索框；把整个药箱和问题发给模型，流式返回简短 Markdown 回答，再按模型给出的 ID 列出命中药品；有基于药箱现状生成的建议问题 |
| 其它 | 到期推送（Telegram／Discord／飞书／邮件）、MCP Server、登录、AI 服务商设置、Docker 自托管 |

数据模型（`medicines` 表）：`name`、`brand`、`name_en`、`spec`、`quantity`（自由文本）、`expires_at`、`category`（自由文本，默认 7 类）、`usage_desc`、`location`、`notes`。临期判断：`expires_at < 今天` 为已过期，`今天 ≤ expires_at ≤ 今天 + 30 天` 为临期，没有有效期为未知。

## 4. 适配原则：逐项取舍

| open-medkit 元素 | 处理 | 说明 |
|---|---|---|
| 深色顶栏、Logo、主题切换、设置 | 不采用 | SparkClaw 已有窗口标题栏、全局主题和设置；药箱不另做顶栏 |
| 「AI 检索／药品列表」分段与 AI 检索 | 暂不实现 | 负责人决定后续另行讨论 |
| 页头统计行 | 采用 | 放在工作区标题下方 |
| 左侧分类面板 | 映射到现有侧栏 | 不重复做第二个分类面板；`MedicineSidebar` 保留现有样式和计数 |
| 搜索、状态分段、筛选标签、清除筛选 | 采用 | 纯客户端计算 |
| 刷新按钮 | 不采用 | 数据在本机，模块激活和保存后已自动重读 |
| 卡片／列表切换 | 采用，默认卡片 | 列表视图沿用现有行内编辑／删除 |
| 排序（按过期／按添加） | 采用 | 默认按过期时间 |
| 卡片样式和状态底色 | 采用，换用 SparkClaw token | 见 5.10 |
| 详情弹窗 | 采用 | 新增，点卡片打开；加剩余数量快速加减 |
| 两步添加 | 采用 | 第一步可选照片或文字，第二步统一核对；不调用摄像头，见 5.8 |
| 一句话文字录入 | 采用（第二阶段） | 每次一种药品；写了多种时提示分开录入，见 6.2 |
| 多行批量录入 | 不采用 | 负责人决定不支持一次输入多种药品 |
| 存放位置、用途、备注 | 采用（第一阶段） | 三项都选填，见 6.1 |
| 自由分类 | 不采用 | 保留 8 个固定功能分类，侧栏按它分组 |
| 自由文本数量 | 不采用 | 保留数字加单位 |
| 品牌、英文名、规格 | 不采用 | 负责人确定的字段里没有这几项 |
| 到期推送、MCP、登录、服务商设置、Docker | 不采用 | 见第 7 节 |
| 暖纸色、Noto Serif SC、Fraunces、DM Mono | 不采用 | 与客户端其它模块保持一致 |

SparkClaw 现有的「规格」「生产企业」两个字段一并去掉，旧数据的处理见 6.1。

源码只作设计参考，不整段拷贝。若实现时移植了某段代码（例如状态判断），须在文件头保留 MIT 版权声明。

## 5. 目标界面设计

### 5.1 整体布局

```text
+------+----------------+------------------------------------------------------------+
| 首页 | 药箱           | 药箱                                     [+ 添加药品]      |
|      | [+ 添加药品]   | 药品总数 12 · 30天内过期 2 · 已过期 1                      |
| 药箱 |                | ---------------------- 结果面板 ----------------------     |
|      | 按功能分类     | [搜索框] (全部|30天内过期|已过期)                          |
|      | 全部药品  12   |                 [卡片|列表] (按过期时间|按添加时间)        |
|      | 感冒       3   | 分类 · 感冒  状态 · 已过期  [清除筛选]                     |
|      | 发烧       2   | ------------------------------------------------------     |
|      | 止痛       1   | [卡片] [卡片] [卡片]    auto-fill, minmax(260px, 1fr)      |
|      | 咳嗽       0   | [卡片] [卡片] [卡片]                                       |
|      | 肠胃       2   | [卡片] [卡片] ...                                          |
|      | 过敏 … 其他    |                                                            |
+------+----------------+------------------------------------------------------------+

+------------------------------------+
| 名称              [状态徽标]       |
| 功能分类                           |
| 用途（两行截断，选填）             |
| --------------------------------   |
| 有效期  2027年12月27日             |
| 剩余  14 粒  |  位置  客厅抽屉     |
+------------------------------------+
```

模块栏、侧栏、窗口标题栏的结构和行为不变。工作区的标题、主按钮位置也不变，主体换成「工具栏加结果区」的面板。

### 5.2 页头与统计行

- 标题照旧：选中「全部」时为「药箱」，否则为分类名。
- 原说明文字「家中常备药品，按功能分类管理。」移到空状态里，页头这一行换成统计行。
- 统计行用小号字和等宽数字（`font-variant-numeric: tabular-nums`，不换字体）：`药品总数 N`，然后 `· 30天内过期 N`（临期色）和 `· 已过期 N`（危险色），为 0 时不显示该项。
- 统计按整个药箱计算，不受分类、搜索和状态筛选影响，与侧栏计数口径一致。
- 「添加药品」主按钮位置和禁用规则不变。

### 5.3 工具栏

吸顶在结果面板顶部，面板使用 `--ui-glass-strong` 底色、`--radius-panel` 圆角、`--ui-divider` 分隔线。

- 搜索框：占位「搜索名称、用途、位置、备注」。匹配时忽略大小写和首尾空格，分类中文名也参与匹配。
- 状态分段：「全部／30天内过期／已过期」。选中「30天内过期」用临期色填充，「已过期」用危险色填充，「全部」用 `--ui-ink` 反色填充。
- 视图切换：卡片和列表两个图标按钮（lucide `LayoutGrid`、`List`），带 `aria-pressed` 和提示文字；默认卡片。
- 排序分段：「按过期时间」（升序，没填有效期的排最后，同日按名称）和「按添加时间」（新的在前）。
- 筛选标签：分类不是「全部」、状态不是「全部」或搜索不为空时，工具栏下方出现 `分类 · 感冒`、`状态 · 已过期`、`搜索 · 布洛芬` 和「清除筛选」。清除筛选把三者都重置，侧栏选中项回到「全部药品」。
- 三种筛选叠加生效：侧栏分类、状态、搜索。
- 窄宽度下工具栏折成两行：搜索加状态一行，视图加排序一行。

### 5.4 卡片视图

- 网格：`grid-template-columns: repeat(auto-fill, minmax(260px, 1fr))`，间距 16px，面板内边距 20px。
- 卡片：圆角 18px，1px `--ui-divider` 边框，`--ui-glass-strong` 底，轻阴影；悬停上移 2px、阴影加深。整张卡片是一个 `<button>`，点开详情。
- 第一行：名称（17px、600，单行截断）加右侧状态徽标。徽标文字：`已过期`、`今天到期`、`N天后到期`、`未临期`、`未填有效期`。新录入的药品有效期必填，「未填有效期」只会出现在以前录入的药品上。
- 第二行：功能分类中文名，12px 次要色。
- 第三行：用途，两行截断；没填时保留两行高的空位，使卡片对齐。
- 分隔线以下：`有效期  2027年12月27日`（过期或临期时日期着色）；`剩余  14 粒 │ 位置  客厅抽屉`，位置没填时显示「未填写」（次要色）。数量为 0 时剩余显示「已用完」。
- 状态底色：已过期为危险底色 60% 加危险色 15% 边框；临期为临期底色 50%；其余为常规卡片。
- 卡片上不放编辑／删除按钮，这两个操作在详情弹窗和列表视图里。
- 入场动画：`fadeUp`（16px 位移、0.45s），每张错开 50ms，最多错开 12 张；`prefers-reduced-motion` 下关闭。

### 5.5 列表视图

在现有 `medicineRow` 的基础上改成表格语义（`<table>`），保留现有的悬停编辑／删除：

| 列 | 内容 |
|---|---|
| 名称 | 药品名称 |
| 分类 | 功能分类中文名 |
| 有效期 | `YYYY年M月D日` 或「未填写」 |
| 状态 | 与卡片相同的徽标 |
| 剩余 | 数量加单位，数字等宽；为 0 时显示「已用完」 |
| 位置 | 存放位置，没填时显示「—」；窄于 1024px 时隐藏 |
| 操作 | 编辑、删除图标按钮，悬停或聚焦时显示 |

点击行打开详情；点编辑直接打开编辑弹窗；点删除沿用现有的危险确认。宽度小于 600px 时每行折成两行（名称加徽标／有效期·剩余·位置加操作）。

### 5.6 详情弹窗

复用现有弹窗外壳（`documentPickerOverlay` 和 `useDismissibleLayer`，支持 Esc、点遮罩关闭、焦点陷阱），最大宽度 720px。

- 头部：名称（22px），后面是分类标签和状态徽标；右上角关闭按钮。
- 提示条，按状态显示：
  - 已过期：「这盒药已经过期，请勿继续使用，尽快清理。」
  - 临期：「这盒药将在 N 天内到期，留意尽快使用或更换。」
  - 正常：「状态良好。」
  - 未填有效期：「还没有填写有效期，建议补充。」
- 两列信息卡：有效期、剩余数量、存放位置、功能分类、添加时间。剩余数量卡带快速加减，见 5.7。
- 区块：「用途」「备注」，没填时显示「未填写」。
- 底部：「编辑」（次按钮，切换到编辑弹窗）和「删除」（危险次按钮，走 `useConfirm` 危险确认）。删除失败时在底部显示错误，弹窗不关闭。

### 5.7 剩余数量快速加减

- 位置：详情弹窗的「剩余数量」信息卡，显示为 `[−] 14 粒 [+]`。卡片和列表上不放，避免误触。
- 每点一次加减 1 个单位，下限 0，上限 100000。小数数量（如 2.5 毫升）同样加减 1，减到不足 1 时归 0。数量为 0 时「−」禁用。
- 每次点击立即保存：用该药品当前的完整字段调用 `save()`，只改 `quantity`，保存格式与编辑完全相同。
- 保存期间两个按钮禁用，数字先在界面上更新；本机 SQLite 写入只需几毫秒，不做合并或防抖。
- 保存失败时数字回到保存前的值，底部显示「剩余数量没有保存，请重试。」
- 保存成功后列表随之更新。数量为 0 时，卡片和列表的剩余一栏显示「已用完」（次要色）。药品不会被自动删除，效期状态也不受影响。
- 无障碍：按钮的 `aria-label` 为「减少 1 粒」「增加 1 粒」（单位随药品），数字区域 `aria-live="polite"`。

### 5.8 添加／编辑弹窗

添加分两步，顶部有步骤标签「① 录入」「② 核对并入库」。照片和文字只是两种录入方式，第二步完全相同。

第一步：录入

第一步顶部是「照片／文字」分段，默认照片；照片识别不可用而文字解析可用时，默认文字。

照片：
- 沿用现有照片区：「选择照片」按钮、拖入、粘贴、缩略图预览和「重新选择」。不加「拍照」按钮，不使用 `capture` 属性。
- 照片只识别包装正面能看清的药品名称、功能分类、单位，第二阶段起再加用途。剩余数量和有效期一律不从照片读取，即使照片上印有日期，也留给用户在第二步填写；存放位置和备注同样由用户填写。
- 照片区下方一行固定说明：「照片只用于识别，不会保存。剩余数量和有效期请在下一步填写。」
- 选图后立即识别，进度文字沿用「正在识别药品…」，识别成功后自动进入第二步。
- 识别失败（看不出是药品、照片读不出、服务不可用）时停在第一步，显示现有的问题文案，并给出「直接填写」按钮。

文字（第二阶段）：
- 多行输入框，占位「例如：布洛芬缓释胶囊，还剩 14 粒，2027 年 12 月到期，放在客厅抽屉，退烧止痛」，最多 500 字。
- 每次只录入一种药品。点「解析」或按 ⌘／Ctrl+Enter 后发给后端解析，解析中显示「正在解析…」，不能重复提交。
- 文字里写了的名称、剩余数量、单位、有效期、存放位置和用途就填入，没写的不猜；功能分类按名称和用途判断；只写年月的有效期按当月最后一天填入。备注不从文字提取。解析结果在第二步核对。
- 输入框下方一行固定说明：「文字只用于解析，不会保存。一次录入一种药品，解析结果请在下一步核对。」
- 解析成功后自动进入第二步。
- 文字里写了不止一种药品时，停在第一步，什么都不填，提示「一次只能录入一种药品，请分开录入。」
- 看不出药品时停在第一步，提示「没能从文字里认出药品，请写出药品名称，或直接填写。」；服务不可用时提示「解析服务暂不可用，可以直接填写。」
- 没有连接，或对端没有 `medicine.parse` 操作时，「文字」分段保留但禁用，悬停说明原因。

两种方式共用：
- 底部始终有「跳过，直接填写」。照片和文字都不可用时，直接从第二步开始。

第二步：核对并入库

- 照片录入、文字录入和手动填写共用同一个表单、同一套校验，保存同一个 `MedicineFields`，不记录来源。录入方式只决定哪些字段预先填好。
- 「关键信息」（必填）：药品名称、功能分类、剩余数量加单位、有效期。
- 「补充信息」（选填）：存放位置、用途、备注。
- 各字段的来源：

| 字段 | 照片录入 | 文字录入 | 手动 |
|---|---|---|---|
| 名称、功能分类、单位 | 识别填入，待核对 | 解析填入，待核对 | 用户填写，输入名称时猜分类 |
| 剩余数量、有效期 | 留空，用户必须填写 | 文字里有就填入并待核对，没有就留空 | 用户填写 |
| 存放位置 | 留空，可不填 | 文字里有就填入并待核对，没有就留空 | 用户填写，可不填 |
| 用途 | 第二阶段起识别填入并待核对，否则留空 | 文字里有就填入并待核对，没有就留空 | 用户填写，可不填 |
| 备注 | 留空，可不填 | 留空，可不填 | 用户填写，可不填 |

- 预填的字段在标签旁显示「待核对」，用户改过该字段后标记消失。表单上方一行提示：「以下内容由照片识别／文字解析填入，请逐项核对后确认入库。」
- 预填字段闪一次高亮（`flashField`，0.5s），减弱动效时不闪。
- 聚焦落在第一个空的必填项上。照片录入一定是剩余数量；必填项都已填好时落在名称上。
- 手动输入名称时，仍按 `suggestMedicineCategory` 猜分类，但不覆盖已识别或用户选过的分类。
- 按钮：「上一步」（回到第一步，已填内容和原照片／文字都保留）、「取消」、「确认入库」。必填项不全时「确认入库」禁用。
- 识别和解析结果不会直接写进药箱；只有用户点「确认入库」才保存。

编辑：不显示步骤标签，直接是第二步表单，必填项相同，按钮为「取消」「保存」，聚焦在剩余数量。以前没填有效期的药品，编辑保存时须补上有效期。

保存成功后的行为不变：关闭弹窗、重读列表；如果当前在某个分类下，跳到新药所在的分类。

### 5.9 空状态、加载与错误

- 药箱为空：图标、「药箱里还没有药品」、原说明文字，以及「添加药品」按钮。没有桥接时按钮禁用。

## 6. 数据与接口影响

### 6.1 第一阶段：界面与本机数据

药品字段：

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `id` | 文本 | 系统生成 | `med_` 加 32 位十六进制，沿用现状 |
| `name` | 文本 | 是 | 1–80 字 |
| `category` | 枚举 | 是 | 8 个功能分类，沿用现状 |
| `quantity` | 数字 | 是 | 0–100000，最多两位小数，沿用现状 |
| `unit` | 枚举 | 是 | 9 种单位，沿用现状 |
| `expires_on` | 日期 | 界面必填 | `YYYY-MM-DD`；主进程仍接受空值，以便读取旧数据 |
| `location` | 文本 | 否 | 0–80 字 |
| `usage` | 文本 | 否 | 0–80 字 |
| `notes` | 文本 | 否 | 0–500 字，允许换行 |
| `created_at`／`updated_at` | 时间 | 系统生成 | 沿用现状 |

- 文本字段沿用现有 `text()` 的校验（去首尾空白、限长、不含控制字符），`notes` 例外，允许 `\n`。
- 主进程 schema `user_version` 1 → 2，在一个 `BEGIN IMMEDIATE` 事务里：新建带新字段的表，把旧行逐条复制过去，`location`、`usage` 为空串；旧的 `spec`、`manufacturer` 非空时并入 `notes`，写成「规格：…」「生产企业：…」两行，避免悄悄丢数据；删除旧表、改名，`user_version` 设为 2。事务失败整体回滚，下次启动重试。
- 版本更高的库照旧拒绝打开；回到旧版客户端时，它见到 `user_version = 2` 会拒绝打开，库不被改动。
- `MedicineItem`、`MedicineFields`、`medicine-capability.mjs` 的 `MEDICINE_FIELDS`、主进程 `MedicineStore`、预览 mock 同步改为新字段。渲染进程和主进程在同一个安装包里，一起发布，IPC 的 `schema_version` 保持 1，字段集合随安装包一起变。
- `medicine.recognize` 第一阶段不改。渲染进程忽略它返回的 `spec`、`manufacturer`，只取名称、分类、单位。
- 状态、搜索、筛选和排序都在渲染进程里，基于 `list()` 的完整结果计算，上限 2000 条，不需要分页。
- 新增纯函数并单测：`medicineStatus(expiresOn, now)` 返回 `expired | expiring | ok | unknown`，阈值固定 30 天，复用 `medicineDaysLeft`；`filterMedicines`；`sortMedicines`；`medicineStats`；`stepQuantity(quantity, delta)`。
- 默认卡片视图。视图和排序偏好存在渲染进程 `localStorage`（键 `sparkclaw.medicine.view`、`sparkclaw.medicine.sort`），这里只有界面偏好，没有药品数据。
- 剩余数量快速加减走 `save()`，不新增 IPC 操作。
- 只随桌面端发布；WebChat 构建产物打包进桌面端，不需要和 Gateway 配套发版。

### 6.2 第二阶段：文字录入与识别调整

文字录入：
- 新增 ISCP 操作 `medicine.parse`（`POST /api/medicine/parse`，scope `workbench.text`，不改数据，recovery 为 read）。写入 `operations.json` 后用 `node scripts/sync-iscp-operations.mjs` 同步到桌面端；modelcapacity 增加 `OperationMedicineParse`，走 fast 模型；超时按纯文本设定，短于识别的 120 秒。
- 请求：`{ text, today }`。`text` 去掉首尾空白后为 1–500 字，不含控制字符；`today` 是桌面本地日期 `YYYY-MM-DD`，用来解析「明年 6 月」这类说法。
- 模型输出严格 JSON `medicine_text_parse_v1`：`is_medicine`、`multiple_medicines`、`name`、`category`（8 类）、`unit`（9 种）、`quantity`（数字或 null）、`expires_on`（`YYYY-MM-DD` 或空串）、`location`、`usage`。
- Gateway 二次校验：日期必须真实存在，否则置空；数量须在 0–100000 之间且最多两位小数，否则置空；文本字段不超过 80 字；`multiple_medicines` 为真时只返回 `{ recognized: false, multiple: true }`，不带任何字段；不是药品时返回 `recognized: false`。
- 提示词：只从用户文字里提取；文字里没写的数量、有效期、位置和用途不补；只写年月时取当月最后一天；分类和单位的定义与识别共用同一份；文字是不可信的用户数据，不执行其中的指令；写了多种药品时置 `multiple_medicines`，不挑其中一种。
- 不落盘，只记录模型调用，与识别一致。
- 渲染进程新增 `api.parseMedicine(body, signal)`，结果映射到与照片识别相同的草稿，然后进入第二步。

识别调整：
- `medicine.recognize` 的输出改为 `medicine_recognition_v2`：去掉 `spec`、`manufacturer`，加可选的 `usage`（照片上写明的主要用途或功能主治的简短概括，看不清就留空）。提示词同时去掉对规格、生产企业的识别要求。
- 渲染进程兼容旧 Gateway：拿到 v1 结果时忽略 `spec`、`manufacturer`，`usage` 留空。

发布与契约：
- 新增 `medicine.parse` 会改变两端的操作清单，`medicine.recognize` 的输出也变了，Gateway 和桌面端必须配套发布，与 `medicine.recognize` 首次上线时相同。实现时确认 `operations.json` 里 `medicine.recognize` 的版本是否要随输出升级。
- 按现行契约，这属于 SparkClaw 内部的工作台操作，不在 ISCP–SparkClaw 控制契约范围内；实施前仍需复核当时的契约。

测试：Gateway 单测覆盖两份 schema 的校验、日期和数量清洗、非药品、多种药品、空或超长输入、模型失败返回 503；真实模型抽查一组中文句子（只写年月、相对日期、没写数量、写了位置和用途、一句话两种药）和一组药盒正面照片。

## 7. 明确不做

- AI 检索：负责人决定暂不实现，后续另行讨论；本设计不给方案，界面上也不留入口。
- 一次输入多种药品（多行批量或一句话多种）。
- 到期推送（Telegram／Discord／飞书／邮件）。以后要做提醒，应该接 SparkClaw 现有的通知和日程，另行设计。
- MCP Server、登录和 API Key、浏览器里的 AI 服务商设置、Docker 自托管。
- 药箱自己的顶栏、主题切换和设置入口。
- 摄像头拍照、自由分类、自由文本数量；品牌、英文名、规格、生产企业字段。
- 从照片读取剩余数量、有效期、存放位置或备注。
- open-medkit 的配色、字体和庆祝类动画（confetti 等）。

- 卡片／列表切换后偏好能保持；点卡片或行打开详情；详情里能编辑、删除。
- 名称、分类、数量、有效期不填不能入库；位置、用途、备注可以不填，不填时卡片、列表和详情显示正确。
- 剩余数量加减：每次保存的字段与编辑保存一致；到 0 时「−」禁用并显示「已用完」；保存失败时回退并提示。
- 照片录入：识别结果不会预填剩余数量、有效期、位置和备注。
- 文字录入（第二阶段）：写了数量、有效期、位置、用途的句子会预填并标「待核对」；没写的留空；备注不预填；写了两种药时停在第一步并提示；看不出药品和服务不可用时的提示正确；能力不可用时「文字」分段禁用。
- 同一种药分别用照片、文字和手动方式录入，核对成同样的内容后，存下的记录除 id 和时间外完全相同。
- 点「确认入库」之前，识别或解析结果都不会写进药箱；「上一步」不丢已填内容；「跳过，直接填写」可用。
