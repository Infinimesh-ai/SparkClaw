# 自建官网设计

> 语言：简体中文 | [English](../../docs/self-hosted-console-design.md)

日期：2026-11-19。状态：目标设计，未实现，未部署。

本文只讲官网这一侧：域、设备绑定、接入凭据和授权的签发。设备与后端之间怎么通信见[三端连接层设计](client-link-layer-design.md)，两份文档分开维护。

## 1. 前提

以下前提由用户在 2026-11-19 确认。

1. 正式环境里，设备和后端都加入官网的同一个"域"，由官网签发接入凭据，之后才能通信。
2. 官网只负责设备绑定、配对和签发凭据。消息不经官网。
3. 自建官网是这同一种方式的开发环境，自己搭建，部署在自己的主机上。它不是另一种连接方式。
4. 自建官网只要求表现形式与官网一致，接口不要求逐一相同。自建的目的是方便后续接入；与真实官网的差异在接入时再调整，现在不为此反复权衡。
5. 接入方式只做一种：签发 SparkClaw 接入凭据。官网上的旧版配对码和面向其他产品的接入票据都不实现。
6. 三端暂时不用 ITES 登录。
7. 一台后端只给一个人用，所以一个域对应一个人和一台后端。
8. 凭证走官网的域模型。现有的 node issuer 是另一套签发方式，最终退役。

## 2. 真实官网现在是什么样

2026-11-19 只读查看了已登录的控制台页面和它公开的前端脚本。没有调用会改变状态的接口。

| 概念 | 官网里的含义 |
|---|---|
| 账号 | 手机号登录，对应一个用户 ID |
| 域 | 设备与信任关系的隔离边界，目前支持个人域，有"活跃""暂停"状态 |
| 设备 | 名称、类型和角色（例如 `phone / owner_device`）、信任状态和 Relay 状态（例如 `trusted / active`）、公钥指纹、绑定账号 |
| 配对授权（Trust Grant） | 短期运行凭证，写明对端设备、权限、到期时间。可手动续期，也可开启有上限的自动续期（续期授权默认 90 天到期）。每次续期都要设备用原私钥证明，官网不向设备下发长期凭证 |
| 接入方式 | 旧版一次性配对码 `pair_…`；或信任根签名的一次性接入票据，粘贴或扫码使用 |
| 撤销 | 立即失去连接和授权，需重新配对 |
| 审计、用量 | 域内管理操作的只读记录；用量和额度 |

控制台注明：目录里的状态不代表设备在线，在线以端到端会话就绪为准。

控制台调用的接口都在 `/v1` 下：

- `accounts/login`、`logout`、`me`、`register`
- `domains`、`domains/{域}`
- `domains/{域}/devices`、`devices/{设备}`、`devices/{设备}/revoke`
- `devices/{设备}/grant-renewals`、`devices/{设备}/renewal-authorizations`
- `domains/{域}/pairing-tickets`、`domains/{域}/provisioning-tickets`
- `domains/{域}/audit`、`usage`、`quota`

设备一侧已有两份真实官网接口的客户端：JingSi Android 的 `ManagedCloud.java` 和 JingSi iOS 的 `CloudAPIClient.swift`。

## 3. 自建官网做什么

### 3.1 职责

| 做 | 不做 |
|---|---|
| 账号登录（开发期用最简单的方式，不接 ITES） | 转交或保存任何消息、会话、附件 |
| 创建和查看域 | 管理功能开放（由连接层按设备条件判断） |
| 后端加入域 | 旧版配对码、面向其他产品的接入票据 |
| 签发 SparkClaw 接入凭据 | 用量、额度、计费 |
| 设备列表、改名、撤销 | 多人、多后端的域 |
| 授权的签发和自动续期 | |
| 审计记录 | |
| 告诉设备用哪些 Relay | |

### 3.2 设备的类型和角色

沿用官网"类型 / 角色"的写法。

| 设备 | 类型 | 角色 | 数量 |
|---|---|---|---|
| 后端 | `sparkclaw` | `domain_host` | 每个域恰好一台 |
| 电脑 | `desktop` | `owner_device` | 不限 |
| 手机 | `phone` | `owner_device` | 不限 |
| 手表 | `watch` | `owner_device` | 不限 |

规则：

- 授权只在 `owner_device` 与 `domain_host` 之间签发。`owner_device` 之间没有授权，三端互不连通。
- 每份授权的对端都是本域的 `domain_host`。
- 授权的权限名只有一个：`sparkclaw.link`。功能开放不靠权限区分。
- 连接层用"类型"作为设备类别，决定投影和可用功能。

`phone / owner_device` 与官网现有的写法一致。`sparkclaw / domain_host` 是本设计自定的；接入真实官网时如果官网用别的名称，只在适配器里做映射。

### 3.3 数据

| 记录 | 内容 |
|---|---|
| 账号 | 用户 ID、登录方式 |
| 域 | 域 ID、所属账号、状态（活跃或暂停） |
| 设备 | 设备 ID、所属域、名称、类型、角色、公钥指纹、状态（已信任、已撤销）、创建和更新时间 |
| 接入凭据 | 一次性；所属域、目标设备类型、到期时间、是否已使用 |
| 授权 | 授权 ID、设备、对端、到期时间、状态；续期授权的到期时间 |
| 审计 | 谁在什么时候做了什么管理操作 |

设备的私钥只在设备上。后端的私钥只在后端。自建官网只保存公钥和自己的信任根签名密钥。

### 3.4 三条流程

**后端加入域**

1. 用户在自建官网创建域。
2. 用户为后端签发一份接入凭据，目标类型选 `sparkclaw`。
3. 后端的 ISCP 连接器凭它注册：上交后端公钥，成为域里的 `domain_host`。
4. 一个域只允许一台 `domain_host`。已有时拒绝再次注册。

**设备加入域**

1. 用户在自建官网签发一份 SparkClaw 接入凭据，选设备类型。
2. 页面显示这份凭据的二维码和可复制的文本。凭据一次性有效，只显示这一次，有到期时间。
3. 设备扫码或粘贴，生成自己的密钥，凭这份凭据注册并上交公钥。
4. 自建官网登记设备，并签发这台设备与 `domain_host` 之间的授权。
5. 设备同时拿到：域 ID、`domain_host` 的设备 ID 和公钥、Relay 节点列表。之后设备不再需要这份接入凭据。

域里还没有 `domain_host` 时，设备可以先加入；授权在后端加入后签发。

**续期和撤销**

- 授权是短期的。设备在到期前用自己的私钥证明身份，换发新的授权。绑定关系、密钥、对端都不变。
- 自动续期有绝对上限，参照官网默认 90 天。到期后用户回到官网重新授权。
- 撤销立即生效：授权作废，后端同步到撤销后拒绝该设备。设备要重新走"设备加入域"。

### 3.5 页面

参照真实官网的版式，只保留用得到的部分：

- 域列表、域概览
- 设备列表、设备详情（名称、类型和角色、状态、公钥指纹、授权状态和到期时间、撤销）
- 签发接入凭据
- 审计

### 3.6 与连接层的接口

连接层只通过"官网适配器"接触官网，适配器只暴露四个操作：

| 操作 | 谁调用 | 用途 |
|---|---|---|
| 加入域 | 设备、后端 | 凭接入凭据注册，上交公钥，拿回域内身份和连接信息 |
| 取授权并续期 | 设备、后端 | 拿到和换发短期授权 |
| 同步设备目录 | 后端 | 得到域内设备名单和撤销状态，在本地保存一份，局域网断网时仍能验证设备 |
| 退出域 | 设备 | 解除绑定 |

接入真实官网时只改适配器。JingSi Android 和 iOS 已有的官网客户端可以作为真实官网一侧适配器的起点。

## 4. 实现

- **起点**：ISCP 仓库的参考信任根（`services/trust-root-reference`）。它已经有设备注册、授权签发和配对票据的基础。
- **要改的地方**：参考实现把 `text` 权限的授权上限定为一小时，而且不支持续期。自建官网按官网的做法改成天级有效期，并加上有上限的自动续期。
- **要加的地方**：域和账号、接入凭据的签发与一次性消费、设备的类型和角色、设备目录查询、审计、页面。
- **代码位置**：放在本仓库里，标明只用于开发（暂名 `cmd/dev-console`）。
- **部署**：TEST1，新开一个端口，与现有的 Relay 并列。Relay 继续使用，角色不变。

## 5. 与现有部件的关系

| 部件 | 现在 | 之后 |
|---|---|---|
| TEST1 上的 Relay | 转发 ISCP 流量 | 不变 |
| TEST1 上的控制转发器 | 把签发请求转给 work2 的 node issuer | 随 node issuer 一起退役 |
| work2 上的 node issuer | 给电脑和手机签发 900 秒授权 | 迁移期间保留给已装客户端；新连接层全部切换完成后退役 |
| 电脑端设置里的设备页和一次性凭证二维码 | 签发 node issuer 的邀请 | 入口保留；改动遵守项目的界面变更规则，另行确认 |

## 6. 分阶段

| 阶段 | 内容 |
|---|---|
| C0 | 数据和三条流程定稿；接入凭据的格式；适配器的四个操作定稿 |
| C1 | 信任根改造：天级授权、自动续期、一次性接入凭据、类型和角色；用命令行跑通"后端加入域、设备加入域、续期、撤销" |
| C2 | 页面；部署到 TEST1 |
| C3 | 接入真实官网时：写真实官网一侧的适配器，核对差异 |

C1 完成后连接层就可以开始联调，不必等页面。

## 7. 留到接入真实官网时的事

下面这些现在不解决，C3 时按真实官网的情况调整：

- 真实官网里后端该用什么类型和角色。本设计自定为 `sparkclaw / domain_host`。
- "多台设备各自与同一台后端建立授权"在官网现行流程里是否直接支持。官网页面上的票据流程是为"一个代理端对一台控制手机"设计的。
- 接入凭据的格式与官网现行接入票据的差异。
- 参考信任根离目标还差多少。目前只确认了一小时上限和不能续期这两点。

## 8. 需要用户单独批准的事

- TEST1 新开对外端口属于公网入口变更，实施前需要批准。
- node issuer 和控制转发器的停用时间。
