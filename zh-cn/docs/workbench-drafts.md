# 工作台草稿持久化

> 语言：简体中文 | [English](../../docs/workbench-drafts.md)

草稿属于发起它的工作台。保存或加载草稿不会创建消息、请求 ID 或执行。桌面与主机 WebChat 均已接入共享前端 `WorkbenchDrafts` 队列及窄化读写适配器：桌面通过可信 IPC 和 `useWorkbenchDraft`，主机 WebChat 通过已认证 API 和 `useHostWorkbenchDrafts`。界面接入已完成。

## 共用保存与冲突行为

草稿包含 `content`、`attachment_ids` 和数值 `revision`。队列对输入采用 250 毫秒防抖，串行保存，并在写入前比较已保存修订。迟到回执只推进版本，不覆盖更新的输入。界面区分加载中、未保存、保存中、已保存和错误；所选草稿加载完成前不能发送。保存失败时保留编辑文本并提供重试；普通重试不会悄悄推进冲突修订。

冲突恢复必须明确操作：桌面的“用我的输入替换已保存草稿”或主机 WebChat 的“保留我的草稿并保存”会先读最新保存修订，再用保留文本比较后保存；若此时又有并发写入，仍可能冲突。凭据／作用域变化会隔离旧适配器、迟到回执和释放时的刷入操作，不能把上一账户的输入写入新身份。

桌面切换对话前先刷入当前草稿；保存或目标加载失败时保留原可编辑草稿。主机 WebChat 为每个对话保留独立队列，加载当前选中草稿，并在离开旧对话时刷入其队列；附件选择也使用同一保存队列。页面隐藏或卸载会尝试刷入，有待保存输入时触发浏览器离开确认。这些生命周期保存只是尽力而为：进程／标签页在持久化回执到达前突然退出，仍可能丢失尚未保存的按键输入。只有已保存回执才表示可靠落盘。

两端仓库遵循共用的 64 KiB UTF-8 输入与 32 个所选文件上限。桌面存储归属当前作用域的本地文件 ID；主机 WebChat 存储有界展示引用，每条不超过 4 KiB。引用不授予文件或审批权限，使用时仍须通过正常资源验证。草稿保留空白字符。清空时保存空值并推进修订，迟到自动保存不能重新创建已经发送或清空的文本。

## 桌面仓库与发送

`<userData>/workbench` 下的私有 SQLite 仓库保存欢迎页及各对话草稿，包括所选本地文件 ID。主进程校验作用域与附件归属；可信 IPC 在修改前比较适配器的原认证作用域和当前作用域。欢迎页草稿迁入首次对话是原子的，并推进源修订。

发送先刷入所选草稿，再于同一 SQLite 事务中消费确切修订、保存用户消息、不可变上下文及任务请求。事务失败保留草稿且不创建任务。向执行服务提交是独立操作，使用已经持久保存的任务 ID。调度保存独立明确的定义，不消费对话草稿。

## 主机仓库与发送

主机草稿与 WebChat 对话同存于后端 Store，按已认证 Owner 和对话限定范围；同一范围的标签页共享草稿。欢迎页草稿使用相同 Owner，但没有对话 ID。桌面仓库保持独立，不同步这些草稿。

`GET` 和 `PUT /api/sessions/{id}/draft` 访问对话草稿；`GET` 和 `PUT /api/workbench/draft` 访问欢迎页草稿。缺失草稿读为 `{content:"", attachment_ids:[], revision:0}`，不会创建记录。对话访问验证持久化 Owner，且排除 MCP 管理会话。PUT 提交内容、附件引用和上次读取修订；CAS 成功返回下一修订及 `updated_at`，旧修订返回 HTTP 409。

Memory、File 和 PostgreSQL 实现相同仓库契约。File 一次性保存内容与修订，并处理确定失败回滚及不确定结果栅栏；PostgreSQL 在 `workbench_drafts` 中执行事务性 CAS。持久 File 和 PostgreSQL 仓库可在普通重启后恢复草稿，Memory 则是临时存储。删除对话会删除其草稿，但不删除 Owner 的欢迎页草稿。欢迎页发送时，界面先保存新对话草稿，再用 CAS 清空欢迎页副本；这是两个独立主机操作，冲突会保留较新的欢迎页草稿。

主机发送携带 UUID `request_id`，并可携带 `draft_revision`。网关先持久记录执行接收栅栏，再以固定消息 ID 保存用户消息。只有校验该消息已保存后，才以 CAS 清空提交时的草稿修订，并记录清空后的修订用于接收响应／SSE 事件。执行接收、消息存储和草稿清空属于独立持久化步骤，不是单个数据库事务。草稿冲突保留较新文本，不自动覆盖；执行接收后出现其他持久化失败，则原请求保留栅栏并进入不确定状态。

界面接纳流中确认的清空修订，并在响应脱离或丢失后对账保存草稿与请求状态。界面展示请求状态，并防止保留的已提交草稿修订再次发送。不确定结果仅查询原请求 ID，即使查询返回 404 也不重提；重试保存草稿从不意味着获准重放执行。

## 验证与切换

覆盖范围包括桌面原子入队／清空、主机 Memory／File／PostgreSQL CAS、普通重启、归属与附件隔离、确定／不确定写入失败、清空后拒绝旧写入、导航、重挂载／StrictMode、身份变化、明确冲突恢复，以及 SSE 接收前的固定请求接收栅栏。Mac 原生夹具验证三个全新 Electron 进程间的文本和所选文件引用持久化。所有这些检查使用隔离夹具，不修改运行中的部署或真实配置目录。详见[版本切换](workbench-release.md)：本版本要求新存储，不导入或迁移旧草稿和 schema；同版本普通重启继续保留已创建数据。
