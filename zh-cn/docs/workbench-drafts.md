# 工作台草稿持久化

> 语言：简体中文 | [English](../../docs/workbench-drafts.md)

草稿属于发起它的工作台。保存草稿不会创建消息、请求 ID 或执行。共享前端的
`WorkbenchDrafts` 队列与 `useWorkbenchDraft` hook 只依赖窄化的读写适配器，与
传输方式及存储位置无关。草稿包含文本、附件 ID 列表和数值修订号；不支持草稿附件
的适配器提供空列表。

队列对输入采用 250 毫秒防抖，串行写入，并通过修订号进行比较后交换。迟到的保存
回执不能覆盖更新的输入。切换对话先刷入当前草稿；失败时保留当前输入并显示错误。
界面区分已保存与待保存，失败时提供重新保存按钮，不能将未保存输入标为可靠落盘。
组件释放时刷入待保存内容，但进程在持久化回执之前突然退出，仍可能丢失最后尚未
保存的按键输入。

桌面适配器在 SQLite 中按认证作用域保存欢迎页及各对话草稿，包括所选本地文件 ID。
它校验附件归属与共用输入字节预算。欢迎页草稿迁入首次对话是原子的，同时推进源
修订号，防止迟到写入重新创建旧草稿。可信 IPC 在写操作前比较草稿原认证作用域与
当前作用域，迟到的欢迎页自动保存不能写进另一个账户或部署。

发送先刷入选中草稿，再于同一事务中消费该修订号、保存用户消息、不可变上下文和
任务请求。清空草稿会推进修订号。事务失败保留草稿且不创建任务；迟到写入不能
复活已发送文本。向执行服务提交仍是独立操作，使用已经可靠保存的任务 ID。定时
任务保存其独立明确的定义，不消费对话草稿。

桌面实现直接初始化选定研发 schema，不迁移旧 schema 或导入旧草稿。本提交验证：
121 项桌面测试、48 个文件共 202 项 WebChat 测试，以及 WebChat 类型检查与生产
构建均通过。重点覆盖重启持久化、作用域隔离、附件归属、修订冲突、磁盘故障、原子
入队／清空、迟到保存回执、导航／重挂载，以及保存过程中输入更新的保留。主机
WebChat 适配器及其原子发送边界须在整体工作台统一重构中复用同一队列与修订语义。

## 主机仓库

主机草稿属于工作台本地数据，与 WebChat 会话一同保存在部署主机。已认证 Owner 与会话确定草稿范围；同范围的浏览器标签页共享草稿。欢迎页草稿使用相同 Owner 范围，但没有会话 ID。桌面安装仍使用自己的本地草稿仓库。

`GET` 和 `PUT /api/sessions/{id}/draft` 访问会话草稿，`GET` 和 `PUT /api/workbench/draft` 访问欢迎页草稿，均经过普通主机 API 的认证。不存在的草稿读为 `{content:"", attachment_ids:[], revision:0}`，不会创建记录。会话访问检查持久化会话的 Owner，且不允许访问 MCP 管理会话的草稿。

PUT 提供 `content`、`attachment_ids` 和上次读取的 `revision`。仓库保留空白字符，原子比较版本，然后返回新版本及 `updated_at`。旧版本写入返回 HTTP 409。清空也保存带新版本的空草稿，不删除版本栅栏。因此另一标签页迟到的自动保存不能重新恢复已被较新操作清空的文本。GET 只读，保存与加载草稿都不会提交执行。

当前 Store 上限为 1 MiB UTF-8 草稿文本、64 个附件引用，每个引用不超过 4 KiB。这些是草稿存储限制，不是执行接收限额。引用不会授予文件权限；执行接收时仍要进行正常附件和资源验证。草稿不包含可执行的审批授权。

Memory、默认 File 快照和 PostgreSQL 实现相同的 `SessionRepository` 方法。File 一次提交内容和版本，并处理确定失败回滚及不确定结果栅栏。PostgreSQL 使用新建 `workbench_drafts` 表与事务性比较交换。删除会话会删除对应草稿，不影响 Owner 的欢迎页草稿。不提供旧草稿导入或迁移路径。

固定执行请求被接收后，工作台可清空该次提交使用的确切草稿版本。执行栅栏与主机草稿仓库属于不同持久化域：清空失败后应读取草稿版本对账；版本冲突时必须保留新文本，不能将保留的草稿自动重新提交。共享前端草稿控制器串行保存并对齐适配器返回的版本；其界面接入与本次主机仓库/API 实现属于独立实施步骤。

验收覆盖同一 Memory/File/PostgreSQL 契约：空读取、空白与附件隔离、Owner/会话隔离、欢迎页草稿、并发比较交换、清空后拒绝旧写入、普通重启、会话删除、确定写入失败与提交响应丢失后的对账。测试不会修改运行中的部署或真实数据。
