# 主机工作台调度

> 语言：简体中文 | [English](../../docs/workbench-host-scheduler.md)

WebChat 工作台在部署主机保存调度定义及轮次记录，关闭浏览器标签页不会停止主机调度器。此实现遵循统一的[工作台架构](architecture.md)；连接器所属的定时任务仍是服务职责。

Schedule Registry 根据已持久化且通过所有权检查的来源会话（`webchat` 或隐藏的 `schedule` 会话）确定调度归属，与结果发送目的地无关。请求不能自行指定该权限。在线轮次发布前，仓库先原子记录固定请求 ID，并将循环定义推进到下一轮。Memory、File、PostgreSQL 实现相同的比较交换操作；File 快照一次性持久化定义和轮次记录。

启动后的首次扫描、仓库访问失败、发布器不可用、超过两个正常轮询间隔的停顿，以及检测到的墙钟与单调时钟暂停差异，都会使期间到期的工作台轮次记为 `missed`。持续健康的轮询只接收自上次轮询以来到期的轮次，保留正常计时抖动，同时防止过期积压变成可运行任务。每次扫描有数量上限；尚未登记的过期轮次保留原到期时间，之后只补记跳过记录。未来循环轮次仍可在其到期时执行。

工作台轮次记录 ID 同时也是 Message Runtime 信封 ID；对应运行 ID 是 `run_` 加上该 ID。提交结果不确定时，轮次记为 `unknown`，只允许对账原请求。重启不会重新发布已提交或已跳过的轮次。循环定义在提交前已保存下一次到期时间，因此接收执行后、保存结果前的崩溃既不会重放本轮，也不会丢失未来定义。连接器服务任务保留原有重试和重新领取规则。

WebChat 定时任务列表将已跳过的单次任务显示为“离线已跳过”，未确认完成的已提交轮次显示为“已提交”，不允许编辑、重新排期或自动重提这些轮次。历史轮次记录留在主机仓库，不会同步到桌面安装。

2026-10-06 验证：受影响 Memory/File 契约测试、重启与并发调度测试、回滚及不确定提交测试通过；同一 Store 契约在全新隔离 PostgreSQL 16/pgvector 容器中通过。WebChat 调度测试、双语文案检查和生产构建通过。未修改运行中的服务或真实数据。主机原生睡眠/唤醒验收仍属于配套版本发布时的硬件验收。

持续在线期间，分批扫描延迟的轮次保持可执行；公共可用时间边界只在启动或离线间隙重设，不能在每次 tick 前移而把正常在线积压误记为 missed。
