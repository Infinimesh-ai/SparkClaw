# 主机工作台调度

> 语言：简体中文 | [English](../../docs/workbench-host-scheduler.md)

WebChat 在部署主机的 Store 中拥有调度定义和轮次账本。后端调度器独立于浏览器标签页运行，关闭 WebChat 不会停止它。File 和 PostgreSQL 在普通服务重启后保留记录；Memory 是临时存储。定义和历史不会同步到桌面安装。新存储要求详见[版本切换](workbench-release.md)；桌面主进程及认证连接的独立可用性规则详见[桌面调度](desktop-scheduling.md)。

## 归属与持久领取

Schedule Registry 根据已持久化且通过归属校验的来源会话（`webchat` 或隐藏的 `schedule` 会话）确定调度归属，与结果发送目的地无关。请求不能自行声明这种权限。连接器所属任务仍由服务负责，并保留现有重试／重新领取规则。

在线工作台轮次发布之前，仓库先原子记录固定请求 ID，并将循环定义推进到下一次到期时间。Memory、File 和 PostgreSQL 实现相同比较交换操作；File 快照一次性保存定义与轮次账本。竞争工作者不能重复领取同一定义修订。执行进入普通 Message Runtime，不使用后端未来执行租约。

轮次账本 ID 同时也是 Message Runtime 信封 ID；运行 ID 为 `run_` 加上该 ID。发布结果不确定时，轮次进入 `unknown` 并要求对账。持久领取后即使在发布之前崩溃，也不授权重放。重启不会重新发布已提交或已跳过的轮次。只按原身份对账；结果缺失或查询失败不授权创建替代执行。下一到期时间已与领取一同提交，因此未来循环任务能跨过本轮不确定状态继续存在，并使用自己的轮次身份。

## 可用性与跳过轮次

启动后的首次扫描、仓库访问失败、发布器不可用、时钟倒退、超过两个正常轮询间隔的停顿，或检测到的墙钟／单调时钟挂起差异，都会重置可用性边界。在该边界及之前到期的工作台轮次永久记为 `missed`。这是服务可用性规则，浏览器连接或可见性不决定主机调度器是否在线。

持续健康的轮询保留同一个稳定可用性边界；其后到期的轮次即使遇到正常计时抖动或有界扫描／工作队列延迟，仍可执行。每次扫描限制仓库工作量。长时间离线后，旧到期时间保持不变，直到后续扫描补记为跳过，绝不变成可运行的补跑积压。循环定义逐步跳过遗漏轮次并保留未来到期时间。唤醒或服务重启不能执行不可用期间到期的工作。

WebChat 任务列表将已跳过的单次轮次显示为“离线已跳过”，尚未确认完成的已提交轮次显示为“已提交”，不提供编辑、重新排期或自动重提这些轮次。历史记录留在主机仓库。用户明确创建的新请求使用新身份，不会复活已跳过或不确定的轮次。

## 验证边界

确定性调度与 Memory／File 契约测试覆盖启动、可用性中断、连续计时抖动、有界批次、并发领取、未来循环身份、重启、回滚和提交结果不确定。同一 Store 契约也在新建隔离 PostgreSQL 存储上执行；WebChat 测试覆盖已跳过和已提交的展示。这些检查不修改运行服务或真实数据。原生主机挂起／恢复资格验证属于准确匹配版本的独立硬件证据；注入时钟的测试不代表已完成物理睡眠验收。

生产分派保留一个有界待投递批次，在工作线程投递与定时脉冲间 select。工作线程背压不会中断在线状态观察：105 个慢任务回归保持连续在线轮次可执行；注入实际可用性间隙时，尚未领取且已过期的轮次仍会被记为错过。
