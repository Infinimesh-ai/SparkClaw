# 工作台版本切换

> 语言：简体中文 | [English](../../docs/workbench-release.md)

本文规定后端、主机 WebChat 与桌面工作台源代码版本的全新初始化边界。三者必须使用同一已验证修订的匹配构建。本文及本次实现不部署服务、不替换已安装应用、不重置配置目录，也不删除真实数据；实际切换属于独立运维操作。

## 存储选择

为本版本选择新的部署身份、后端业务 Store 及文件／工作区存储。显式选择新的 `state.path`（Go 中的 `State.Path`）作为持久控制存储锚点。完成切换后保持这些位置稳定，普通重启继续打开同一份存储。

| 数据 | 位置与权威来源 |
|---|---|
| 主机 WebChat 对话、草稿、历史、调度定义和轮次 | 所选后端 Store；需要重启持久化时使用 File 或 PostgreSQL |
| 执行接收、请求身份与投递控制 | `State.Path + ".execution"` |
| 邮件同步控制 | `State.Path + ".mailsync"`；邮箱内容的权威来源仍是后端 |
| 桌面对话、草稿、任务、文件和调度 | 该安装的 `<userData>/workbench` |
| 桌面邮件缓存 | `<userData>/workbench/mail`；后端邮箱的本地投影 |
| 桌面选定后端与加密凭据 | `<userData>/backend.json` 及同一配置目录下的安全凭据仓库 |

PostgreSQL 不会代替文件系统中的控制存储锚点。即使使用 `state.backend = "postgres"`，也要显式配置 `state.path`，选择新的绝对路径并保证父目录可由服务写入；将派生的 `.execution`、`.mailsync` 目录与所选数据库及授权文件存储一并持久保存。只更换 PostgreSQL DSN 并不构成完整的全新切换。Memory Store 仍是临时测试／运行选项，不承诺重启后保留历史。

每个桌面安装首次启动匹配构建之前，将 `SPARKCLAW_DESKTOP_USER_DATA_DIR` 设为新的绝对目录；后续启动复用同一目录，相对路径会被拒绝。通过当前凭据流程配置新后端并重新注册；新配置目录获得自己的安装身份。普通启动只读取选定描述文件和安全凭据仓库，不发现旧启动器路径或导入明文凭据。平台允许时，显式选择的回环描述文件仍受支持；夹具路径注入仅限资格验证模式。

本版本不提供旧 schema 迁移、旧数据导出／导入管线、路径别名、旧设备别名或自动载入旧历史。桌面遇到不支持的 schema 会明确失败，不升级或擦除旧数据。不要复用旧业务存储作为迁移捷径。实际切换前，应在独立授权范围内停止或排空旧执行，并阻止旧写入者继续写入。邮件服务目录、部署秘密及外部协议要求的去重账本须按各自契约保留；新建业务 Store 不等于获准清理这些资源。

## 匹配的 API

桌面与后端使用 `/api/v1/installations`、`/api/v1/executions`、`/api/v1/inputs`、`/api/v1/mail` 和 `/api/v1/browser/hosts`。执行／输入摘要使用 `X-SparkClaw-Digest`。不要将该后端与仍使用已退役产品路由或请求头的桌面混用；本版本不提供兼容别名。

主机 WebChat 通过 `POST /api/sessions/{id}/messages` 或 `POST /api/sessions/{id}/messages/stream` 发送消息。每次发送携带 UUID `request_id`；可选的 `draft_revision` 标识已提交的草稿修订。请求列表和原请求查询分别为 `GET /api/sessions/{id}/requests`、`GET /api/sessions/{id}/requests/{request}`。明确取消使用 `POST /api/sessions/{id}/requests/{request}/cancel`。主机请求控制复用执行栅栏，同时保留主机工作台自己的会话 Store。

已冻结的外部 R3 App-CLI／JingSi 契约、其必需账本及历史验收证据保持不变。本版本产品路由和存储命名的调整不重新定义外部协议，也不改写以往证据。

## 重启与到期行为

在选定版本内，普通重启会恢复工作台已保存的草稿、对话历史、文件、调度定义及轮次记录。桌面存储属于该安装；主机 WebChat 数据属于主机仓库和已认证 Owner。不同工作台之间不自动同步历史、草稿、文件或调度。邮件是例外：各缓存按修订号和游标同步后端的权威邮箱。

桌面调度只有在主进程运行且与后端保持可用认证连接时才在线。隐藏窗口不会停止调度器；退出、挂起、连接中断或认证代次变化会结束当前可用窗口。主机调度器在后端服务中运行，不依赖浏览器标签页保持打开；其仓库／发布器可用性及服务轮询连续性决定到期轮次能否被接收执行。

所属调度器不可用期间到期的轮次会永久跳过。启动、重连及唤醒只扫描并记录这些遗漏，不执行补跑积压。持续可用期间的正常计时延迟仍可执行。循环定义保留未来轮次，各轮次使用不同请求身份。提交结果不确定时，包括响应丢失后查询得到 404，只按原请求 ID 对账，不重放 POST，也不自动生成替代请求。结果重投递和持久 ACK 重试不等于重新执行请求。

## 资格验证边界

版本检查须使用匹配构建与隔离存储，覆盖草稿保存／恢复／冲突、本地历史及所选文件恢复、循环定义和轮次恢复、离线永久跳过、未来轮次保留，以及提交响应丢失后只查询不重放。Mac 原生夹具在三个全新 Electron 进程中运行 prepare／restore／revoke，使用临时配置目录、真实安全存储及合成回环后端，并验证进程间变为过期的轮次不会产生执行 POST。它不执行真实系统睡眠，也不重置钥匙串、已安装应用或真实配置目录。

原生挂起／恢复和已安装包验收仍需提供准确目标构建的独立证据。实现边界详见[草稿持久化](workbench-drafts.md)、[桌面调度](desktop-scheduling.md)和[主机调度](workbench-host-scheduler.md)。
